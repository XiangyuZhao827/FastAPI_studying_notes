# 05｜元数据和文档 URL（Metadata and Docs URLs）

**FastAPI 用户指南 · 独立复习手册｜核心问题：怎样让别人一打开 /docs 就看懂 Agent API？**

官方文档：https://fastapi.tiangolo.com/zh/tutorial/metadata/

## 一、本章主要学习什么？

之前你会通过 `@app.post('/chat')` 创建 API，也能打开 Swagger UI。但一个真实 Agent 平台可能有登录、Agent 管理、会话、文件、聊天等几十个接口。如果文档不分组，别人就需要逐一试错。

本章讲的是 API 的**说明和组织信息**：应用叫什么、版本多少、各组接口做什么、文档放在哪里。它改善文档体验，不会让 Agent 推理变强，也不会自动增添安全性。

## 二、创建 FastAPI 时可设置的元数据

最常用的是 `title`、`summary`、`description`、`version`。还可以设置 `terms_of_service`、`contact`、`license_info` 等公开信息。官方示例演示了这些字段，下面保留与 Agent 场景相关的简短用法：

```python
from fastapi import FastAPI

app = FastAPI(
    title="My Agent API",
    summary="AI Agent Backend Service",
    description="提供 Agent 对话与会话管理接口",
    version="1.0.0",
)
```

| 参数 | 主要告诉调用者什么 | 注意 |
| --- | --- | --- |
| `title` | API 项目名称 | 不是 Agent 模型名称 |
| `summary` | 用一句话概括 | 便于快速浏览 |
| `description` | 服务提供的能力 | 可以使用 Markdown |
| `version` | 当前应用 API 版本 | 不是 Python、FastAPI 或 LLM 的版本 |
| `contact` | 公开的联系渠道 | 与用户登录无关 |
| `license_info` | 许可证信息 | 名称必填；identifier 与 url 不同时使用 |

**重点：**填写 `version='1.0.0'` 只是文档信息，不会自动创建 `/v1/` 版本化路由。

## 三、为什么要用标签（tags）？

假设 `/docs` 中希望显示 Users、Agents、Chat、Sessions、Files 五类接口。你以前学过：

```python
@app.get("/agents", tags=["Agents"])
def get_agents():
    return []
```

这行的 `tags` 表示“把此接口放进 Agents 类别”。但如果你还想为类别写一句说明，就用 `openapi_tags`。

```python
tags_metadata = [
    {"name": "Users", "description": "登录和查询当前用户"},
    {"name": "Agents", "description": "查询和管理 Agent"},
    {"name": "Chat", "description": "与 Agent 对话"},
]

app = FastAPI(
    title="My Agent API",
    openapi_tags=tags_metadata,
)
```

这段为教学精简的示例可配合下面的路径操作使用：

```python
@app.post("/chat", tags=["Chat"], summary="与 Agent 对话")
def chat():
    return {"answer": "演示回复"}
```

三个角色要分清：

- `tags_metadata`：普通 Python 变量，包含分类说明，你也可以改名。
- `openapi_tags=tags_metadata`：注册分类元数据，是 FastAPI 的固定参数名。
- `tags=['Chat']`：将当前具体路由归入 Chat 分类。名称应与 `openapi_tags` 定义相对应。

官方还介绍 `externalDocs` 用于指向外部文档；类别在 `openapi_tags` 中的排列顺序可影响显示顺序。

## 四、与 APIRouter 配合时更省事

你在《更大的应用》一章已经学过：

```python
from fastapi import APIRouter

router = APIRouter(prefix="/agents", tags=["Agents"])

@router.get("/")
def list_agents():
    return []
```

只需要在主应用里 `app.include_router(router)`，这一组 Router 的接口就会带上 Agents 标签。这样项目大了以后无需在每个路由重复声明分类。

但是必须明白：`tags` 和 `openapi_tags` 只影响接口文档的分类与说明，不负责用户认证或管理员权限。

## 五、`/docs`、`/redoc` 与 `/openapi.json`

| 地址 | 用途 | 控制它的参数 |
| --- | --- | --- |
| `/docs` | 可交互的 Swagger UI | `docs_url` |
| `/redoc` | 偏阅读的 ReDoc | `redoc_url` |
| `/openapi.json` | 供程序读取的 OpenAPI 描述 | `openapi_url` |

例如：

```python
app = FastAPI(
    docs_url="/documentation",
    redoc_url=None,
    openapi_url="/api/v1/openapi.json",
)
```

这意味着 Swagger UI 迁移到 `/documentation`；ReDoc 被关闭；OpenAPI 数据从新 URL 获取。若设置 `openapi_url=None`，则关闭 OpenAPI 路由以及依赖它的自动文档页面。

**安全提醒：**关闭或改名 `/docs` 不等于保护 `/chat`。业务接口仍需独立的登录与权限检查。

## 六、Agent 实战：设计一份好用的 API 文档

假设平台有：

```text
Users     POST /token                  GET /users/me
Agents    GET /agents                  GET /agents/{agent_id}
Chat      POST /chat
Sessions  GET /sessions/{session_id}
Files     POST /files
```

你可以为每类接口添加 `openapi_tags` 的说明、给接口设置 `summary`、给请求模型准备有代表性的示例。这样前端开发者不用打开代码，也能看到调用方式并在 Swagger UI 中试验。

这有两层好处：**对开发者：少问问题、减少接入成本；对你：接口文档和代码定义自动同步，更容易维护。**

## 七、常见误区

1. `version` 是 FastAPI 包版本吗？不是，是你的 API 应用版本。
2. `tags=['Admin']` 会让接口只允许管理员吗？不会，它只是文档分类。
3. `openapi_tags` 会自动创建 /chat 等路由吗？不会，仍然要编写路径操作或 Router。
4. `docs_url=None` 会删除 API 的实际处理逻辑吗？不会，仅影响文档 UI。
5. `responses={404: ...}` 的文档声明会自动替你抛出 404 吗？不会，那属于路由实际业务处理。

## 八、5 道复习题（附答案解析）

**1. `title` 与 `description` 各做什么？**  答：一个给 API 命名，一个解释它提供的服务；都用于文档信息。

**2. `openapi_tags` 和路由 `tags` 的区别？**  答：前者定义标签说明，后者把具体接口归入标签。

**3. Agent 业务权限能靠 tags 控制吗？**  答：不能，需要 Depends、安全依赖和业务授权检查。

**4. 修改 `docs_url` 为 `/documentation` 后，旧 `/docs` 是否还能访问原文档？**  答：默认不会，应访问新设置的 URL。

**5. 如果 `openapi_url=None`，为何文档 UI 也受影响？**  答：Swagger UI、ReDoc 依赖 OpenAPI 描述来展示接口，关闭规范路由会连带禁用这些默认文档页面。

## 九、思考题

你的 Agent 平台有 15 个接口，涉及聊天、会话、模型管理与文件上传。你会如何设置 tags、openapi_tags 和 summary，避免别人误把“标签分组”当成“安全分组”？

**参考方向：**按功能定义清晰标签，标签说明写出调用用途，敏感接口单独定义真实认证和授权，文档中不记录明文密码或真实密钥。

**本章一句话总结：**元数据改善 API 的可理解性；它不是功能实现，也不是权限保护。
