# 第三章　服务器发送事件（SSE）

官方文档：https://fastapi.tiangolo.com/zh/tutorial/server-sent-events/

版本提示：官方原生 `fastapi.sse` 教程功能从 FastAPI 0.135.0 开始提供。

## 1. SSE 是什么？

SSE（Server-Sent Events）是在 HTTP 上从服务器持续向客户端发送事件的一套标准格式。它也是流式传输的一种具体形式，不等于“与流式输出不同的显示效果”。SSE 响应一般使用 `text/event-stream`。

典型事件数据用空行分隔：

```text
event: progress
data: {"step":"search"}

event: done
data: {"status":"completed"}

```

浏览器原生 EventSource 对 SSE 有专门支持；它主要建立 GET 连接。FastAPI 也允许用 POST 接口返回 SSE，接收 POST 的前端可使用 fetch 及流式解析来处理。

## 2. 核心实现：EventSourceResponse

```python
from collections.abc import AsyncIterable
from fastapi import FastAPI
from fastapi.sse import EventSourceResponse

app = FastAPI()

@app.get('/events', response_class=EventSourceResponse)
async def events() -> AsyncIterable[dict]:
    yield {'message': 'hello'}
    yield {'message': 'world'}
```

**记忆重点：** `response_class=EventSourceResponse` 告诉 FastAPI 以 SSE 格式发送；路由继续使用 `yield` 逐条提供事件数据。上面是便于学习的精简版，官方主要通过 Pydantic Item 模型演示。

## 3. 官方的 ServerSentEvent 负责事件细节

当你需要显式声明事件名、ID 或重连建议，可以返回 `ServerSentEvent`：

```python
from fastapi.sse import ServerSentEvent

yield ServerSentEvent(
    data={'step': 'search'},
    event='progress',
    id='1',
    retry=5000,
)
```

| 字段 | 含义 | Agent 中的理解 |
| --- | --- | --- |
| data | 发送的事件数据（官方实现会 JSON 编码） | 模型文字、工具结果、进度数据 |
| event | 事件类别 | token / progress / done |
| id | 事件标识 | 用于标记事件顺序或续传位置 |
| retry | 建议客户端重连等待时间（毫秒） | 网络中断后的重连策略 |
| comment | 注释信息 | 例如连接保活 |

`raw_data` 用于发送不经 JSON 编码的原始文本，例如 `[DONE]`；同一个 ServerSentEvent 的 `data` 与 `raw_data` 不可同时设置。

## 4. Last-Event-ID 不是 Agent 的自动记忆

在浏览器使用 EventSource 的典型场景中，如果连接中断并重新连接，浏览器可以通过 `Last-Event-ID` 告诉服务器最后收到的事件 ID。服务器可依据这个值选择继续发送哪些事件。

但这**不意味着** FastAPI 自动保存历史事件或 Agent 的推理状态。真正的“任务断点恢复”需要应用另外保存执行结果、事件日志或任务状态。

## 5. SSE 与用户感受到的流式输出

| 方式 | 用户看到的体验 | 技术上要注意 |
| --- | --- | --- |
| 普通 JSON | 等完整结果后一次性展示 | 实现简单，适合短任务 |
| 流式文本 / JSON Lines | 内容逐步显示或逐条处理 | 客户端负责解释每条数据 |
| SSE | 同样可逐步显示，还能基于事件名称更新不同 UI | 格式中有 event、data、id 等字段 |

**关键：** 用户看到的打字效果叫“流式输出体验”，可以用 SSE 实现，也可以用其他流式机制实现。SSE 的优势是提供标准化事件格式，而不是它独占“边生成边显示”的功能。

## 6. 在 Agent 中怎样应用？

用户说：“帮我整理最近的 AI 研究并生成摘要。”前端可以依次收到：

```text
event: progress
data: {"step":"searching"}

event: progress
data: {"step":"summarizing"}

event: token
data: "摘要正在生成"

event: done
data: {"status":"completed"}

```

前端看到 `progress` 就更新执行状态，看到 `token` 就增加文字，看到 `done` 就显示完成。以上事件名只是业务约定，不是 SSE 规定的必须名称。

**注意：** SSE 只传递已有的事件。LLM 的文本增量、LangGraph 的步骤更新等，需要在内部业务层真实产生并转发；不能指望换用 SSE 就自动看到工具调用过程。
