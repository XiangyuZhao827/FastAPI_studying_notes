# 第一章：表单数据（Form Data）

## 一、为什么有了 JSON Body，还需要 Form？

你已经非常熟悉这样的 Agent API：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class ChatRequest(BaseModel):
    message: str


@app.post("/chat")
def chat(request: ChatRequest):
    return {"answer": request.message}
```

客户端发送：

```http
POST /chat HTTP/1.1
Content-Type: application/json
```

Body：

```json
{
  "message": "请解释 FastAPI"
}
```

这种请求格式是 `application/json`。

但假设你做了一个网页登录界面：

  

    **Agent 平台登录 · 示意界面**

  

用户名

      
alice

  

    
密码

      
••••••••

  

    **登录**

  
这是表单界面的示意，不会发送真实登录请求。

如果它是传统 HTML 表单，浏览器通常会以表单编码方式提交字段，而不是自动把它们变成 JSON。

例如：

```text
username=alice&password=example123
```

所以：

**JSON 和 Form 都可以携带用户输入，但它们在 HTTP 请求体中的编码方式不同。**

## 二、JSON、Form、Query 到底有什么区别？

这是本章最重要的概念。

假设三个场景都需要传：

```text
username = alice
```

### 情况 A：Query 查询参数

```http
GET /users?username=alice
```

FastAPI：

```python
username: Annotated[str, Query()]
```

这里的数据在 URL 中。

### 情况 B：JSON 请求体

```http
POST /users HTTP/1.1
Content-Type: application/json
```

Body：

```json
{
  "username": "alice"
}
```

FastAPI 可以使用：

```python
class UserRequest(BaseModel):
    username: str
```

### 情况 C：表单请求体

```http
POST /users HTTP/1.1
Content-Type: application/x-www-form-urlencoded
```

Body：

```text
username=alice
```

FastAPI：

```python
username: Annotated[str, Form()]
```

对比：

| 特征 | Query | JSON Body | Form Body |
|---|---|---|---|
| 数据位置 | URL 问号后 | HTTP 请求体 | HTTP 请求体 |
| 常用声明 | `Query()` | `BaseModel` / `Body()` | `Form()` |
| 典型格式 | `?name=alice` | `{"name":"alice"}` | `name=alice` |
| 常见应用 | 搜索、筛选、分页 | Agent 消息与配置 | 登录表单、简单网页提交 |

特别注意：

**Form 并不是 Query。Form 和 JSON Body 都使用 HTTP Body，但通常有不同的 `Content-Type`。**

## 三、官网代码：使用 Form() 接收登录字段

这是官方教程的核心示例：

```python
from typing import Annotated

from fastapi import FastAPI, Form

app = FastAPI()


@app.post("/login/")
async def login(
    username: Annotated[str, Form()],
    password: Annotated[str, Form()]
):
    return {"username": username}
```

我们逐行讲解。

### 1. 导入 Form

```python
from fastapi import Form
```

这里的 `Form` 和之前学过的 `Query`、`Cookie`、`Header` 十分相似。

但它指定的参数来源是：

**HTTP 请求体中的表单字段。**

### 2. 分析 username

```python
username: Annotated[str, Form()]
```

可以拆成：

| 部分 | 含义 |
|---|---|
| `username` | Python 函数参数名 |
| `str` | 应该解析为字符串 |
| `Annotated[...]` | 组合类型与 FastAPI 参数声明 |
| `Form()` | 从表单数据读取 username |
| 没有默认值 | username 必填 |

password 同理：

```python
password: Annotated[str, Form()]
```

因此客户端必须提供这两个表单字段。

### 3. 为什么返回值只有 username？

官方示例特意写成：

```python
return {"username": username}
```

没有返回 password。

这正是你上一章《响应模型－返回类型》学到的安全意识：

**请求中可以包含密码，但响应不应该把明文密码返回给客户端。**

不过，这个示例只是说明如何提取字段，**没有真正验证用户名和密码，也没有完成登录认证**。

## 四、表单实际是怎么发送的？

假设用户填写：

```text
username = alice
password = example123
```

传统表单请求可以表示为：

```http
POST /login/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=alice&password=example123
```

这里的：

```text
username=alice&password=example123
```

类似 URL 查询字符串，但要注意：

**它现在位于 HTTP Body 中，而不是 URL 问号后。**

例如包含中文时：

```text
message=你好
```

实际传输需要经过适当的 URL 编码。你不需要手工编码，浏览器和 `httpx` 等 HTTP 客户端一般会完成这件事。

### 1. JSON 和表单为什么不能混着发？

对比两个请求。

**JSON 请求体：**

```http
Content-Type: application/json
```

```json
{
  "username": "alice",
  "password": "example123"
}
```

**表单请求体：**

```http
Content-Type: application/x-www-form-urlencoded
```

```text
username=alice&password=example123
```

服务器根据请求体的媒体类型，决定如何解释内容。

因此，如果接口要求：

```python
username: Annotated[str, Form()]
```

你却直接发送 JSON：

```json
{
  "username": "alice"
}
```

FastAPI 不会自动把这份 JSON 当作表单字段来读取，通常会因为缺少预期表单字段而返回 422。

反过来，若接口期待 JSON 模型，你发送普通表单，也不应该期望 FastAPI 自动完成相同解析。

官方教程特别提醒：不能在同一个普通路径操作中，一边声明传统 Form 字段，一边又期望另一些 Body 字段来自独立的 JSON 请求体。因为一次请求只有一个请求体，其整体编码类型需要一致。

这并不禁止你在表单字段中传递 JSON 字符串后手动解析，但那属于另一种明确设计的接口协议，并不是 FastAPI 自动混合两种请求体。

## 五、什么是 application/x-www-form-urlencoded 和 multipart/form-data？

它们都属于表单传输方式。

### 1. application/x-www-form-urlencoded

最常见的简单表单格式。

例如：

```text
username=alice&password=example123
```

适合：

- 用户名。
- 密码。
- 简短文本字段。
- 数值、布尔值等简单数据。

### 2. multipart/form-data

另一种表单编码形式，特别适合**同时上传文件和普通字段**。

例如，用户在 Agent 页面上传一份 PDF，并填写：

```text
description = 请总结这个文件
file = report.pdf
```

浏览器一般会使用 `multipart/form-data`。

不过，这属于后续《请求文件》《请求表单与文件》章节的重点。你现在先记住：

| 媒体类型 | 典型用途 |
|---|---|
| `application/json` | 复杂结构化 JSON |
| `application/x-www-form-urlencoded` | 不包含文件的普通表单 |
| `multipart/form-data` | 表单字段与文件上传 |

FastAPI 可以通过 `Form()` 读取普通表单字段，也可以在后续学习中结合 `File()`、`UploadFile` 处理上传文件。

## 六、使用 Form() 前，为什么要安装 python-multipart？

这点必须记住。

官方文档要求安装：

```bash
pip install python-multipart
```

原因是 FastAPI 需要相应的表单解析能力。

建议你在自己的 Windows conda `(llm)` 环境中检查：

```bash
python -m pip show python-multipart
```

如果没有安装，再运行：

```bash
python -m pip install python-multipart
```

如果你安装的是当前的：

```bash
python -m pip install "fastapi[standard]"
```

通常也会安装 FastAPI 标准开发环境需要的依赖，但单独检查 `python-multipart` 是否存在更加直接。

若缺少它，定义使用 `Form()` 的接口时，FastAPI 可能直接在启动或注册路由阶段提示需要安装该依赖。

这和普通的 422 不同：

- **缺少 python-multipart**：服务端运行环境依赖问题。
- **表单字段缺失**：请求输入验证问题，通常返回 422。

## 八、如果没传 password，会出现什么？

我们看代码：

```python
password: Annotated[str, Form()]
```

它没有默认值，所以属于必填字段。

如果客户端只提交：

```text
username=alice
```

却没提交 password，通常会返回：

**HTTP 422。**

错误信息的关键位置类似：

```json
{
  "detail": [
    {
      "loc": ["body", "password"],
      "msg": "Field required",
      "type": "missing"
    }
  ]
}
```

注意：

```json
["body", "password"]
```

为什么不是：

```json
["form", "password"]
```

因为表单数据本质上仍然位于 **HTTP 请求体（Body）** 中。

这也是本章非常值得记住的考点。

## 九、Form() 也支持字段验证

和之前的 `Query()`、`Field()` 一样，可以设置约束：

```python
@app.post("/login/")
def login(
    username: Annotated[
        str,
        Form(min_length=3, max_length=30)
    ],
    password: Annotated[
        str,
        Form(min_length=8)
    ]
):
    return {"username": username}
```

现在：

| 输入情况 | 结果 |
|---|---|
| username = `"alice"`、password = `"example123"` | 200 |
| username = `"ab"` | 422，长度不足 |
| password = `"123"` | 422，长度不足 |
| 缺少 username | 422 |
| 缺少 password | 422 |

你已经学习过的验证规则，可以直接复用。

但要注意，`min_length=8` 只是在检查字符长度，**不是一个完整的密码安全策略**。

真实系统仍然需要用户认证、密码安全存储、登录频率限制等措施。

### 🤖 Agent 开发中的应用

表单适合 Agent 平台的登录页、简单设置页、传统 HTML 提交页面。

但是对于复杂的 Agent 请求，比如：

```json
{
  "message": "请分析这个项目",
  "config": {
    "max_steps": 3,
    "tools": [
      {"name": "search", "enabled": true}
    ]
  }
}
```

一般仍然更适合使用 `BaseModel` + JSON Body。

所以：

**Form 不是要替代 JSON，而是让 FastAPI 能正确处理另一种常见的 HTTP 请求格式。**

### 思考题 1

为什么下面两个请求虽然都包含 `username=alice`，但 FastAPI 的声明方式不同？

```http
GET /users?username=alice
```

与：

```http
POST /login
Content-Type: application/x-www-form-urlencoded

username=alice
```

### 思考题 2

解释为什么一个登录页面可以采用 Form，而一个包含 `messages: list[Message]`、`config: RunConfig` 的复杂 Agent 对话接口通常更适合 JSON Body。

### 第一章参考答案

| 题号 | 答案 | 解析 |
|---|---|---|
| 1 | C | Form 明确从请求体的表单字段提取数据 |
| 2 | B | 简单表单通常使用 URL 编码 |
| 3 | A | 没有默认值，因此必填 |
| 4 | D | 缺少必填表单字段，通常返回 422 |
| 5 | B | JSON 与 Form 采用不同的请求体编码 |
| 6 | C | 表单解析需要 python-multipart |

**思考题 1：** 第一个 username 出现在 URL 问号后，属于 Query；第二个 username 出现在表单编码的请求体中，属于 Form。参数名相同不代表数据来源相同。

**思考题 2：** 登录通常只涉及少量简单字段，传统 HTML Form 足够表达；复杂 Agent 请求涉及嵌套模型、消息数组和工具配置，JSON 更适合保持这些结构。两者都是合法的 API 设计，取决于客户端实际发送的数据格式。
