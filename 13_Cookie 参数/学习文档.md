# 📘 FastAPI 四章联合学习：Cookie、Header 与参数模型

FastAPI → AI Agent 后端开发 · 四章整合讲解

这次我们一次学习四个官方章节：

1. [Cookie 参数](https://fastapi.tiangolo.com/zh/tutorial/cookie-params/)
2. [Header 参数](https://fastapi.tiangolo.com/zh/tutorial/header-params/)
3. [Cookie 参数模型](https://fastapi.tiangolo.com/zh/tutorial/cookie-param-models/)
4. [Header 参数模型](https://fastapi.tiangolo.com/zh/tutorial/header-param-models/)

它们和你之前学过的 `Query()`、查询参数模型有非常相似的设计思想，所以合在一起学习反而更容易理解。

## 一、先搞清楚：Cookie 和 Header 到底是什么？

你之前学习过三种请求数据来源：

- **Path**：`/agents/2/chat` 中的 `2`。
- **Query**：`?verbose=true` 中的 `verbose`。
- **Body**：用户问题、Agent 运行配置等 JSON。

现在再补充两个概念：

**Header（请求头）**：HTTP 请求中描述客户端、请求格式、授权信息等的元数据。

**Cookie**：客户端保存并随符合条件的请求发送的小段数据，常用于会话标识、偏好设置等。

### 1. 一个完整的 Agent HTTP 请求长什么样？

假设用户在网页输入：

> 请解释什么是 FastAPI。

前端可能发送：

```http
POST /agents/2/chat?verbose=true HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: application/json
X-Client-Name: agent-web
X-Request-ID: req001
Cookie: session_id=demo001; theme=dark

{
  "message": "请解释什么是 FastAPI",
  "max_steps": 3
}
```

这里是一份用于教学的 HTTP 请求示意。

  

请求方法与 URL

    **POST /agents/2/chat?verbose=true**
    
Path → agent_id=2；Query → verbose=True

  

请求头 Header

    `X-Client-Name: agent-web`
    
    `X-Request-ID: req001`

  

Cookie（通过 Cookie 请求头发送）

    `session_id=demo001; theme=dark`

  

请求体 Body

    ```json
    {
      "message": "请解释什么是 FastAPI",
      "max_steps": 3
    }
    ```

注意一个细节：

**从 HTTP 协议角度看，Cookie 是通过一个名为 `Cookie` 的请求头发送的；但 FastAPI 提供了专门的 `Cookie()`，帮我们直接提取其中单个 Cookie 的值。**

你可以这样理解它们的典型分工：

| 数据来源 | FastAPI 工具 | Agent 项目中的例子 |
|---|---|---|
| Path | `Path()` | 选择 Agent ID |
| Query | `Query()` | 是否开启详细输出 |
| Body | `Body()`、`BaseModel` | 用户消息和任务参数 |
| Cookie | `Cookie()` | 会话标识、界面偏好 |
| Header | `Header()` | 请求追踪 ID、客户端标识、授权信息 |

这五种参数来源能够在同一个接口中一起使用。

# 第一章：Cookie 参数 🍪

## 二、什么是 Cookie？

假设你访问一个聊天网站，第一次打开时选择了深色主题。

下一次访问时，网站仍然显示深色主题。

一种可能的实现方式，是浏览器保存了：

```text
theme=dark
```

然后在之后符合条件的请求中携带：

```http
Cookie: theme=dark
```

后端读取 Cookie，就可以知道客户端保存了什么偏好设置。

Cookie 还常用于会话管理，但这里必须区分：

**Cookie 可以携带会话标识，并不意味着客户端传来的任何 session_id 都能直接证明用户身份。** 真实应用必须由服务器验证会话的有效性与所属用户。

## 三、官方代码：读取单个 Cookie

官方教程使用 `ads_id` 作为示例。

```python
from typing import Annotated

from fastapi import Cookie, FastAPI

app = FastAPI()


@app.get("/items/")
async def read_items(
    ads_id: Annotated[str | None, Cookie()] = None
):
    return {"ads_id": ads_id}
```

### 1. 逐行拆解

首先：

```python
from fastapi import Cookie, FastAPI
```

这里的 `Cookie` 与之前学过的 `Query`、`Path` 类似，都是 FastAPI 提供的参数声明工具。

接下来：

```python
ads_id: Annotated[str | None, Cookie()] = None
```

我们拆成四部分：

| 代码 | 作用 |
|---|---|
| `ads_id` | Python 函数参数名 |
| `str \| None` | 允许字符串或 None |
| `Cookie()` | 明确从 Cookie 中读取，而不是从 Query 中读取 |
| `= None` | 没有发送这个 Cookie 时，默认使用 None |

因此这个 Cookie 参数**不是必填的**。

### 2. 客户端如何发送 Cookie？

请求：

```http
GET /items/ HTTP/1.1
Host: 127.0.0.1:8000
Cookie: ads_id=abc123
```

FastAPI 会提取：

```python
ads_id = "abc123"
```

响应：

```json
{
  "ads_id": "abc123"
}
```

如果没有发送该 Cookie：

```http
GET /items/ HTTP/1.1
Host: 127.0.0.1:8000
```

响应：

```json
{
  "ads_id": null
}
```

### 3. 如果不写 Cookie() 会怎样？

假设写成：

```python
@app.get("/items/")
def read_items(ads_id: str | None = None):
    return {"ads_id": ads_id}
```

FastAPI 通常会把 `ads_id` 识别为 **Query 参数**。

于是期望：

```text
GET /items/?ads_id=abc123
```

而不是读取 Cookie。

所以这一章最关键的是：

**当你希望参数来自 Cookie 时，要明确使用 `Cookie()`。**

### 4. Cookie 同样支持字段校验

比如：

```python
@app.get("/session")
def read_session(
    session_id: Annotated[
        str,
        Cookie(min_length=3, max_length=40)
    ]
):
    return {"has_session": True}
```

这里：

- `session_id` 是必填 Cookie。
- 长度至少为 3。
- 长度最多为 40。

没有携带这个 Cookie，或者长度不符合要求，FastAPI 通常返回 **HTTP 422**。

但请注意，长度验证只是检查格式；它不代表服务器已经验证了真实的登录状态。
