## 一、FastAPI 是什么？

### 1. 用一句话理解

**FastAPI 是一个基于 Python 的 Web API 开发框架，可以让你把 Python 函数变成能够通过网络调用的接口。**

举个例子：

假设你使用 Python 写好了一个智能助手：

```python
def my_agent(question):
    return "这是 Agent 的回答"
```

这个函数只能在 Python 程序中直接调用。

但如果你想让网页、手机 App、Dify 工作流或者其他服务使用它，就需要一个对外提供访问的接口。

FastAPI 正是帮助你完成这件事的工具。

### 2. 理解 FastAPI 的几个核心概念

| 概念 | 小白理解 | Agent 开发用途 |
|---|---|---|
| API | 程序之间沟通的窗口 | 前端调用 Agent |
| HTTP | 网络通信的规则 | 传递用户问题与回答 |
| GET | 获取信息 | 查询 Agent 服务状态 |
| POST | 发送数据 | 向 Agent 发送问题 |
| JSON | 通用数据格式 | 传递消息、工具调用结果 |
| Pydantic | 数据检查工具 | 检查用户输入是否合法 |
| async/await | 处理等待任务的机制 | 等待 LLM、数据库等外部服务 |
| Swagger UI | 自动生成的接口调试页面 | 不写前端也能测试 Agent |

FastAPI 的几个重要特点是：支持 Python 类型提示、利用 Pydantic 做数据验证、提供依赖注入，并能自动生成基于 OpenAPI 的交互式文档。

你可以把它们理解为一家餐厅：

- **FastAPI 是服务员**：负责接收顾客需求、传递订单、送回结果。
- **Agent 是厨师**：决定如何完成任务。
- **LLM 是厨师的大脑**：负责理解和生成内容。
- **Tools 是厨房工具**：例如联网搜索、数据库查询、调用其他 API。
- **Memory 是订单记录**：帮助系统记住当前任务和历史上下文。

一个重要结论是：**FastAPI 本身不会让 Agent 变聪明，它负责让你开发的 Agent 能被稳定、规范地访问。**

## 二、在 Agent 开发中如何使用 FastAPI？

### 1. FastAPI 在 Agent 中的 5 个典型用途

| 场景 | FastAPI 的作用 | 示例接口 |
|---|---|---|
| Agent 对话 | 接收用户问题，调用 Agent | `POST /chat` |
| 工具服务 | 将 Python 函数开放给其他程序 | `POST /tools/search` |
| 多轮对话 | 管理会话 ID，查询历史消息 | `GET /sessions/{id}` |
| 流式响应 | 逐步返回 LLM 的输出 | `POST /chat/stream` |
| 服务管理 | 健康检查、认证、监控 | `GET /health` |

例如，你开发了一个订单查询 Agent，使用 FastAPI 后，网页可以向 `/chat` 发送：

```json
{
  "message": "帮我查询最新订单"
}
```

FastAPI 接到消息，调用 Agent。Agent 再决定是否调用查询订单的工具，最后由 FastAPI 返回结果。

```bash
python -m pip install "fastapi[standard]"
```

**第二步：创建 `main.py`**

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

# 创建 FastAPI 应用
app = FastAPI(title="My First Agent API")

# 定义用户输入的数据格式
class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)

# 定义返回结果的数据格式
class ChatResponse(BaseModel):
    answer: str

# 这是模拟 Agent，后续替换成真正的 LLM Agent
def run_agent(question: str) -> str:
    if "FastAPI" in question:
        return "FastAPI 可以把 Agent 封装为 Web API。"
    return f"模拟 Agent 收到了你的问题：{question}"

# 健康检查接口
@app.get("/health")
def health():
    return {"status": "ok"}

# 对话接口
@app.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest):
    result = run_agent(request.message)
    return ChatResponse(answer=result)
```

**第三步：启动服务**

```bash
fastapi dev main.py
```

## 二、为什么会出现 404？

你日志里实际上有三种情况。

### 问题 1：访问 `/` 返回 404

```text
GET / HTTP/1.1" 404
```

因为你的代码里只有两个自定义接口：

```python
@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest):
    result = run_agent(request.message)
    return ChatResponse(answer=result)
```

并没有定义：

```python
@app.get("/")
```

因此，当你访问：

```text
http://127.0.0.1:8000/
```

FastAPI 找不到对应的接口，就会返回：

```json
{
  "detail": "Not Found"
}
```

这是正常行为。

### 问题 2：访问 `/docs` 和 `/health` 返回 404

注意你日志里的这两行：

```text
GET /docs%2A%2A?utm_source=chatgpt.com HTTP/1.1" 404

GET /health%2A%2A?utm_source=chatgpt.com HTTP/1.1" 404
```

关键是：

`%2A` 是字符 `*` 的 URL 编码。

所以：

```text
/docs%2A%2A
```

实际上相当于：

```text
/docs**
```

FastAPI 识别的是 `/docs`，而不是 `/docs**`。

同样，`/health**` 也不是你定义的 `/health`。

这可能是我前面提供的链接格式造成的，抱歉！其中的 `utm_source=chatgpt.com` 只是查询参数，不是这次 404 的原因。

### 问题 3：`favicon.ico` 返回 404

```text
GET /favicon.ico HTTP/1.1" 404
```

这是因为浏览器会尝试获取网站图标，而你的 FastAPI 项目没有提供这个文件。

**完全不用管它，不影响任何 API 功能。**

## 三、建议你做个小修改

为了让你访问根路径 `/` 时也能看到正常内容，可以在 `first.py` 中增加一个接口。

你的其他代码都不需要修改。

```python
# 首页接口
@app.get("/")
def home():
    return {
        "message": "欢迎使用我的第一个 Agent API",
        "docs": "/docs",
        "health": "/health"
    }
```

此时你的 API 会有以下功能：

| 路径 | 请求方法 | 作用 |
|---|---|---|
| `/` | GET | 显示欢迎信息 |
| `/health` | GET | 检查服务状态 |
| `/chat` | POST | 调用模拟 Agent |
| `/docs` | GET | 打开自动生成的接口文档 |

FastAPI 的开发模式会自动检测代码变化并重新加载，所以一般不需要手动重启。
