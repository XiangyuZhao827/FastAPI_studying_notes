## 一、先回顾：普通查询参数有什么不足？

### 1. 前一章的写法

在《查询参数》这一章，我们写过：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/")
def read_items(q: str | None = None):
    results = {
        "items": [
            {"item_id": "Foo"},
            {"item_id": "Bar"}
        ]
    }

    if q:
        results.update({"q": q})

    return results
```

假设访问：

```text
/items/?q=python
```

得到：

```json
{
  "items": [
    {"item_id": "Foo"},
    {"item_id": "Bar"}
  ],
  "q": "python"
}
```

我们已经知道：

```python
q: str | None = None
```

表示：

| 组成部分 | 含义 |
|---|---|
| `q` | 参数名称 |
| `str` | 允许字符串 |
| `\| None` | Python 类型允许 None |
| `= None` | 没有传入时默认使用 None |

但是这个接口存在一个问题。

假设用户访问：

```text
/items/?q=a
```

或者传入一个几千字符的关键词，普通的 `str` 类型都不会限制其长度。

因此，我们需要新的工具来定义更严格的规则。

### 2. 为什么需要字符串校验？

假设你开发一个 Agent 搜索功能。

你希望用户的关键词至少为 3 个字符，最长不超过 50 个字符。

那么：

| 用户传入的 q | 是否允许 | 原因 |
|---|---|---|
| 不传 q | ✅ | 参数可选 |
| `python` | ✅ | 长度符合要求 |
| `AI` | ❌ | 只有 2 个字符 |
| `FastAPI` | ✅ | 有 7 个字符 |
| 超过 50 个字符 | ❌ | 超过最大长度 |

注意：这里不是让你自己写几十行 `if` 去检查，而是**让 FastAPI 自动完成这些验证**。

## 二、认识 `Query()`：它到底是什么？

这一节是整章的基础。

### 1. 从 FastAPI 导入 Query

官方代码：

```python
from fastapi import FastAPI, Query
```

这里的：

```python
Query
```

是 FastAPI 提供的参数声明工具。

它用于告诉 FastAPI：

> 这是一个查询参数，我还想为它指定额外的验证规则和文档信息。

例如：

```python
Query(max_length=50)
```

表示查询参数的字符串长度不能超过 50。

再例如：

```python
Query(min_length=3, max_length=50)
```

表示字符串长度必须在 3 到 50 之间，包括边界。

**Query 的作用不是查询数据库，而是声明 HTTP 查询参数的规则。**

这点对于学习 Agent 开发特别重要。

因为 `Query` 这个单词容易让人联想到：

- 数据库查询
- RAG 检索
- 用户提问
- 搜索引擎查询

但这里的 `Query()` 与这些具体业务功能没有直接关系，它是 FastAPI 的接口参数声明工具。

### 2. 最简单的 Query 示例

先看一种旧式但仍然受支持的写法：

```python
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: str | None = Query(
        default=None,
        max_length=50
    )
):
    return {"q": q}
```

重点：

```python
q: str | None = Query(default=None, max_length=50)
```

它表示：

- `q` 是查询参数。
- `q` 可以是字符串或 None。
- 如果不传，默认使用 None。
- 如果传入字符串，长度最多 50 个字符。

例如：

```text
/items/?q=hello
```

返回：

```json
{
  "q": "hello"
}
```

而超过 50 个字符的参数会触发数据校验错误，FastAPI 返回 HTTP 422。

### 3. 为什么官方还要引入 Annotated？

因为虽然上面的写法能够正常工作，但官方现在更推荐将**类型信息、验证规则、默认值分开写**。

也就是：

```python
q: Annotated[str | None, Query(max_length=50)] = None
```

接下来我们把它彻底拆解。

## 三、`Annotated` 是什么？为什么这么写？

这是本章最需要理解的知识点。⭐

### 1. 先理解 Python 的类型注解

你之前已经会写：

```python
name: str
age: int
price: float
```

这些代码中的：

```python
: str
: int
: float
```

都是 Python 类型注解。

它们用于描述数据应该是什么类型。

现在假设我们不仅要规定：

```python
name: str
```

还要告诉 FastAPI：

> name 必须是字符串，而且最长只能有 20 个字符。

这就需要额外的元数据。

### 2. Annotated 就是给类型附加额外信息

首先导入：

```python
from typing import Annotated
```

`Annotated` 是 Python 标准库 `typing` 提供的工具。

它的基本形式是：

```python
Annotated[数据类型, 额外信息]
```

例如：

```python
Annotated[str, Query(max_length=20)]
```

拆开来看：

  
Annotated 语法结构

    
`Annotated[str, Query(max_length=20)]`

      

          **Annotated**
          
附加元数据的工具

      

        

          **str**
          
Python 数据类型

      

        

          **Query(...)**
          
FastAPI 校验规则

      

  

你可以把它理解为：

**`Annotated` 负责把类型和额外说明包装在一起，而 `Query()` 提供具体的查询参数规则。**

注意：`Annotated` 自己不会自动执行长度验证。真正读取这些元数据并进行校验的是 FastAPI 和它使用的数据验证机制。

### 3. 把完整代码一步一步拆开

现在来看官方推荐写法：

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/items/")
def read_items(
    q: Annotated[str | None, Query(max_length=50)] = None
):
    return {"q": q}
```

我们只分析这一行：

```python
q: Annotated[str | None, Query(max_length=50)] = None
```

  
拆成四层理解

    **第一层：`q`**
    
这是函数参数的名称。

  

    **第二层：`str | None`**
    
表示 q 可以是字符串，也可以是 None。

  

    **第三层：`Query(max_length=50)`**
    
给 FastAPI 增加字符串长度不能超过 50 的校验规则。

  

    **第四层：`= None`**
    
用户不传 q 时，使用 None，所以这是非必填参数。

最终这行代码的意思就是：

> q 是一个可选查询参数，如果用户填写，必须是长度不超过 50 的字符串。

### 4. 为什么 `= None` 放在 Annotated 的外面？

这是因为：

```python
Annotated[str | None, Query(max_length=50)]
```

描述的是**类型和校验规则**。

而：

```python
= None
```

描述的是**Python 函数参数的默认值**。

两者各司其职。

我们可以对比：

| 代码部分 | 负责什么 |
|---|---|
| `str \| None` | 允许的数据类型 |
| `Query(max_length=50)` | 额外的校验规则 |
| `= None` | 没传参数时的默认值 |

因此，在推荐写法中，**不要把默认值再写进 Annotated 里面的 Query**。

推荐：

```python
q: Annotated[str | None, Query(max_length=50)] = None
```

不推荐混用成：

```python
q: Annotated[
    str | None,
    Query(default=None, max_length=50)
] = None
```

在这种 `Annotated` 声明方式中，应该让 Python 函数自身负责默认值。

### 5. 旧写法和新写法有什么区别？

| 旧式写法 | 官方推荐写法 |
|---|---|
| `q: str \| None = Query(default=None, max_length=50)` | `q: Annotated[str \| None, Query(max_length=50)] = None` |
| 验证规则和默认值放在 Query 中 | 类型、规则、默认值分工更清晰 |
| 仍然可以使用 | 新项目优先使用 |

官方推荐 `Annotated`，一个重要原因是：Python 函数的真正默认值保持为普通的 `None` 或其他默认值，脱离 FastAPI 直接调用函数时也更符合 Python 的直觉。

在你后续学习其他 FastAPI 工具时，也会遇到类似写法：

```python
Annotated[int, Path(...)]
Annotated[str, Header(...)]
Annotated[str, Body(...)]
```

不需要现在掌握它们，只要知道 `Annotated` 是一种可复用的类型注解方式。

## 四、字符串长度校验：min_length 和 max_length

你已经知道：

```python
Query(max_length=50)
```

是限制最大长度。

那么，如果还想限制最小长度呢？

答案是：

```python
Query(min_length=3, max_length=50)
```

### 1. 官方完整代码

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: Annotated[
        str | None,
        Query(min_length=3, max_length=50)
    ] = None
):
    results = {
        "items": [
            {"item_id": "Foo"},
            {"item_id": "Bar"}
        ]
    }

    if q:
        results.update({"q": q})

    return results
```

注意：代码虽然换成了多行，但核心与单行写法完全一样。

```python
q: Annotated[str | None, Query(min_length=3, max_length=50)] = None
```

### 2. min_length 和 max_length 分别是什么意思？

```python
min_length=3
```

表示字符串长度最少为 3。

```python
max_length=50
```

表示字符串长度最多为 50。

所以允许的范围是：

\[
3 \leq \operatorname{len}(q) \leq 50
\]

这里的 `len(q)` 是 Python 获取字符串长度的函数。

例如：

```python
len("AI")       # 2
len("Agent")    # 5
len("FastAPI")  # 7
```

### 3. 如果 q 是可选参数，为什么还有最小长度？

因为：

```python
= None
```

表示可以完全不传 q。

但是，一旦传入 q，就要满足长度要求。

例如：

| URL | 状态码 | 说明 |
|---|---|---|
| `/items/` | 200 | 没传 q，允许 |
| `/items/?q=AI` | 422 | 长度只有 2 |
| `/items/?q=Agent` | 200 | 长度为 5 |
| `/items/?q=` | 422 | 传入了空字符串 |
| q 超过 50 个字符 | 422 | 超出长度上限 |

这也解释了一个重要区别：

**没有传入参数，与传入空字符串，并不是一回事。**

### 5. 与上一章的 Field 有什么关系？

你在《请求体》一章已经见过：

```python
from pydantic import Field

class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
```

现在又学到了：

```python
q: Annotated[
    str,
    Query(min_length=3, max_length=50)
]
```

是不是非常相似？

| 对比 | Query | Field |
|---|---|---|
| 常见使用位置 | 查询参数 | Pydantic 模型字段 |
| 可以设置 min_length | ✅ | ✅ |
| 可以设置 max_length | ✅ | ✅ |
| 可以帮助生成 API 文档 | ✅ | ✅ |
| 主要目的 | 描述和校验 HTTP 查询参数 | 描述和校验模型字段 |

**记忆方法：Query 管查询参数，Field 管模型字段。**

## 五、正则表达式校验：`pattern` 是什么？

官方这一节叫作「添加正则表达式」。

这是很多 Python 初学者第一次看到正则表达式（Regular Expression）。

### 1. 为什么需要正则表达式？

我们已经能够限制字符串长度：

```python
Query(min_length=3, max_length=50)
```

但是有些场景，仅仅限制长度还不够。

例如，你开发了一个 Agent 系统，只允许选择三种工作模式：

```text
chat
code
research
```

假设用户输入：

```text
music
```

虽然它符合字符串长度要求，但并不是我们允许的工作模式。

这时候就需要限制**字符串的内容格式**。

正则表达式就是用来描述字符串应当匹配什么模式的一种规则。

### 2. 先看官方示例

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: Annotated[
        str | None,
        Query(
            min_length=3,
            max_length=50,
            pattern="^fixedquery$"
        )
    ] = None
):
    return {"q": q}
```

这里新增了：

```python
pattern="^fixedquery$"
```

这就是正则表达式校验。

它要求 q 的值必须匹配 `fixedquery`，不能有额外的前后字符。

### 3. `^` 和 `$` 分别是什么意思？

我们拆开看：

```text
^fixedquery$
```

| 符号 | 含义 |
|---|---|
| `^` | 要从字符串开头匹配 |
| `fixedquery` | 要匹配的具体字符 |
| `$` | 匹配到字符串末尾 |

可以这样理解：

  

      

        **^**

      

        **fixedquery**

      

        **$**

    

      

开头

      

具体内容

      

结尾

    

  
这里介绍的是基本的匹配方式。对于需要严格匹配到绝对结尾的复杂情况，还会涉及 `\Z` 等其他正则表达式语法。

来看看测试结果：

| q 的值 | 是否通过 |
|---|---|
| `fixedquery` | ✅ |
| `fixed` | ❌ |
| `myfixedquery` | ❌ |
| `fixedquery123` | ❌ |
| `hello` | ❌ |
| 不传 q | ✅，因为默认值是 None |

### 4. 在 Agent 开发中怎么使用？

假设我们希望接口只能接收：

```text
chat
code
research
```

可以使用：

```python
@app.get("/models/")
def get_model(
    mode: Annotated[
        str,
        Query(pattern=r"^(chat|code|research)$")
    ] = "chat"
):
    return {"mode": mode}
```

这里：

```python
(chat|code|research)
```

表示三种选择中的任意一种。

`|` 在正则表达式里表示「或」。

注意：它和 Python 类型注解中的 `str | None` 虽然使用了相同符号，但含义不一样。

测试：

```text
/models/?mode=chat
/models/?mode=code
/models/?mode=research
```

都能够成功。

但是：

```text
/models/?mode=music
```

会返回 HTTP 422。

如果你觉得正则表达式难理解，完全正常。这个阶段先掌握 `^`、`$`、`|` 和 `pattern` 的用途就够了。

而且，对于仅有少数固定选项的场景，你在《路径参数》一章学习过的 **Enum 通常更容易阅读和维护**。

## 六、默认值、必填参数，以及可以为 None 的参数

这部分其实是上一章知识的延伸，但加上 `Annotated` 后，写法会有些变化。

### 1. 有默认值的查询参数

官方示例：

```python
@app.get("/items/")
def read_items(
    q: Annotated[str, Query(min_length=3)] = "fixedquery"
):
    return {"q": q}
```

这里：

```python
= "fixedquery"
```

说明用户不传 q 时，会使用 `"fixedquery"`。

访问：

```text
/items/
```

返回：

```json
{
  "q": "fixedquery"
}
```

访问：

```text
/items/?q=hello
```

返回：

```json
{
  "q": "hello"
}
```

但：

```text
/items/?q=hi
```

会返回 422，因为 `hi` 只有两个字符。

### 2. 必填查询参数

如果你希望用户必须传入 q，就去掉默认值：

```python
@app.get("/items/")
def read_items(
    q: Annotated[str, Query(min_length=3)]
):
    return {"q": q}
```

重点是：

```python
q: Annotated[str, Query(min_length=3)]
```

没有 `= None` 或其他默认值。

因此：

```text
/items/
```

会返回 422，原因是缺少必填查询参数 q。

而：

```text
/items/?q=python
```

可以正常执行。

### 3. 必填，但允许 None

官方还提供了这种写法：

```python
@app.get("/items/")
def read_items(
    q: Annotated[
        str | None,
        Query(min_length=3)
    ]
):
    return {"q": q}
```

你可能会困惑：

> 既然 q 可以是 None，为什么还要求必填？

因为**参数是否必填**和**Python 类型是否允许 None**是两回事。

虽然：

```python
str | None
```

允许 Python 层面的 `None`，但我们没有给函数参数设置默认值，所以 FastAPI 仍然要求客户端提供 q。

而且，普通 URL 查询参数本身没有专门表示 Python `None` 的方式。

例如：

```text
/items/?q=None
```

这里的 `None` 其实是字符串 `"None"`。

同样：

```text
/items/?q=null
```

这里的 `null` 也是字符串 `"null"`。

它们并不会自动变成 Python 的 `None`。

这是和 JSON 请求体的重要区别：JSON 可以明确包含 `null`。

### 4. 四种常见写法对比

| 写法 | 必填吗 | 不传参数时 |
|---|---|---|
| `q: Annotated[str, Query()]` | ✅ | 422 |
| `q: Annotated[str, Query()] = "hello"` | ❌ | `"hello"` |
| `q: Annotated[str \| None, Query()] = None` | ❌ | `None` |
| `q: Annotated[str \| None, Query()]` | ✅ | 422 |

最重要的结论：

**有无默认值决定这个查询参数是否必填；类型注解决定它允许什么 Python 类型。**

## 七、查询参数列表：一个参数怎么接收多个值？

这是本章非常实用的一节！⭐

假设你开发一个 Agent 管理系统，希望按多个标签筛选 Agent。

用户可以同时选择：

```text
python
coding
research
```

那么如何把多个标签传给 FastAPI 呢？

### 1. 先看 URL

```text
/agents/?tag=python&tag=coding&tag=research
```

你会发现：

`tag` 重复出现了三次。

在普通的 URL 查询字符串中，这是允许的。

但是，如果你希望 FastAPI 把这些值全部收集起来，就需要声明一个列表类型。

### 2. 官方的列表写法

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: Annotated[list[str] | None, Query()] = None
):
    return {"q": q}
```

关键是：

```python
q: Annotated[list[str] | None, Query()] = None
```

这次我们再拆成几部分。

**第一部分：**

```python
list[str]
```

表示 Python 列表，里面的每个元素应当是字符串。

例如：

```python
["python", "fastapi", "agent"]
```

**第二部分：**

```python
| None
```

表示这个值也可以为 None。

**第三部分：**

```python
Query()
```

明确告诉 FastAPI，这是查询参数。

**第四部分：**

```python
= None
```

表示用户可以不提供这个参数。

### 3. 实际请求会怎样？

假设访问：

```text
/items/?q=foo&q=bar
```

FastAPI 会把两个 q 合并为一个 Python 列表：

```python
q = ["foo", "bar"]
```

最终返回：

```json
{
  "q": ["foo", "bar"]
}
```

这个过程可以这样理解：

  

    **URL 查询字符串**
    
`?q=foo&q=bar`

  

  

    **FastAPI 识别重复的 q**
    
根据 `list[str]` 收集所有值

  

  

    **Python 列表**
    `["foo", "bar"]`

### 4. 为什么这里必须显式使用 Query？

这点特别重要。

如果你只写：

```python
@app.get("/items/")
def read_items(q: list[str]):
    return {"q": q}
```

FastAPI 一般会把 `q` 当作**请求体参数**，而不是查询参数。

因为列表已经属于比普通 `str`、`int` 更复杂的数据类型。

所以，我们需要：

```python
q: Annotated[list[str], Query()]
```

明确指定它来自 URL 查询字符串。

这是官方教程特别强调的一个知识点。

### 5. 为列表设置默认值

官方还给出了一个例子：

```python
@app.get("/items/")
def read_items(
    q: Annotated[list[str], Query()] = ["foo", "bar"]
):
    return {"q": q}
```

如果访问：

```text
/items/
```

没有传 q，就使用默认列表：

```json
{
  "q": ["foo", "bar"]
}
```

如果访问：

```text
/items/?q=python&q=fastapi
```

就使用传入的列表：

```json
{
  "q": ["python", "fastapi"]
}
```

### 6. 为什么推荐 `list[str]`，而不是普通 `list`？

对比：

```python
q: Annotated[list[str], Query()]
```

与：

```python
q: Annotated[list, Query()]
```

第一种明确告诉 FastAPI：

> 这是一个列表，而且每个元素都应该是字符串。

第二种只告诉 FastAPI：

> 这是一个列表。

如果使用 `list[int]`，FastAPI 还会尝试把每个查询参数解析为整数。

因此，开发 Agent API 时，建议尽量写清楚列表元素类型。这样代码更容易理解，校验和自动文档也更准确。

## 九、别名参数：为什么需要 `alias`？

这也是非常实用的知识点。

### 1. 问题：URL 参数名和 Python 变量名不一定相同

假设你的前端发送：

```text
/items/?item-query=python
```

注意：

```text
item-query
```

包含减号 `-`。

但 Python 变量名不能这样写：

```python
def read_items(item-query: str):
    ...
```

这是非法的 Python 语法。

因为 Python 会把 `-` 识别成减号运算符。

那么我们怎么接收 URL 中的 `item-query` 呢？

答案是：使用 **alias（别名）**。

### 2. 官方代码

```python
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items/")
def read_items(
    q: Annotated[
        str | None,
        Query(alias="item-query")
    ] = None
):
    return {"q": q}
```

重点：

```python
Query(alias="item-query")
```

它告诉 FastAPI：

> 虽然 Python 函数中的参数叫 q，但客户端需要通过 URL 中的 item-query 给它传值。

### 3. 运行过程

用户请求：

```text
/items/?item-query=python
```

FastAPI 首先找到：

```text
item-query=python
```

然后根据：

```python
alias="item-query"
```

把值绑定到函数参数：

```python
q = "python"
```

最终返回：

```json
{
  "q": "python"
}
```

  

    **URL 中的参数名**
    `item-query=python`

  

    
Query(alias="item-query")

  

    **Python 函数内部**
    `q = "python"`

注意：设置 `alias="item-query"` 后，这个参数通常就要通过 `item-query` 传值。不能想当然地认为 `?q=python` 也会同时生效。

**一句话记住：alias 让 API 对外的参数名称，与 Python 内部的变量名称可以不同。**

## 十、弃用参数：`deprecated=True` 是什么意思？

假设你开发了一个 Agent 平台。

最开始使用：

```text
/agents/?old_query=python
```

后来你觉得这个命名不好，希望改成：

```text
/agents/?search=python
```

但问题是：已经有其他应用在使用旧接口了。

如果你直接删除 `old_query`，这些应用就可能出现问题。

于是你希望：

- 暂时保留旧参数。
- 告诉其他开发者它不推荐继续使用。
- 鼓励大家迁移到新参数。

这就是 `deprecated=True` 的用途。

### 1. 代码示例

```python
@app.get("/agents/")
def search_agents(
    old_query: Annotated[
        str | None,
        Query(deprecated=True)
    ] = None
):
    return {"old_query": old_query}
```

`deprecated=True` 表示：

**这个参数已经被标记为弃用。**

在 `/docs` 中，会显示对应的弃用提示或标识。

但需要特别注意：

```python
deprecated=True
```

**不会让参数自动失效。**

它只是为 API 文档和调用方提供一条迁移信息。

只要你的代码仍然支持这个参数，客户端就依然可以使用它。

## 十一、从 OpenAPI 中隐藏参数：`include_in_schema=False`

官方这一节讲了一个比较特殊的选项：

```python
include_in_schema=False
```

### 1. 代码示例

```python
@app.get("/items/")
def read_items(
    hidden_query: Annotated[
        str | None,
        Query(include_in_schema=False)
    ] = None
):
    return {"hidden_query": hidden_query}
```

正常情况下，FastAPI 会在 OpenAPI 文档中列出所有声明的查询参数。

但是：

```python
Query(include_in_schema=False)
```

会告诉 FastAPI：

> 不要把这个参数包含在自动生成的 OpenAPI Schema 中。

因此，它通常不会显示在 Swagger UI 的参数列表中。

### 2. 隐藏后还能传入吗？

可以。

例如：

```text
/items/?hidden_query=hello
```

仍然会被 FastAPI 接收。

返回：

```json
{
  "hidden_query": "hello"
}
```

所以：

| 配置 | 文档是否显示参数 | 能否正常使用 |
|---|---|---|
| `include_in_schema=True` | ✅ | ✅ |
| `include_in_schema=False` | ❌ | ✅ |

这里有一个很重要的安全知识：

**隐藏参数不等于保护参数。**

即使没有显示在 `/docs` 中，别人仍然可能知道或猜出这个参数名称，并直接调用。

所以千万不要把 `include_in_schema=False` 当成身份验证、权限控制或保护 API Key 的手段。

这一节属于较进阶的接口文档管理知识，第一周学习时知道它的作用即可。

## 十二、自定义校验：AfterValidator 是什么？

这一部分是官方教程中比较进阶的内容。

到目前为止，我们已经可以使用：

```python
min_length
max_length
pattern
```

校验字符串。

但是，有些特殊的业务规则并不能方便地使用这些参数描述。

例如：

> 用户提交的资源 ID，必须以 `isbn-` 或 `imdb-` 开头。

这种情况，可以使用 Pydantic 的 `AfterValidator`。

### 1. 官方示例的核心代码

```python
from typing import Annotated
from fastapi import FastAPI
from pydantic import AfterValidator

app = FastAPI()


def check_valid_id(id: str) -> str:
    if not id.startswith(("isbn-", "imdb-")):
        raise ValueError(
            'ID must start with "isbn-" or "imdb-"'
        )

    return id


@app.get("/items/")
def read_items(
    id: Annotated[
        str | None,
        AfterValidator(check_valid_id)
    ] = None
):
    return {"id": id}
```

这是官方校验逻辑的简化版本，先专注于最重要的部分。

### 2. 什么是 AfterValidator？

先看：

```python
AfterValidator(check_valid_id)
```

它的意思是：

> 在常规类型解析和验证后，使用 `check_valid_id` 这个 Python 函数继续检查数据。

整个流程是：

  

    **用户提交 ID**
    
`?id=isbn-123456`

  

  

    **Pydantic 进行基础类型校验**
    
检查是否符合 str 等基本要求

  

  

    **执行 check_valid_id()**
    
检查字符串前缀

  

  

      

        **符合规则**
        
继续执行接口

    

      

        **不符合规则**
        
返回 422

    

### 3. `startswith()` 是什么意思？

代码中有一行：

```python
id.startswith(("isbn-", "imdb-"))
```

`startswith()` 是 Python 字符串自带的方法。

作用是判断字符串是不是以指定内容开头。

例如：

```python
name = "python_agent"

print(name.startswith("python"))
# True

print(name.startswith("java"))
# False
```

而：

```python
("isbn-", "imdb-")
```

是一个 Python 元组（tuple）。

当 `startswith()` 接收元组时，只要匹配其中任意一个前缀，就返回 True。

例如：

```python
"isbn-123".startswith(("isbn-", "imdb-"))
# True

"imdb-456".startswith(("isbn-", "imdb-"))
# True

"hello-123".startswith(("isbn-", "imdb-"))
# False
```

### 4. `raise ValueError` 是什么意思？

看这段：

```python
if not id.startswith(("isbn-", "imdb-")):
    raise ValueError("Invalid ID format")
```

这里：

```python
raise
```

表示主动抛出异常。

```python
ValueError
```

是一种 Python 异常类型，表示数据的值不符合要求。

在这个 Pydantic 自定义验证场景中，抛出的 `ValueError` 会被转换为输入校验错误，FastAPI 通常返回 HTTP 422。

因此：

```text
/items/?id=isbn-123
```

校验成功。

而：

```text
/items/?id=hello
```

校验失败。

### 5. 为什么函数最后要写 `return id`？

```python
def check_valid_id(id: str) -> str:
    if not id.startswith(("isbn-", "imdb-")):
        raise ValueError("Invalid ID format")

    return id
```

因为自定义验证函数需要返回验证后的值。

如果验证成功，我们就把原来的 id 返回。

以后你也可以编写更复杂的转换逻辑，但当前这个例子只负责检查格式，不修改数据。

### 6. 官方代码中的 random.choice() 是什么？

官方原始示例还包含一个模拟数据字典，以及这样的代码：

```python
id, item = random.choice(list(data.items()))
```

这行其实与 FastAPI 没有直接关系，是普通 Python 语法。

假设有：

```python
import random

data = {
    "isbn-123": "Python Book",
    "imdb-456": "Python Movie"
}
```

那么：

```python
data.items()
```

可以获得由键值对组成的数据。

```python
list(data.items())
```

将其转换成列表，类似：

```python
[
    ("isbn-123", "Python Book"),
    ("imdb-456", "Python Movie")
]
```

接下来：

```python
random.choice(...)
```

会从列表中随机选一个元素。

假设选中：

```python
("isbn-123", "Python Book")
```

通过：

```python
id, item = ...
```

就可以分别得到：

```python
id = "isbn-123"
item = "Python Book"
```

官方用它实现：用户不传 ID 时，随机推荐一个条目。

还需要注意：**ID 格式合法，不代表这个 ID 一定存在于数据库中。**

例如，`isbn-999` 虽然通过了前缀校验，但未必有对应的数据。

### 7. 在 Agent 开发中怎么使用？

我们可以要求 Agent ID 必须以 `agent-` 开头：

```python
from typing import Annotated
from fastapi import FastAPI
from pydantic import AfterValidator

app = FastAPI()


def validate_agent_id(agent_id: str) -> str:
    if not agent_id.startswith("agent-"):
        raise ValueError(
            "Agent ID must start with agent-"
        )

    return agent_id


@app.get("/agent-details/")
def get_agent(
    agent_id: Annotated[
        str,
        AfterValidator(validate_agent_id)
    ]
):
    return {"agent_id": agent_id}
```

例如：

```text
/agent-details/?agent_id=agent-123
```

成功。

但是：

```text
/agent-details/?agent_id=123
```

返回 422。

这样你就能利用 Pydantic 的自定义验证逻辑，在进入业务函数之前检查 Agent ID 的格式。

`AfterValidator` 需要 Pydantic v2 或更高版本。官方还特别建议：如果校验涉及数据库访问、外部 API 等操作，应考虑使用 FastAPI 依赖注入等机制，而不是把网络请求直接放进这种简单字段验证函数。

```python
@app.get("/agent-details/")
def get_agent_details(
    agent_id: Annotated[
        str | None,
        AfterValidator(validate_agent_id)
    ] = None
):
    if agent_id is None:
        return {"message": "No agent ID provided"}

    for agent in fake_agents:
        if agent["id"] == agent_id:
            return {"agent": agent}

    return {
        "agent": None,
        "message": "Agent not found"
    }

class ChatRequest(BaseModel):
    message: str = Field(
        min_length=1,
        max_length=2000
    )


@app.post("/chat/")
def chat(
    request: ChatRequest,

    mode: Annotated[
        str,
        Query(pattern=r"^(chat|code|research)$")
    ] = "chat"
):
    return {
        "mode": mode,
        "answer": (
            f"[{mode}] 模拟 Agent 收到："
            f"{request.message}"
        )
    }
```

这份代码中的 Agent 数据都是模拟的，不需要调用真实大模型，也没有数据库连接。

其中有一段 Python 列表推导式：

```python
results = [
    agent for agent in results
    if q.lower() in agent["name"].lower()
]
```

它的意思是：遍历所有 Agent，只保留名称中包含查询关键词的 Agent。

`lower()` 把英文转换为小写，方便进行不区分大小写的搜索。

另一段：

```python
if any(t in agent["tags"] for t in tag)
```

使用了 Python 的 `any()`。

它表示：只要用户提供的任意一个标签存在于 Agent 的标签列表中，就保留这个 Agent。

这两段属于普通 Python 业务逻辑，而不是 FastAPI 特有的语法。

### 最后再帮你把核心语法记住

本章最重要的一行：

```python
q: Annotated[
    str | None,
    Query(min_length=3, max_length=50)
] = None
```

可以总结为三个问题：

| 问题 | 对应代码 | 答案 |
|---|---|---|
| q 可以是什么类型？ | `str \| None` | 字符串或 None |
| q 要符合什么规则？ | `Query(min_length=3, max_length=50)` | 长度在 3～50 之间 |
| 用户不传 q 会怎样？ | `= None` | 使用 None |

只要你理解了这三层含义，就掌握了 `Annotated + Query` 最核心的使用方法。

```python
from typing import Annotated
```
