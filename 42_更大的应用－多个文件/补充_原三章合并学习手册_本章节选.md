# 第一章　更大的应用－多个文件

官方文档：https://fastapi.tiangolo.com/zh/tutorial/bigger-applications/

## 1. 这一章主要解决什么？

初学时，main.py 只有 /health 与 /chat 两个路由，写在同一个文件里就够了。但真实 Agent 平台可能还有 /users、/agents、/sessions、/files、/admin 等功能。如果所有路径操作都放在一个文件中，阅读、修改和协作会越来越困难。

**目标不是启动更多服务器，而是在同一个 FastAPI 应用内，把不同业务接口拆分成多个 Python 文件。**

## 2. 官方目录结构怎样理解？

```text
app/
├── __init__.py
├── main.py
├── dependencies.py
├── routers/
│   ├── __init__.py
│   ├── items.py
│   └── users.py
└── internal/
    ├── __init__.py
    └── admin.py
```

- main.py：创建 FastAPI 主应用，负责把各个路由器加入应用。
- routers/*.py：存放某一组相关路径操作，例如用户和商品接口。
- dependencies.py：复用的依赖函数，能够被不同路由文件调用。
- internal/admin.py：另外一组后台管理接口。
- __init__.py：让 Python 的包结构与导入关系更明确。

## 3. 记住两个名字：APIRouter 和 include_router

在单文件中，我们用 `app = FastAPI()` 加 `@app.get(...)` 定义接口。拆分之后，在一个模块中使用 `router = APIRouter()` 加 `@router.get(...)`；最后在 main.py 中使用 `app.include_router(...)` 把路由注册到主应用。

```python
# app/routers/users.py：只演示本章最核心的两行
from fastapi import APIRouter
router = APIRouter()

@router.get('/users/')
def read_users():
    return [{'username': 'Rick'}]
```

```python
# app/main.py：在主应用中注册用户路由器
from fastapi import FastAPI
from .routers import users

app = FastAPI()
app.include_router(users.router)
```

**理解：** router 是“一组路由的收纳盒”；include_router 是“把盒子里的接口加入当前主应用”。路由仍然使用同一个 FastAPI 服务，而不是新的微服务。

## 4. Router 能统一配置哪些东西？

```python
router = APIRouter(
    prefix='/items',
    tags=['items'],
    dependencies=[Depends(get_token_header)],
    responses={404: {'description': 'Not found'}},
)
```

- prefix：自动给内部路由加共同路径前缀；例如 /items + /{item_id}。
- tags：在 /docs 中分类展示；这不是权限控制。
- dependencies：对这一组路径操作统一执行检查；与前面学过的 Depends 相连。
- responses：补充 OpenAPI 中可能响应的说明，不会自动替你抛出 404。

## 5. 官方后续内容，不必背诵全部语法

官方还介绍相对导入（如 `from .routers import users`）、`from ..dependencies import ...`、在 include_router 时附加 prefix/tags 等、重复注册 Router、Router 嵌套、`pyproject.toml` 里的入口配置，以及最终统一生成 /docs 文档。

真正重要的是：文件之间可以互相导入；每个 Router 维护本组接口；主应用负责组合它们。把 Router 放在独立模块并不会使依赖注入、参数验证或自动文档失效。

## 6. Agent 实战：拆分职责，而不是拆分服务器

```text
agent_api/
└── app/
    ├── main.py             # 应用入口，include_router
    ├── dependencies.py     # 当前用户、公共检查
    ├── routers/
    │   ├── users.py        # 用户与账号接口
    │   ├── agents.py       # Agent 列表与配置
    │   ├── chat.py         # /chat 聊天接口
    │   └── sessions.py     # 会话与历史记录
    └── agents/
        └── research.py     # 研究 Agent 的业务逻辑
```

一条聊天请求的概念流程：前端调用 /chat → main.py 注册的 chat.router 找到对应路由 → FastAPI 通过 Depends 检查身份 → chat.py 组织请求参数 → research.py 运行 Agent → chat.py 将结果返回。这里 routers 负责“对外怎么调用”，agents 负责“内部怎么完成任务”。

**记忆要点：** APIRouter（组织接口） ≠ FastAPI（主应用） ≠ Agent（业务推理）。
