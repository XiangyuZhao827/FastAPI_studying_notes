# 第二章：路径操作配置（Path Operation Configuration）

## 一、路径操作配置的作用

之前你一直使用：

```python
@app.get("/agents")
def get_agents():
    return [{"name": "Chat Agent"}]
```

这里有两个重要部分：

```python
@app.get("/agents")
```

和：

```python
def get_agents():
```

前者是 FastAPI 的**路径操作装饰器**。

后者是实际处理请求的 Python 函数。

其中：

- `/agents`：请求路径。
- `GET`：HTTP 请求方法。

**一个 HTTP 方法与一个路径组合起来，通常就对应一个路径操作。**

例如：

```text
GET  /agents
POST /agents
```

虽然路径相同，但请求方法不同，所以是两个不同的路径操作。

前面我们只在装饰器里填写路径：

```python
@app.post("/agents")
```

今天要学习的是：

**除了路径，装饰器里还可以配置状态码、标签、摘要、描述、响应说明以及弃用标记。** 

例如：

```python
@app.post(
    "/agents",
    status_code=201,
    tags=["Agents"],
    summary="创建一个 Agent",
    description="根据用户提交的数据创建 Agent",
    response_description="创建成功后的 Agent 信息"
)
def create_agent(...):
    ...
```

这些配置集中写在 `@app.post(...)` 里，而不是写成 Python 函数的普通输入参数。

## 二、status_code：设置正常响应的状态码

你之前学习过：

```python
response_model=AgentOut
```

用于规定响应数据的结构。

现在新增：

```python
status_code=201
```

用于规定接口正常完成时的 HTTP 状态码。

### 1. 创建 Agent 的示例

```python
from fastapi import FastAPI, status
from pydantic import BaseModel

app = FastAPI()


class AgentCreate(BaseModel):
    name: str


class AgentOut(BaseModel):
    agent_id: int
    name: str


@app.post(
    "/agents",
    response_model=AgentOut,
    status_code=status.HTTP_201_CREATED
)
def create_agent(agent: AgentCreate):

    return {
        "agent_id": 1,
        "name": agent.name
    }
```

你之前学过：

```python
response_model=AgentOut
```

现在再看：

```python
status_code=status.HTTP_201_CREATED
```

这里的 `status` 是 FastAPI 提供的状态码常量集合。

```python
status.HTTP_201_CREATED
```

其实等价于整数：

```python
201
```

所以你也可以写：

```python
@app.post("/agents", status_code=201)
```

官方教程同时支持这两种写法。

### 2. 测试结果

发送：

```http
POST /agents HTTP/1.1
Content-Type: application/json
```

Body：

```json
{
  "name": "Research Agent"
}
```

返回：

**HTTP 201 Created**

```json
{
  "agent_id": 1,
  "name": "Research Agent"
}
```

其中：

- HTTP 201 表示资源已创建。
- JSON 响应体描述新创建的 Agent。

需要特别说明：这里的代码只是教学模拟，它返回固定的 Agent ID，没有真正进行数据库持久化。**设置 `status_code=201` 本身并不会创建或保存任何数据。**

### 3. status_code 与 HTTPException 的区别

这是两章最重要的联系。

```python
@app.post("/agents", status_code=201)
```

通常是在规定：

> 这个接口成功完成时返回 201。

但如果业务代码中出现：

```python
raise HTTPException(
    status_code=404,
    detail="Agent not found"
)
```

则该请求返回 404，而不是 201。

因此：

| 写法 | 主要作用 |
|---|---|
| 装饰器中的 `status_code=201` | 声明正常成功响应的状态码 |
| `raise HTTPException(status_code=404)` | 在实际执行过程中产生错误响应 |

**装饰器的状态码配置不会覆盖业务代码主动抛出的 HTTP 错误。**

## 三、tags：在 /docs 中分组接口

当你第一次学习 FastAPI 时，接口可能只有两个：

```text
GET /items
POST /items
```

但是，一个 Agent 后端以后可能包含几十个接口：

```text
GET    /agents
POST   /agents
DELETE /agents/1
POST   /chat
GET    /sessions
POST   /files
GET    /health
```

如果全部混在一起，Swagger UI 就不方便阅读。

于是可以使用：

```python
tags=["Agents"]
```

例如：

```python
@app.get("/agents", tags=["Agents"])
def get_agents():
    return [{"name": "Chat Agent"}]


@app.post("/agents", tags=["Agents"])
def create_agent():
    return {"name": "New Agent"}


@app.get("/health", tags=["System"])
def health():
    return {"status": "ok"}
```

现在打开：

```text
http://127.0.0.1:8000/docs
```

Swagger UI 就可以按标签分组展示这些接口。

  

      
      **Agents**

    

        
GET

/agents

        
查询列表

      

        
POST

/agents

        
创建 Agent

    

  

      
      **System**

    

        
GET

/health

        
健康检查

    

  
Swagger UI 分组效果示意；tags 用于组织文档，不会自动创建权限控制。

注意：

**tags 只是 API 文档的组织方式，不是用户权限系统。**

例如：

```python
tags=["Admin"]
```

不会自动让这个接口变成“只有管理员才能调用”。

真正的身份认证、授权控制，仍然需要单独实现。

## 四、使用 Enum 统一管理 tags

你之前在路径参数章节学过：

```python
Enum
```

它同样可以用在接口标签上。

例如：

```python
from enum import Enum


class Tags(str, Enum):
    agents = "Agents"
    sessions = "Sessions"
    system = "System"
```

然后：

```python
@app.get(
    "/agents",
    tags=[Tags.agents]
)
def get_agents():
    return []
```

或者：

```python
@app.get(
    "/health",
    tags=[Tags.system]
)
def health():
    return {"status": "ok"}
```

这样的好处是：

当项目接口逐渐增多时，可以统一管理标签名称，避免有人写 `"Agent"`，有人写 `"Agents"`，导致 Swagger UI 出现不必要的多个分组。

如果只有两三个路由，直接使用字符串就足够了。

如果有很多模块，可以考虑 Enum。

## 五、summary 和 description：完善接口说明

这两个配置都用于 API 文档，但用途不一样。

### 1. summary：简短摘要

```python
@app.post(
    "/agents",
    summary="创建 Agent"
)
```

`summary` 通常是一句简洁的话，帮助开发者快速了解这个接口做什么。

例如：

```text
创建 Agent
查询 Agent
删除 Agent
上传文件
执行 Agent
```

### 2. description：详细描述

```python
@app.post(
    "/agents",
    summary="创建 Agent",
    description="接收 Agent 名称和描述，并返回创建后的公开信息。"
)
```

`description` 用来进一步说明：

- 这个接口具体执行什么。
- 需要什么数据。
- 可能有哪些重要限制。
- 调用方需要注意什么。

你可以在 `/docs` 展开对应接口，查看这些说明。

### 3. 与 Field(description=...) 的区别

你之前学过：

```python
class AgentCreate(BaseModel):
    name: str = Field(
        description="Agent 的名称"
    )
```

现在学：

```python
@app.post(
    "/agents",
    description="创建一个新的 Agent"
)
```

它们描述的对象不同：

| 写法 | 描述对象 |
|---|---|
| `Field(description="...")` | 模型中的某一个字段 |
| `Query(description="...")` | 某一个查询参数 |
| 路由中的 `description="..."` | 整个 API 路径操作 |

这也是 FastAPI 文档系统的一个重要特点：**可以在不同层级分别描述数据和接口。**

## 六、使用 docstring 编写较长的描述

如果你的接口说明比较长，全部写在：

```python
description="..."
```

里会不方便维护。

FastAPI 支持读取 Python 函数的**文档字符串（docstring）**，并将其作为路径操作的描述。

例如：

```python
@app.get(
    "/agents/{agent_id}/status",
    summary="查询 Agent 状态"
)
def get_agent_status(agent_id: int):
    """
    查询指定 Agent 的运行状态。

    该接口用于了解 Agent 的**模拟状态**。

    - `agent_id`：Agent 编号
    - `state`：当前状态

    **注意**：这个示例没有检查真实 LLM 服务。
    """

    return {
        "agent_id": agent_id,
        "state": "ready"
    }
```

你应该注意到：

```python
"""
...
"""
```

这就是 Python 文档字符串。

它位于函数体开头，用三引号包裹。

FastAPI 可以将其放入 OpenAPI 描述中，Swagger UI 支持展示其中的 Markdown 排版。

### summary 与 docstring 的分工

```python
summary="查询 Agent 状态"
```

用一句话概括接口。

函数中的 docstring：

```python
"""
查询指定 Agent 的运行状态。

...
"""
```

进一步解释细节。

这是我建议你在今后的 Agent 项目中逐渐采用的写法。

## 七、response_description：说明响应的含义

你已经学过：

```python
response_model=AgentOut
```

它规定响应 JSON 的结构。

但你还可以额外写：

```python
response_description="创建成功后的 Agent 信息"
```

例如：

```python
@app.post(
    "/agents",
    response_model=AgentOut,
    status_code=201,
    summary="创建 Agent",
    response_description="新创建 Agent 的公开信息"
)
def create_agent(...):
    ...
```

注意这里有两种完全不同的声明：

| 声明 | 作用 |
|---|---|
| `response_model=AgentOut` | 校验、序列化并规范 JSON 响应结构 |
| `response_description="..."` | 在 API 文档中说明响应的含义 |

**`response_description` 不会替代 `response_model`，也不会改变真实返回的 JSON。**

如果没有填写响应描述，FastAPI 通常会生成默认的成功响应说明。

## 八、deprecated=True：标记旧接口

你以后可能需要升级 Agent API。

例如：

旧接口：

```text
GET /legacy/agents
```

新接口：

```text
GET /agents
```

你希望通知其他开发者：

> 旧接口仍然可用，但不建议新代码继续使用。

可以写：

```python
@app.get(
    "/legacy/agents",
    deprecated=True
)
def legacy_agents():
    return [{"name": "Chat Agent"}]
```

打开 `/docs`，这个接口会被标记为已弃用。

但这里必须注意：

**`deprecated=True` 只是文档中的弃用声明，不会自动删除、关闭或禁止访问该接口。**

因此：

```text
GET /legacy/agents
```

仍然可能正常返回 200。

如果确实需要在未来关闭旧接口，应当另行制定迁移计划和移除安排。

## 九、完整 Agent 接口配置

把本章最重要的配置放在同一个路由里：

```python
from fastapi import FastAPI, status
from pydantic import BaseModel, Field

app = FastAPI()


class AgentCreate(BaseModel):
    name: str = Field(min_length=3)
    description: str | None = None


class AgentOut(BaseModel):
    agent_id: int
    name: str
    description: str | None = None


@app.post(
    "/agents",
    response_model=AgentOut,
    status_code=status.HTTP_201_CREATED,
    tags=["Agents"],
    summary="创建 Agent",
    description="接收 Agent 的基本信息，返回模拟创建结果。",
    response_description="新创建 Agent 的公开信息"
)
def create_agent(data: AgentCreate):

    return {
        "agent_id": 1,
        "name": data.name,
        "description": data.description
    }
```

这次最重要的不是业务函数有多复杂，而是理解装饰器中的每个配置。

| 配置 | 作用 | 是否改变 HTTP 行为 |
|---|---|---|
| `response_model=AgentOut` | 规定并校验输出数据 | 是 |
| `status_code=201` | 设置正常响应状态码 | 是 |
| `tags=["Agents"]` | 在 `/docs` 中分组 | 主要影响文档 |
| `summary="..."` | 接口简短摘要 | 主要影响文档 |
| `description="..."` | 接口详细说明 | 主要影响文档 |
| `response_description="..."` | 正常响应说明 | 主要影响文档 |
| `deprecated=True` | 标记弃用 | 文档标记，不自动关闭接口 |

这张表是第二章最值得记住的知识。

# 十一、两章知识总结

| 对比 | 处理错误 | 路径操作配置 |
|---|---|---|
| 主要目标 | 处理异常情况 | 配置接口行为和文档 |
| 核心语法 | `raise HTTPException(...)` | `@app.post(..., status_code=...)` |
| 常见功能 | 返回 400、404、503 等错误 | 设置成功状态码、分组、摘要和描述 |
| 进阶功能 | 自定义异常处理器 | Enum 标签、docstring、deprecated |
| Agent 实战价值 | 明确表示 Agent 不存在或无法执行 | 规范 Agent 接口及 Swagger 文档 |

尤其需要记住：

**`HTTPException(status_code=404)` 用来在实际执行中报告错误；装饰器里的 `status_code=201` 则规定正常创建成功的响应状态。**

它们并不冲突。

还有一个小更正：第一章第 8 道选择题 B 选项中的“添加请求头”应为“添加**响应头**”。因为 `HTTPException(headers=...)` 设置的是服务器返回给客户端的 Header。
