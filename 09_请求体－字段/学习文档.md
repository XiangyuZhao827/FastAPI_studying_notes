# 📘 FastAPI 第 8 章：请求体 - 字段（Body - Fields）

这一章其实很简单！😊 因为我们之前已经多次使用过它的核心工具：**`Field()`**。

官方教程：[FastAPI《请求体 - 字段》](https://fastapi.tiangolo.com/zh/tutorial/body-fields/)

## 一、这一章主要解决什么问题？

之前我们定义请求体模型：

```python
class Item(BaseModel):
    name: str
    price: float
```

这只能规定：

- `name` 是字符串。
- `price` 是浮点数。
- 两个字段都是必填的。

但如果我们还希望：

- `name` 最长 50 个字符。
- `price` 必须大于 0。
- 为字段添加文字说明，自动显示在 `/docs` 中。

就需要使用 **Pydantic 的 `Field()`**。

## 二、官方代码：如何使用 Field？

```python
from typing import Annotated

from fastapi import Body, FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class Item(BaseModel):
    name: str

    description: str | None = Field(
        default=None,
        title="The description of the item",
        max_length=300
    )

    price: float = Field(
        gt=0,
        description="The price must be greater than zero"
    )

    tax: float | None = None


@app.put("/items/{item_id}")
def update_item(
    item_id: int,
    item: Annotated[Item, Body(embed=True)]
):
    return {"item_id": item_id, "item": item}
```

重点看 `Field()` 中的参数：

| 参数 | 含义 |
|---|---|
| `default=None` | 字段默认值为 None，可以不传 |
| `title="..."` | 字段标题，显示在 API 文档中 |
| `description="..."` | 字段说明 |
| `max_length=300` | 字符串最多 300 个字符 |
| `gt=0` | 数字必须大于 0 |

**注意：`Field` 从 `pydantic` 导入，而不是 `fastapi`。** 

由于官方示例使用了：

```python
Body(embed=True)
```

所以客户端要发送：

```json
{
  "item": {
    "name": "Python Book",
    "description": "一本 Python 教程",
    "price": 99.9
  }
}
```

其中 `item` 这一层是由 `embed=True` 决定的，不是 `Field()` 决定的。

## 三、Field 与之前学过的 Query、Path、Body 有什么区别？

这张表最值得记住：

| 工具 | 主要负责 |
|---|---|
| `Path()` | 校验 URL 路径参数 |
| `Query()` | 校验 URL 查询参数 |
| `Body()` | 声明请求体参数 |
| **`Field()`** | **校验 Pydantic 模型内部的字段** |

例如：

```python
class ChatRequest(BaseModel):
    message: str = Field(min_length=1)
```

这里的 `Field()` 校验 `ChatRequest` 模型中的 `message` 字段。

## 四、在 Agent 开发中有什么作用？🤖

假设用户在聊天框输入问题，前端自动封装成：

```json
{
  "message": "帮我解释什么是 Agent",
  "max_steps": 3
}
```

我们希望：

- 用户的问题不能为空。
- 问题最多 2000 个字符。
- Agent 最多执行 5 步。
- 用户不提供 `max_steps` 时，默认使用 3。

可以直接这样写：

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class ChatRequest(BaseModel):
    message: str = Field(
        min_length=1,
        max_length=2000,
        description="用户发送给 Agent 的问题"
    )

    max_steps: int = Field(
        default=3,
        ge=1,
        le=5,
        description="Agent 最大执行步骤数"
    )


@app.post("/chat")
def chat(request: ChatRequest):
    return {
        "answer": f"Agent 收到：{request.message}",
        "max_steps": request.max_steps
    }
```

正常请求：

```json
{
  "message": "你好 Agent",
  "max_steps": 3
}
```

返回：

```json
{
  "answer": "Agent 收到：你好 Agent",
  "max_steps": 3
}
```

但如果输入：

```json
{
  "message": "",
  "max_steps": 100
}
```

就会返回 HTTP **422**，因为：

- `message=""` 不符合 `min_length=1`。
- `max_steps=100` 超过了 `le=5` 的上限。

**这些错误会在 Agent 执行前被拦截。**

当然，`Field(le=5)` 只负责校验数值。真正限制 LangGraph 或 Agent 的执行步数，仍然需要业务逻辑使用 `request.max_steps`。

## 五、本章总结

这章最重要的代码就是：

```python
class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
    max_steps: int = Field(default=3, ge=1, le=5)
```

只要记住三个结论就够了：

1. **`BaseModel` 定义整个数据结构。**
2. **`Field()` 为模型内部的每个字段添加默认值、校验规则和文档说明。**
3. **FastAPI 自动使用这些规则验证请求体，非法数据通常返回 422。**

对于未来的 Agent 开发，你可以把 `Field()` 理解为：**在用户输入进入 Agent 之前，负责检查每个字段是否符合接口规则的工具。**
