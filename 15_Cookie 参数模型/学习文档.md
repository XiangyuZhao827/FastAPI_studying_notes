# 第三章：Cookie 参数模型

## 八、为什么要有 Cookie 参数模型？

前面学会了读取单个 Cookie：

```python
session_id: Annotated[str | None, Cookie()] = None
```

但真实应用可能需要读取多个 Cookie：

```http
Cookie: session_id=demo001; theme=dark
```

如果直接为每个 Cookie 创建一个函数参数：

```python
@app.get("/profile")
def profile(
    session_id: Annotated[str, Cookie()],
    theme: Annotated[str, Cookie()] = "light"
):
    ...
```

当然可以。

不过，当 Cookie 数量增加、多个接口又需要重复使用同一组 Cookie 时，把它们组织成一个 Pydantic 模型就更清晰了。

这其实和你之前学过的**查询参数模型**完全是同一种设计思路。

## 九、官方代码：Cookie 参数模型

官方示例：

```python
from typing import Annotated

from fastapi import Cookie, FastAPI
from pydantic import BaseModel

app = FastAPI()


class Cookies(BaseModel):
    session_id: str
    fatebook_tracker: str | None = None
    googall_tracker: str | None = None


@app.get("/items/")
async def read_items(
    cookies: Annotated[Cookies, Cookie()]
):
    return cookies
```

这是 FastAPI 官方文档中的示例结构。Cookie 参数模型从 FastAPI **0.115.0** 开始得到支持。

### 1. 先看模型

```python
class Cookies(BaseModel):
    session_id: str
    fatebook_tracker: str | None = None
    googall_tracker: str | None = None
```

包含三个字段：

| 字段 | 类型 | 是否必填 |
|---|---|---|
| `session_id` | str | 是 |
| `fatebook_tracker` | str 或 None | 否 |
| `googall_tracker` | str 或 None | 否 |

后两个名称只是官方为了演示多个 Cookie 而设置的样例字段。

### 2. 最核心的一行

```python
cookies: Annotated[Cookies, Cookie()]
```

逐层理解：

- `cookies`：Python 函数参数名。
- `Cookies`：Pydantic 模型。
- `Cookie()`：告诉 FastAPI，模型里的各个字段都应该从请求的 Cookie 中读取。

因此，客户端可以发送：

```http
GET /items/ HTTP/1.1
Cookie: session_id=abc123; fatebook_tracker=f001
```

FastAPI 会创建一个模型对象，效果相当于：

```python
cookies = Cookies(
    session_id="abc123",
    fatebook_tracker="f001",
    googall_tracker=None
)
```

你可以访问：

```python
cookies.session_id
cookies.fatebook_tracker
cookies.googall_tracker
```

这里要特别注意：

**Cookie 参数模型不意味着客户端发送 JSON Body。**

它仍然是在读取 HTTP Cookie，只不过 FastAPI 将多个值组合成了一个 Pydantic 对象。

### 3. 与第六章查询参数模型比较

这两行几乎完全对应：

```python
filters: Annotated[FilterParams, Query()]
```

```python
cookies: Annotated[Cookies, Cookie()]
```

区别只有**来源**：

- `Query()`：从 URL 查询字符串提取字段。
- `Cookie()`：从客户端 Cookie 提取字段。

这就是你以前学的知识如何在新章节里复用。

## 十、Cookie 参数模型中的 extra="forbid"

你之前学过：

```python
model_config = {"extra": "forbid"}
```

这同样可以用于 Cookie 模型。

例如：

```python
class Cookies(BaseModel):
    model_config = {"extra": "forbid"}

    session_id: str
    theme: str = "light"
```

它表示：

> 只允许模型声明的 Cookie 字段，其他额外 Cookie 会触发验证错误。

例如请求：

```http
Cookie: session_id=abc123; theme=dark; unknown=yes
```

这里出现了没有声明的：

```text
unknown=yes
```

那么可能返回 HTTP 422，提示额外字段不被允许。

但这里有一个**实际项目中尤其重要的注意事项**：

浏览器可能自动附带同一作用域下的其他 Cookie。如果你使用 `extra="forbid"`，这些原本无关的 Cookie 也可能导致接口返回 422。

因此：

**Cookie 模型能够使用 `extra="forbid"`，不代表每一个真实网站都应该启用它。**

对于普通浏览器 Agent 应用，如果同一网站可能存在多个组件设置的 Cookie，往往需要更谨慎地设计。

## 十一、为什么在 /docs 中测试 Cookie 可能不成功？

这是这四章里最需要提前提醒你的实际问题。

你之前一直习惯：

```text
http://127.0.0.1:8000/docs
```

然后点击 Try it out 和 Execute。

对于 Query、Path、Body，这通常很好用。

**但 Cookie 不完全一样。**

浏览器不允许网页 JavaScript 随意设置请求中的 `Cookie` 请求头。

所以即使 Swagger UI 显示了 Cookie 参数输入框，你在那里填写值，也未必能够像普通 Query 参数一样把 Cookie 手动发送出去。

FastAPI 官方文档专门提醒了这个限制。

例如，你在 `/docs` 中填写：

```text
session_id = abc123
```

却仍然得到：

```json
{
  "detail": [
    {
      "loc": ["cookie", "session_id"],
      "msg": "Field required"
    }
  ]
}
```

这不一定代表你写错了 FastAPI 代码，也可能是因为浏览器没有实际发送该 Cookie。

解决方法：

- 使用 Python `httpx` 测试客户端显式发送 Cookie。
- 使用其他支持 Cookie 的 HTTP 测试工具。
- 在真正的网页应用里，让浏览器通过正确设置的 Cookie 自动携带它。
