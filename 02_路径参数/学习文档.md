# 📘 FastAPI 路径参数：零基础完整讲解

你正在学习的这一章，叫作 **路径参数（Path Parameters）**。

我已经对照了 [FastAPI 官方《路径参数》教程](https://fastapi.tiangolo.com/zh/tutorial/path-params/)。这次我们按照官方章节的顺序，把每个知识点、代码示例以及背后的 Python 语法讲清楚。

我会结合你之前编写的 `first.py` 和 Agent 项目举例，因为你已经学会了创建 FastAPI 应用、编写 `/health` 和 `/chat` 接口。

## 一、先理解：什么是路径参数？

假设你开发了一个用户查询系统。

现在需要查询不同用户的信息：

```text
http://127.0.0.1:8000/users/1
http://127.0.0.1:8000/users/2
http://127.0.0.1:8000/users/3
```

观察这三个 URL，你会发现：

- `/users/` 是固定不变的。
- 后面的 `1`、`2`、`3` 是变化的。
- 变化的数字代表不同用户的 ID。

如果使用传统的方式，你可能要为不同用户写不同的接口。但 FastAPI 允许你使用一个变量来接收这些不同的值。

```python
@app.get("/users/{user_id}")
def get_user(user_id):
    return {"user_id": user_id}
```

这里的 `{user_id}` 就是**路径参数**。

  
图解：URL 是如何变成 Python 函数参数的？

    

/users/

        
123

    

      
      
FastAPI 提取变化的部分

    

`user_id = "123"`

传入函数参数，默认是字符串

    

      
调用 Python 函数

    

`get_user(user_id="123")`

  

如果把函数参数声明为 `user_id: int`，FastAPI 还会尝试把 `"123"` 转换成整数 `123`。

**一句话记忆：路径参数就是把 URL 中变化的部分提取出来，交给 Python 函数使用。**

### 1. 官方第一个代码示例

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
async def read_item(item_id):
    return {"item_id": item_id}
```

我们逐行解释。

**第一行：**

```python
from fastapi import FastAPI
```

从 `fastapi` 包中导入 `FastAPI` 类。

**第二行：**

```python
app = FastAPI()
```

创建一个 FastAPI 应用对象。

**第三行：**

```python
@app.get("/items/{item_id}")
```

这是一个 Python 装饰器，你可以先理解成：

告诉 FastAPI，当用户使用 GET 请求访问 `/items/某个值` 时，运行下面的函数。

**第四行：**

```python
async def read_item(item_id):
```

定义一个名叫 `read_item` 的异步函数。`item_id` 是函数接收的参数。

这里的 `async` 是 Python 的异步语法，你暂时不必深入研究。这一章使用普通的 `def` 也可以完成同样的路径参数练习。

**第五行：**

```python
return {"item_id": item_id}
```

返回一个 Python 字典，FastAPI 会把它转换成 JSON 响应。

例如：

| 浏览器访问 | 返回的 JSON |
|---|---|
| `/items/123` | `{"item_id":"123"}` |
| `/items/hello` | `{"item_id":"hello"}` |
| `/items/agent` | `{"item_id":"agent"}` |

注意，此时没有声明 `item_id` 的类型，因此收到的路径值是字符串。

### 2. 为什么一定要用 `{}`？

对比下面两个路由：

```python
@app.get("/items/item_id")
```

```python
@app.get("/items/{item_id}")
```

它们有本质区别。

| 写法 | 含义 |
|---|---|
| `/items/item_id` | 固定路径，必须访问字面上的 `item_id` |
| `/items/{item_id}` | 动态路径，`item_id` 是变量 |

例如，访问 `/items/100`：

第一个路由不能匹配，第二个路由可以匹配，并把 `"100"` 传入函数。

这里还有一个小白容易忽略的规则：

```python
@app.get("/items/{item_id}")
def read_item(item_id):
    ...
```

花括号里的名称 `item_id`，要和函数里对应的参数名一致。

你当然可以改名，例如全部使用 `product_id`，但不能只改其中一个地方。

## 二、声明路径参数的类型

现在来看官方文档中的第二个例子。

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/items/{item_id}")
async def read_item(item_id: int):
    return {"item_id": item_id}
```

与第一个例子相比，只有一个重要变化：

```python
item_id: int
```

你可能会疑惑：

**冒号 `:` 后面的 `int` 是什么意思？**

这是 Python 的类型注解（Type Hint）。

例如：

```python
age: int = 18
name: str = "Tom"
price: float = 19.9
```

分别表示：

- `int`：整数，例如 `1`、`10`、`100`
- `str`：字符串，例如 `"hello"`
- `float`：浮点数，例如 `3.14`

在普通 Python 中，类型注解主要用于代码提示和静态检查，并不会自动阻止你传入不符合类型的数据。

但是 **FastAPI 会读取类型注解，并利用它进行数据解析和校验**。这是 FastAPI 非常重要的设计。

### 1. FastAPI 的自动数据转换

当你访问：

```text
http://127.0.0.1:8000/items/3
```

URL 里面的 `3` 原本是字符串。

但是你声明了：

```python
item_id: int
```

于是 FastAPI 会尝试把它转换成整数。

  

浏览器传入

`"3"`

str · 字符串

  

    
FastAPI 根据 `item_id: int` 解析

  

`3`

int · 整数

  

  

    ```json
    {"item_id": 3}
    ```

重点区别：

```python
"3"  # 字符串
3    # 整数
```

虽然看起来相似，但是 Python 认为它们是不同类型。

你可以给官方的代码增加一行，亲自验证：

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    print(type(item_id))
    return {"item_id": item_id}
```

访问 `/items/3` 后，你的终端会打印：

```text
<class 'int'>
```

这说明传入函数时，它已经变成了整数。

## 三、数据校验：为什么会出现 422 错误？

还是这段代码：

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

如果你访问：

```text
http://127.0.0.1:8000/items/hello
```

会发生什么？

因为 `hello` 无法转换成整数，FastAPI 会自动拒绝这个请求。

它返回的是 **HTTP 422 Unprocessable Content**（部分界面也会显示旧称 Unprocessable Entity），而不是正常的 200。

错误响应大致如下：

```json
{
  "detail": [
    {
      "type": "int_parsing",
      "loc": ["path", "item_id"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "input": "hello"
    }
  ]
}
```

别被这一大段英文吓到，我们逐个拆开。

| 字段 | 意思 |
|---|---|
| `detail` | 错误的详细信息 |
| `type: "int_parsing"` | 整数解析失败 |
| `loc: ["path", "item_id"]` | 错误发生在路径参数 `item_id` |
| `msg` | 人类可读的错误说明 |
| `input: "hello"` | 用户实际输入的值 |

也就是说，FastAPI 在告诉你：

> 我知道你想调用 `/items/{item_id}`，但是你给我的 `item_id` 不是合法整数，所以我没有执行你的函数。

试试预测下面这些请求：

| 请求 | 结果 | 原因 |
|---|---|---|
| `/items/10` | 200 | 合法整数 |
| `/items/-5` | 200 | 负数也是整数 |
| `/items/3.14` | 422 | 不能解析为整数 |
| `/items/abc` | 422 | 字符串不能解析为整数 |
| `/items/` | 404 | 缺少匹配的路径段 |

注意：`/items/` 返回 404 的前提是没有另外定义能匹配它的接口。

### 最容易混淆的三个 HTTP 状态码

| 状态码 | 小白理解 | 示例 |
|---|---|---|
| 200 | 请求成功 | `/items/123` |
| 404 | 没找到符合要求的路由 | `/unknown` |
| 422 | 路由匹配了，但数据校验失败 | `/items/abc` |

**这个区别非常重要。** 你之前遇到的 404 是 URL 没有匹配到路由，而本章的 422 通常是 URL 匹配成功了，但参数不符合要求。

## 四、自动生成 API 文档：`/docs` 和 `/redoc`

官方文档接下来介绍了 FastAPI 非常实用的一个功能：自动生成接口文档。

如果你写：

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

FastAPI 会自动知道：

1. 这个接口使用 `GET` 请求。
2. 路径是 `/items/{item_id}`。
3. 它要求提供 `item_id`。
4. `item_id` 必须是整数。

因此，即使你没有手动编写接口文档，FastAPI 也能自动生成。

### 两种文档界面

  

    

      **Swagger UI — `/docs`**
      
支持点击 Try it out，直接发送请求进行测试。初学者最常用。

  

  

    

      **ReDoc — `/redoc`**
      
更偏向阅读和查阅 API 说明，适合展示接口定义。

  

在你自己的电脑上启动服务后，访问：

```text
http://127.0.0.1:8000/docs
http://127.0.0.1:8000/redoc
```

它们的区别主要是展示方式，而不是生成两套不同的接口。

### OpenAPI 又是什么？

官方文档这里提到了一个新名词：OpenAPI。

你可以把它理解成：

**描述 API 长什么样的一套通用标准。**

比如它可以描述：

- 接口的地址是什么。
- 使用 GET 还是 POST。
- 参数叫什么。
- 参数是什么类型。
- 返回的数据结构是什么。

FastAPI 会根据你的代码自动生成 OpenAPI 描述，Swagger UI 和 ReDoc 再根据这些描述生成文档页面。

你也可以访问：

```text
http://127.0.0.1:8000/openapi.json
```

查看原始的 OpenAPI JSON 描述。

对于 Agent 开发来说，这很实用，因为将来你的 Agent 后端有 `/chat`、`/history`、`/tools` 等接口时，其他开发者可以直接根据文档了解调用方式。

## 五、Pydantic 在路径参数中起什么作用？

你之前已经使用过：

```python
from pydantic import BaseModel, Field
```

比如：

```python
class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
```

这是让 Pydantic 验证用户提交的 JSON 请求体。

在路径参数这一章，FastAPI 同样利用 Pydantic 来完成数据的解析和校验。

比较一下：

  
路径参数验证

  ```python
  @app.get("/items/{item_id}")
  def read_item(item_id: int):
      return {"item_id": item_id}
  ```
  
这里的 `int` 告诉 FastAPI：`item_id` 应该是整数。

  
请求体验证

  ```python
  class ChatRequest(BaseModel):
      message: str
  ```
  
这里的 `str` 告诉 Pydantic：`message` 应该是字符串。

它们有一个共同点：你声明数据规则，框架负责按照规则校验。

你目前只需要记住：

**Pydantic 负责数据验证，FastAPI 利用它帮助我们减少大量重复的验证代码。**

## 六、为什么官方说“顺序很重要”？

这是整章中最容易踩坑的知识点之一。

假设你的网站有两个需求：

1. `/users/me`：查看当前用户。
2. `/users/{user_id}`：通过 ID 查看某个用户。

我们先看正确写法。

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/users/me")
def read_user_me():
    return {"user_id": "the current user"}


@app.get("/users/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}
```

注意两个路由的顺序：

```text
第一个：/users/me
第二个：/users/{user_id}
```

为什么要这样写？

因为 `/users/{user_id}` 允许 `{user_id}` 接收一个动态值。

假如你访问：

```text
/users/me
```

它既可能与固定路径 `/users/me` 匹配，也可能被动态路径 `/users/{user_id}` 认为：

```python
user_id = "me"
```

FastAPI 的路由按照注册顺序匹配。

因此，需要把**更具体的固定路径放在更通用的动态路径之前**。

  

      

          
          **正确顺序**

        

1. `/users/me`

2. `/users/{user_id}`

        
访问 `/users/me` 时，匹配第一个路由。

    

      

          
          **错误顺序**

        

1. `/users/{user_id}`

2. `/users/me`

        
`me` 被前一个路由当作 `user_id`。

    

### 一个容易让初学者误解的细节

假如你的动态路由写成：

```python
@app.get("/users/{user_id}")
def read_user(user_id: int):
    return {"user_id": user_id}


@app.get("/users/me")
def read_user_me():
    return {"user_id": "current"}
```

虽然 `user_id` 被声明成了整数，但是访问 `/users/me` 时，仍然会优先匹配第一个动态路由，然后因为 `me` 不能解析成整数而返回 422。

**类型注解负责数据校验，并不会自动帮你重新选择其他路由。**

### 为什么不能重复定义完全相同的路由？

官方还有一个例子：

```python
@app.get("/users")
def read_users():
    return ["Rick", "Morty"]


@app.get("/users")
def read_users2():
    return ["Bean", "Elfo"]
```

两个接口都是：

```text
GET /users
```

当用户发送 GET 请求到 `/users` 时，首先注册的那个接口会处理请求。

因此，你不能指望第二个函数覆盖第一个函数。

需要区分不同功能时，可以使用不同的路径或 HTTP 方法。

## 七、预设值：Enum 枚举类（重点 ⭐）

你给出的官方链接定位在 `Create an Enum class`。这一部分确实有一定难度，因为它同时使用了 Python 的类、继承、枚举和 FastAPI 类型注解。

我们从最基础的思路开始。

### 1. 什么情况下需要 Enum？

假设你在开发一个提供多种 AI 模型的服务。

用户只能选择以下三种模型：

```text
alexnet
resnet
lenet
```

不允许用户随便传入：

```text
hello
abc
unknown
```

如果不用 Enum，你可能这样写：

```python
@app.get("/models/{model_name}")
def get_model(model_name: str):
    if model_name not in ["alexnet", "resnet", "lenet"]:
        return {"error": "不支持的模型"}

    return {"model_name": model_name}
```

这段代码能够工作，但每次都要自己写判断。

还有一个问题：直接返回 `{"error": ...}`，默认仍然可能是 HTTP 200，而不是标准的参数校验错误状态码。

FastAPI 提供了更规范的办法：使用 Python 的 `Enum`。

### 2. Enum 到底是什么？

Enum 是 Enumeration 的缩写，中文叫作**枚举**。

你可以把它理解成：

> 提前定义一组合法选项，然后让程序只能从这些选项里选择。

先看最简单的 Python 例子：

```python
from enum import Enum

class Color(Enum):
    red = "red"
    blue = "blue"
    green = "green"
```

这里定义了三种颜色。

```python
print(Color.red)
```

输出：

```text
Color.red
```

再执行：

```python
print(Color.red.value)
```

输出：

```text
red
```

注意它们的区别：

- `Color.red` 是一个枚举成员。
- `Color.red.value` 是这个枚举成员保存的实际值。

理解了这个区别，再看官方代码就容易得多。

### 3. 官方的 Enum 代码

```python
from enum import Enum
from fastapi import FastAPI


class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"


app = FastAPI()
```

我们逐个拆解：

**第一行：**

```python
from enum import Enum
```

从 Python 标准库里导入 `Enum`，不需要额外安装。

**第二部分：**

```python
class ModelName(str, Enum):
```

这行最容易令人困惑。

- `class`：定义一个类。
- `ModelName`：类的名字。
- `str`：表示枚举值使用字符串。
- `Enum`：让这个类拥有枚举的能力。

这属于 Python 的多重继承语法。

官方让 `ModelName` 同时继承 `str` 和 `Enum`，主要是为了让它拥有字符串枚举值，并方便 FastAPI 在 API 文档中正确描述这些值。

**接下来：**

```python
alexnet = "alexnet"
resnet = "resnet"
lenet = "lenet"
```

每行定义一个枚举成员。

注意左边和右边的区别：

```python
class AgentType(str, Enum):
    chat = "chat-agent"
```

在这个例子里：

```python
AgentType.chat.name    # "chat"
AgentType.chat.value   # "chat-agent"
```

左边的 `chat` 是枚举成员的名字，而右边的 `"chat-agent"` 是它实际代表的字符串。

这两个值可以相同，也可以不同。

### 4. 把 Enum 用到 FastAPI

现在添加官方的路由：

```python
@app.get("/models/{model_name}")
async def get_model(model_name: ModelName):
    if model_name is ModelName.alexnet:
        return {
            "model_name": model_name,
            "message": "Deep Learning FTW!"
        }

    if model_name.value == "lenet":
        return {
            "model_name": model_name,
            "message": "LeCNN all the images"
        }

    return {
        "model_name": model_name,
        "message": "Have some residuals"
    }
```

最重要的是这一行：

```python
async def get_model(model_name: ModelName):
```

以前你写：

```python
item_id: int
```

意思是要求整数。

现在你写：

```python
model_name: ModelName
```

意思是要求传入符合 `ModelName` 枚举定义的值。

FastAPI 只接受：

```text
alexnet
resnet
lenet
```

其他值不能通过校验。

### 5. 分析这段函数是怎么运行的

假设访问：

```text
/models/alexnet
```

FastAPI 首先匹配路径：

```python
@app.get("/models/{model_name}")
```

提取 `"alexnet"`，再根据 `ModelName` 转成枚举成员：

```python
ModelName.alexnet
```

于是进入函数，运行第一段：

```python
if model_name is ModelName.alexnet:
```

条件成立，就返回：

```json
{
  "model_name": "alexnet",
  "message": "Deep Learning FTW!"
}
```

接下来假设访问：

```text
/models/lenet
```

第一段判断不成立：

```python
if model_name is ModelName.alexnet:
```

继续到第二段：

```python
if model_name.value == "lenet":
```

这时：

```python
model_name.value
```

等于：

```python
"lenet"
```

所以条件成立，返回：

```json
{
  "model_name": "lenet",
  "message": "LeCNN all the images"
}
```

最后，如果访问：

```text
/models/resnet
```

前面两个判断都不成立，就执行最后一个 `return`：

```json
{
  "model_name": "resnet",
  "message": "Have some residuals"
}
```

### 6. 为什么一会儿用 `is`，一会儿用 `==`？

这是官方代码非常值得研究的地方。

第一种：

```python
model_name is ModelName.alexnet
```

使用 `is` 判断两个对象是不是同一个对象。

枚举成员是固定的单例，因此这样比较是合理的。

也可以写成：

```python
model_name == ModelName.alexnet
```

第二种：

```python
model_name.value == "lenet"
```

比较的是枚举成员的字符串值。

注意区分：

| 代码 | 比较的内容 |
|---|---|
| `model_name is ModelName.alexnet` | 是否为指定的枚举成员对象 |
| `model_name == ModelName.alexnet` | 是否等于指定的枚举成员 |
| `model_name.value == "lenet"` | 枚举成员的值是否等于字符串 |

对于你的学习阶段，建议优先掌握两种写法：

```python
model_name == ModelName.alexnet
```

```python
model_name.value == "alexnet"
```

前者比较枚举成员，后者比较字符串值。

### 7. 为什么可以直接返回 Enum？

官方还有一句话：

> 即使嵌套在 JSON 中，也可以返回枚举成员。

它的意思是，虽然 Python 内部处理的是：

```python
ModelName.alexnet
```

但当你这样返回：

```python
return {
    "model_name": ModelName.alexnet
}
```

FastAPI 会在生成 JSON 响应时把它转换为对应的字符串值：

```json
{
  "model_name": "alexnet"
}
```

不用自己手动把每个枚举成员转换成字符串。

### 8. Enum 有什么实际好处？

看一下请求和结果：

| 请求 | 是否成功 | 结果 |
|---|---|---|
| `/models/alexnet` | ✅ 200 | 返回 AlexNet 结果 |
| `/models/resnet` | ✅ 200 | 返回 ResNet 结果 |
| `/models/lenet` | ✅ 200 | 返回 LeNet 结果 |
| `/models/hello` | ❌ 422 | 不在允许的选项中 |
| `/models/AlexNet` | ❌ 422 | 大小写不符合定义 |

此外，打开 `/docs` 时，Swagger UI 通常还会提供合法枚举值的下拉选项。

因此 **Enum = 限制合法输入 + 自动校验 + 自动生成可选值文档**。

这对 Agent 开发很有帮助，例如：

```python
class AgentType(str, Enum):
    chat = "chat"
    search = "search"
    coding = "coding"
```

以后你就可以提供：

```text
/agents/chat
/agents/search
/agents/coding
```

而不需要让用户自由输入任意 Agent 类型。

## 八、包含路径的路径参数：`{file_path:path}`

这一部分是本章最后一个比较特殊的知识点。

首先看普通路径参数：

```python
@app.get("/files/{file_path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

假设访问：

```text
/files/test.txt
```

可以正常匹配，返回：

```json
{
  "file_path": "test.txt"
}
```

但是如果你访问：

```text
/files/images/cat.png
```

普通的 `{file_path}` 不会把后面的所有路径段一起匹配，因为其中包含 `/`。

### 1. 使用 `:path` 转换器

官方给出的解决方式是：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/files/{file_path:path}")
async def read_file(file_path: str):
    return {"file_path": file_path}
```

仔细看：

```python
{file_path:path}
```

它由两部分组成：

- `file_path`：参数名字。
- `:path`：一个特殊的路径转换器，用于匹配可能含有 `/` 的路径。

它与普通路径参数的区别：

| 写法 | 能否捕获含有 `/` 的内容 |
|---|---|
| `{file_path}` | ❌ 默认不能 |
| `{file_path:path}` | ✅ 可以 |

例如访问：

```text
/files/images/cat.png
```

返回：

```json
{
  "file_path": "images/cat.png"
}
```

这里有两个不同的冒号语法，不要混淆。

```python
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    ...
```

第一处：

```python
{file_path:path}
```

是路由里的路径匹配语法。

第二处：

```python
file_path: str
```

是 Python 的类型注解。

两者虽然都出现了冒号，但含义完全不同。

### 2. 为什么官方还讲了两个连续的 `/`？

官方举了一个绝对路径：

```text
/home/johndoe/myfile.txt
```

注意这个文件路径本身以 `/` 开头。

如果想把它放到 `/files/` 后面，完整的 URL 路径就变成：

```text
/files//home/johndoe/myfile.txt
```

其中两个连续的 `/` 分别来自：

```text
/files/ + /home/johndoe/myfile.txt
```

第一个是路由固定前缀的末尾斜杠，第二个是文件路径自身的起始斜杠。

这样，捕获到的 `file_path` 就是：

```text
/home/johndoe/myfile.txt
```

普通文件路径不以斜杠开头时，就不需要两个连续斜杠。

### 3. OpenAPI 为什么不完全支持这种写法？

官方指出，OpenAPI 没有提供标准方式来声明“一个路径参数内部还可能包含多个 `/`”。

FastAPI 仍然可以通过底层 Starlette 的路径转换器支持它，但自动生成的文档不一定能完整说明这个参数的特殊匹配行为。

对初学者而言，知道它能用、懂得它与普通路径参数的区别就够了。

另外要特别提醒：如果以后你开发真正的文件读取接口，**不要直接把用户传入的 `file_path` 拼接成服务器文件路径再读取**。需要先进行安全的路径限制和校验，避免访问预期目录之外的文件。

## 十、路径参数与查询参数到底有什么区别？

虽然这是下一章的重点，但是建议你现在先理解最基础的区别。

假设有两个 URL：

```text
/items/100
```

```text
/items?item_id=100
```

它们都可能表达“查询编号为 100 的商品”，但参数位置不同。

  

路径参数（Path Parameter）

      
/items/

        
100

    

参数是 URL 路径结构的一部分。

    ```python
    @app.get("/items/{item_id}")
    def get_item(item_id: int):
        return {"item_id": item_id}
    ```

  

    
查询参数（Query Parameter）

      
/items

        
?item_id=100

    

参数位于 `?` 后面，通常用于筛选、排序、分页等。

    ```python
    @app.get("/items")
    def get_item(item_id: int):
        return {"item_id": item_id}
    ```

记住一个简单判断：

**如果参数名出现在路由路径的 `{}` 里面，它就是路径参数；如果没有出现在路径中，但作为简单类型的函数参数声明，FastAPI 通常把它当作查询参数。**

## 四、FastAPI 自动生成 API 文档

这是官方教程中的「文档」与「基于标准的好处，备选文档」两节。

你可能会好奇：

> 我只是写了几个 Python 函数，为什么 FastAPI 就能自动生成一个漂亮的接口文档？

因为 FastAPI 能通过你的路由定义和类型注解，自动知道接口需要什么参数。

例如：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

FastAPI 可以从这几行代码中提取出以下信息：

| 信息 | FastAPI 识别到的内容 |
|---|---|
| 请求方法 | GET |
| URL 路径 | `/items/{item_id}` |
| 参数名称 | `item_id` |
| 参数位置 | URL 路径 |
| 参数类型 | integer（整数） |
| 是否必填 | 是 |

因此，它能够自动生成文档，你不需要手动编写这些说明。

### 1. Swagger UI 和 ReDoc

  

    

      **Swagger UI：`/docs`**
      
可交互的 API 文档，可以直接执行测试请求

    
建议常用

  

    

      **ReDoc：`/redoc`**
      
侧重阅读和查询接口说明的文档页面

  

  

    

      **OpenAPI：`/openapi.json`**
      
供工具读取的机器可解析 API 规范

  

实际上，这三者之间是这样的关系：

  

    **你编写的 FastAPI 代码**
    
路由、参数和类型声明

  

  

    **OpenAPI 规范**
    
统一描述接口的结构

  

  

    

        **Swagger UI**
        
交互式调试

    

      

        **ReDoc**
        
文档展示

    

如果你以后开发 Agent API，别人不一定知道 `/chat` 需要传什么数据，但是他们打开 `/docs` 就可以看到接口要求，甚至直接发送请求测试。

这就是自动文档的价值。

## 五、Pydantic 是什么？它和路径参数有什么关系？

你之前写 Agent API 时已经使用过：

```python
from pydantic import BaseModel, Field

class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
```

但在这一章，我们并没有创建 `BaseModel`：

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

为什么 FastAPI 仍然能进行数据校验？

**因为 FastAPI 在底层使用 Pydantic 来解析和校验数据。**

你可以把它们理解为：

- **FastAPI**：负责接收请求，识别参数来自哪里，并调用函数。
- **Pydantic**：负责检查和解析传入的数据，让它符合你声明的类型。

例如：

```python
item_id: int
```

会让 FastAPI 自动处理整数解析与校验。

而：

```python
class ChatRequest(BaseModel):
    message: str
```

则可以定义更复杂的数据结构，例如 HTTP 请求中的 JSON 请求体。

这里要记住一个重要区别：

**简单的路径参数通常只需要类型注解，不需要每个参数都单独定义一个 Pydantic 模型。**

官方还说明，除了 `int`，你也可以使用 `str`、`float`、`bool` 等类型。

例如：

```python
@app.get("/prices/{price}")
def read_price(price: float):
    return {"price": price}
```

访问：

```text
/prices/19.99
```

就会得到：

```json
{
  "price": 19.99
}
```

## 六、顺序很重要：为什么官方特别强调路由顺序？

这一节非常重要！⭐

先看两种路径：

```text
/users/me
/users/123
```

假设你想实现两个功能：

- `/users/me`：查询当前登录的用户。
- `/users/{user_id}`：根据用户 ID 查询其他用户。

官方推荐这样写：

```python
from fastapi import FastAPI

app = FastAPI()

# 先定义固定路径
@app.get("/users/me")
def read_user_me():
    return {"user_id": "the current user"}

# 后定义动态路径
@app.get("/users/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}
```

### 1. 为什么要先定义 `/users/me`？

因为：

```python
/users/{user_id}
```

理论上可以匹配：

```text
/users/123
/users/abc
/users/me
/users/hello
```

`{user_id}` 可以接收任意符合路径匹配规则的单个路径段。

我们用一张流程图理解：

  

    **请求：GET /users/me**

  

  

先匹配 `/users/me`

      
      
匹配成功

  

  

    **执行 `read_user_me()`**
    
不会继续执行下面的动态路由

但是，如果你把顺序反过来：

```python
@app.get("/users/{user_id}")
def read_user(user_id: str):
    return {"user_id": user_id}

@app.get("/users/me")
def read_user_me():
    return {"user_id": "the current user"}
```

访问 `/users/me` 时，就会先匹配：

```python
/users/{user_id}
```

并把：

```python
user_id = "me"
```

传给第一个函数。

结果就变成：

```json
{
  "user_id": "me"
}
```

这不是你想要的当前用户信息。

### 2. 如果 `user_id` 是整数，会怎么样？

看这个例子：

```python
@app.get("/users/{user_id}")
def read_user(user_id: int):
    return {"user_id": user_id}

@app.get("/users/me")
def read_user_me():
    return {"user_id": "current user"}
```

访问 `/users/me`：

1. FastAPI 首先匹配 `/users/{user_id}`。
2. 提取到字符串 `"me"`。
3. 尝试把 `"me"` 转换成 `int`。
4. 转换失败。
5. 返回 HTTP 422。

**FastAPI 不会因为第一个路由参数校验失败，就继续尝试后面的 `/users/me`。**

因此，最容易记住的原则是：

**固定、具体的路径放前面；动态、宽泛的路径放后面。**

### 3. 同一路径能不能重复定义？

官方还举了一个例子：

```python
@app.get("/users")
def read_users():
    return ["Rick", "Morty"]

@app.get("/users")
def read_users2():
    return ["Bean", "Elfo"]
```

虽然这两个函数的名字不同，但它们都在注册：

```text
GET /users
```

在这个例子中，实际请求会匹配先注册的路由，因此返回：

```json
["Rick", "Morty"]
```

第二个函数不会因为名字不同而自动覆盖第一个接口。

注意，**路径和 HTTP 请求方法一起决定路由**。因此以下写法是可以的：

```python
@app.get("/users")
def get_users():
    return {"action": "get users"}

@app.post("/users")
def create_user():
    return {"action": "create user"}
```

虽然路径相同，但一个是 GET，一个是 POST，它们属于不同的接口操作。

以后开发 Agent 时，你完全可以这样设计：

```text
GET  /agents       查询 Agent 列表
POST /agents       创建 Agent
GET  /agents/me    查询当前用户的 Agent
GET  /agents/{id}  查询指定 Agent
```

这一章的路由顺序知识，在真实后端项目中会经常用到。

## 七、预设值：什么是 Enum 枚举？

这一节是官方教程中比较难理解的部分，尤其是：

```python
class ModelName(str, Enum):
```

以及：

```python
model_name: ModelName
```

我们先不急着看官方代码，先弄懂为什么需要 Enum。

### 1. 为什么需要枚举？

假设你开发一个 AI 模型查询接口，只允许用户选择以下三个模型：

```text
alexnet
resnet
lenet
```

你希望用户只能输入这三个值。

但是，如果使用普通的字符串路径参数：

```python
@app.get("/models/{model_name}")
def get_model(model_name: str):
    return {"model_name": model_name}
```

用户可以访问：

```text
/models/alexnet
/models/resnet
/models/hello
/models/abc
```

因为它们都是字符串，FastAPI 无法判断 `"abc"` 是不是你希望用户输入的模型名称。

这时候就需要 **Enum（枚举）**。

你可以把 Enum 想象成一份事先写好的合法选项名单。

  
Enum 的作用：只允许预先定义的选项

    
允许的模型

      
> *省略对话原版动态控件。*

  

    
    
FastAPI 验证用户输入

  

      

          
          **resnet**

        
允许访问 · 200

    

      

          
          **hello**

        
验证失败 · 422

    

所以：

- `str`：只检查是不是字符串。
- `Enum`：检查是不是预定义的合法选项。

### 2. 官方代码：创建 Enum 类

```python
from enum import Enum

class ModelName(str, Enum):
    alexnet = "alexnet"
    resnet = "resnet"
    lenet = "lenet"
```

我们逐行分析。

**第一行：**

```python
from enum import Enum
```

这是从 Python 标准库导入 `Enum`。

注意：`Enum` 属于 Python，不是 FastAPI 特有的功能。

**第二行：**

```python
class ModelName(str, Enum):
```

这行稍微复杂一些，拆成三部分：

| 代码 | 含义 |
|---|---|
| `class ModelName` | 定义一个名叫 `ModelName` 的类 |
| `str` | 这些枚举值具有字符串特性 |
| `Enum` | 让这个类成为枚举类型 |

你可能会问：

**为什么同时继承 `str` 和 `Enum`？**

因为这里不仅希望定义一组固定的选项，还希望它们在 API 中表现为字符串类型。

这样 FastAPI 可以在文档中正确展示字符串枚举值。

**接下来这三行：**

```python
alexnet = "alexnet"
resnet = "resnet"
lenet = "lenet"
```

它们分别定义了三个枚举成员。

这里要理解两个概念：

```python
ModelName.alexnet
```

代表一个枚举成员。

```python
ModelName.alexnet.value
```

代表这个枚举成员对应的实际值：

```python
"alexnet"
```

这两个概念不完全相同。

可以把枚举理解成：

| 枚举成员 | 对应的实际值 |
|---|---|
| `ModelName.alexnet` | `"alexnet"` |
| `ModelName.resnet` | `"resnet"` |
| `ModelName.lenet` | `"lenet"` |

### 3. 如何在 FastAPI 路径参数中使用 Enum？

把刚才定义的 `ModelName` 用到函数参数里：

```python
@app.get("/models/{model_name}")
def get_model(model_name: ModelName):
    return {"model_name": model_name}
```

关键在于：

```python
model_name: ModelName
```

它表示：

> FastAPI，帮我检查一下，用户输入的 `model_name` 是否属于 `ModelName` 中定义的合法选项。

### 5. 为什么有时候用 `is`，有时候用 `==`？

你可能已经注意到官方代码中有两种判断：

```python
if model_name is ModelName.alexnet:
```

以及：

```python
if model_name.value == "lenet":
```

这两种方式都能达到相应的判断目的，但比较的东西不同。

**第一种：比较是不是同一个枚举成员**

```python
model_name is ModelName.alexnet
```

这里使用 `is`，它通常用于判断两个引用是否指向同一个对象。对于普通的 Python Enum 成员，这样比较是有效的。

**第二种：比较枚举实际存储的值**

```python
model_name.value == "lenet"
```

这里先通过 `.value` 取出字符串，然后比较两个值是否相等。

例如：

```python
print(ModelName.lenet.value)
```

输出：

```text
lenet
```

你也可以写：

```python
if model_name == ModelName.lenet:
```

对初学者来说，我建议优先使用这种写法：

```python
if model_name == ModelName.alexnet:
    ...
```

它的含义直观，而且不需要先转换成普通字符串。

### 6. 为什么可以直接返回 Enum？

官方还有一个知识点：

```python
return {"model_name": model_name}
```

这里的 `model_name` 实际上是枚举成员，为什么最后 JSON 中却是一个字符串？

因为 FastAPI 能够对这个可 JSON 序列化的枚举成员进行编码，最终返回它对应的值。

也就是说：

```python
ModelName.alexnet
```

在响应 JSON 中会表现为：

```json
"alexnet"
```

你不需要总是手动写：

```python
model_name.value
```

不过，如果你希望在 Python 逻辑中明确取得枚举的字符串值，使用 `.value` 是很好的习惯。

### 7. `/docs` 会自动显示枚举选项

这个功能非常适合 Agent 开发！

在 `/docs` 中，FastAPI 可以根据 Enum 自动生成一个枚举选项控件。

用户不必自己猜测合法的模型名称，而是可以从 `alexnet`、`resnet` 和 `lenet` 中选择。

这也是 Enum 比普通字符串更适合固定选项接口的原因之一。

## 八、包含路径的路径参数：`{file_path:path}`

这是本章的最后一个技术知识点。

也是最容易搞混 `{file_path}` 和 `{file_path:path}` 的地方。

### 1. 普通路径参数的局限

先看普通写法：

```python
@app.get("/files/{file_path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

假设访问：

```text
/files/test.txt
```

可以正常匹配。

但是如果访问：

```text
/files/home/user/test.txt
```

可能就不行了。

原因是普通的 `{file_path}` 只匹配一个路径段，而路径段之间用 `/` 分隔。

换句话说，普通路径参数不能直接跨越多个 `/`。

### 2. 使用 `:path` 路径转换器

如果你希望接收包含 `/` 的完整路径，可以使用：

```python
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

关键是：

```python
{file_path:path}
```

这里：

- `file_path`：变量名称。
- `:path`：Starlette 提供的路径转换器。
- `file_path: str`：Python 函数中接收的数据类型仍然是字符串。

注意，两种冒号含义不一样：

```python
@app.get("/files/{file_path:path}")
#                         ^^^^^ 路由匹配方式

def read_file(file_path: str):
#                        ^^^ Python 类型注解
```

对比一下：

| URL | `{file_path}` | `{file_path:path}` |
|---|---|---|
| `/files/a.txt` | ✅ | ✅ |
| `/files/home/a.txt` | ❌ | ✅ |
| `/files/a/b/c.txt` | ❌ | ✅ |

### 3. 为什么官方文档中会出现双斜杠 `//`？

官方还提到一个比较奇怪的 URL：

```text
/files//home/johndoe/myfile.txt
```

为什么 `files` 后面有两个 `/`？

因为你想传递的文件路径是：

```text
/home/johndoe/myfile.txt
```

这个路径本身就以 `/` 开头。

把 URL 拆开：

```text
/files/     路由的固定部分
/home/...   路径参数的实际值
```

拼接以后：

```text
/files//home/johndoe/myfile.txt
```

因此：

```python
file_path = "/home/johndoe/myfile.txt"
```

而如果访问：

```text
/files/home/johndoe/myfile.txt
```

则是：

```python
file_path = "home/johndoe/myfile.txt"
```

区别就是开头有没有 `/`。

此外，官方还说明：OpenAPI 不能完整表达这种包含多层路径的参数匹配规则，因此自动文档不会明确展示 `:path` 的特殊语义。

这里补充一个安全提醒：虽然我们把变量叫作 `file_path`，但这个示例只是**返回字符串，并没有读取真实文件**。未来如果让用户通过 API 读取服务器文件，必须验证路径是否位于允许的目录中，防止目录穿越等安全问题。

## 问题一：FastAPI 如何从 URL 中获取参数？

**答：通过在 URL 路径中使用 `{参数名}`，FastAPI 会自动提取对应的值，并传给 Python 函数。**

例如：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/items/{item_id}")
def read_item(item_id):
    return {"item_id": item_id}
```

当用户访问：

```text
http://127.0.0.1:8000/items/100
```

FastAPI 执行以下过程：

  

    **用户访问 `/items/100`**

  

  

    **匹配 `/items/{item_id}`**
    
提取出 `item_id = "100"`

  

  

    **调用 `read_item(item_id="100")`**

  

  

    **返回 JSON**
    `{"item_id": "100"}`

注意：`{item_id}` 和函数参数 `item_id` 的名称必须一致。

## 问题二：如何利用 int、str、Enum 限制参数？

**答：在函数参数后添加类型注解，FastAPI 就会按照声明的类型自动解析和验证数据。**

### 1. 使用 `int`：限制为整数

```python
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id}
```

- `/items/100` → ✅ 返回 `{"item_id": 100}`
- `/items/abc` → ❌ 返回 422 数据校验错误
- `/items/3.14` → ❌ 返回 422 数据校验错误

### 2. 使用 `str`：接收字符串

```python
@app.get("/users/{username}")
def read_user(username: str):
    return {"username": username}
```

- `/users/tom` → ✅
- `/users/123` → ✅，因为 `"123"` 也可以是字符串

### 3. 使用 `Enum`：限制为预先定义的选项

```python
from enum import Enum

class AgentType(str, Enum):
    chat = "chat"
    code = "code"
    research = "research"

@app.get("/agents/{agent_type}")
def get_agent(agent_type: AgentType):
    return {"agent_type": agent_type}
```

- `/agents/chat` → ✅
- `/agents/code` → ✅
- `/agents/research` → ✅
- `/agents/music` → ❌ 返回 422

| 类型 | 用途 | 例子 |
|---|---|---|
| `int` | 需要整数 | 用户 ID |
| `str` | 接收文本 | 用户名 |
| `Enum` | 只能从固定选项中选择 | Agent 类型 |

**记忆技巧：`int` 管数字，`str` 管文本，`Enum` 管固定选项。**

注意：`int` 默认也允许负整数。若你想限定 ID 必须大于零，还需要额外添加数值约束。

## 问题三：为什么路由的定义顺序会影响执行？

**答：因为 FastAPI 会按照注册顺序匹配路由，先匹配成功的路由会被使用。**

例如，下面这种顺序不合理：

```python
@app.get("/users/{user_id}")
def get_user(user_id: str):
    return {"user_id": user_id}

@app.get("/users/me")
def get_me():
    return {"message": "当前用户"}
```

当访问：

```text
/users/me
```

FastAPI 会先匹配：

```python
/users/{user_id}
```

于是：

```python
user_id = "me"
```

第一个函数就被执行了，后面的 `/users/me` 没有机会执行。

**正确写法：**

```python
# 先写固定路径
@app.get("/users/me")
def get_me():
    return {"message": "当前用户"}

# 后写动态路径
@app.get("/users/{user_id}")
def get_user(user_id: str):
    return {"user_id": user_id}
```

这样：

| 请求 | 执行的函数 |
|---|---|
| `/users/me` | `get_me()` |
| `/users/123` | `get_user()` |
| `/users/tom` | `get_user()` |

记住一句话：**具体的固定路径在前，宽泛的动态路径在后。**

还有一个容易忽略的细节：如果动态路由先匹配成功，但参数类型检查失败，FastAPI 会返回 422，而不是自动尝试后面的固定路由。

## 问题四：如何接收包含 `/` 的多层路径？

**答：使用 `{参数名:path}` 路径转换器。**

普通路径参数：

```python
@app.get("/files/{file_path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

只能匹配一个路径段。

例如：

```text
/files/test.txt
```

但不能直接匹配：

```text
/files/images/cat/photo.png
```

因为其中包含多个 `/`。

需要改为：

```python
@app.get("/files/{file_path:path}")
def read_file(file_path: str):
    return {"file_path": file_path}
```

现在访问：

```text
/files/images/cat/photo.png
```

FastAPI 会提取：

```python
file_path = "images/cat/photo.png"
```

并返回：

```json
{
  "file_path": "images/cat/photo.png"
}
```

注意区分两个 `path`：

```python
@app.get("/files/{file_path:path}")
#                           ^^^^
# 路由路径转换器

def read_file(file_path: str):
#                        ^^^
# Python 参数类型
```

第一个 `path` 表示允许匹配包含 `/` 的路径；第二个 `str` 表示最终得到的是 Python 字符串。
