# 第一章：请求文件（Request Files）

## 一、文件上传的完整过程

上一章你已经理解了普通表单：

```text
用户填写姓名和留言
        ↓
点击提交
        ↓
浏览器发送表单数据
        ↓
FastAPI 使用 Form() 接收
```

现在，表单中增加一个**文件选择框**。

例如，用户要上传一份学习笔记：

  

    **学习资料上传 · 示意界面**

  

      

        **fastapi_notes.txt**
        
用户在电脑中选择的文件

      

  

    提交文件

  
示意界面：这里展示的是文件选择操作，不会实际上传。

此时用户不再只是提交字符串：

```text
nickname=alice
```

还要提交一个真实文件的内容，例如：

```text
fastapi_notes.txt
```

文件内容可能是：

```text
FastAPI 是一个用于构建 API 的 Python Web 框架。
```

这就引出了文件上传和普通表单的第一个区别。

| 普通表单字段 | 上传文件 |
|---|---|
| 用户填写文本，如 `alice` | 用户选择实际文件，如 `notes.txt` |
| 后端主要接收字符串等简单值 | 后端接收文件字节内容 |
| 通常使用 `Form()` | 通常使用 `File()` / `UploadFile` |

文件上传的完整流程是：

```text
用户点击“选择文件”
        ↓
浏览器获取用户选择的文件
        ↓
用户点击“提交”
        ↓
浏览器将文件内容放进 HTTP 请求体
        ↓
服务器收到 HTTP 请求
        ↓
FastAPI 解析文件上传字段
        ↓
Python 函数获得文件数据
```

**特别注意：上传文件不是把电脑上的文件路径告诉服务器，而是把文件内容通过 HTTP 发送给服务器。**

比如，客户端电脑上有：

```text
C:\Users\Alice\Documents\notes.txt
```

服务器不需要访问这个本地路径。浏览器会读取用户选择的文件，并通过网络发送其内容。

## 二、文件在 HTTP 请求中的位置

这里和之前的表单知识完全衔接。

普通表单通常使用：

```http
Content-Type: application/x-www-form-urlencoded
```

请求体类似：

```text
username=alice&message=hello
```

但文件内容可能是图片、PDF、音频等二进制数据，不能简单地全部当作普通表单字符串处理。

因此，包含文件的表单通常使用：

```http
Content-Type: multipart/form-data
```

`multipart` 可以理解为：**一个 HTTP 请求体被分成多个部分，每个部分可以包含一个表单字段或文件。**

例如下面是一份简化后的文件上传请求：

```http
POST /upload/ HTTP/1.1
Content-Type: multipart/form-data; boundary=abc123

--abc123
Content-Disposition: form-data; name="file"; filename="notes.txt"
Content-Type: text/plain

Hello FastAPI
--abc123--
```

这里不用记住全部 HTTP 语法，先看三个重点。

**第一：请求体依然是 Body。**

文件没有凭空创造新的 HTTP 数据位置。

**第二：`name="file"` 是表单字段名。**

FastAPI 要根据这个名字找到上传的文件。

**第三：文件内容跟随文件字段一起发送。**

`filename="notes.txt"` 是文件名信息，`Hello FastAPI` 是这里演示的文件内容。

`boundary` 是用于区分不同部分的分隔标记，正常使用浏览器或 HTTP 客户端时由它们自动处理，不需要你手写。

官方教程明确说明：文件上传使用表单数据，通常采用 `multipart/form-data`。

## 四、使用 bytes 接收文件

这是官方教程的第一种方式。

```python
from typing import Annotated

from fastapi import FastAPI, File

app = FastAPI()


@app.post("/files/")
async def create_file(
    file: Annotated[bytes, File()]
):
    return {
        "file_size": len(file)
    }
```

### 1. 最重要的一行

```python
file: Annotated[bytes, File()]
```

拆开来看：

| 代码 | 含义 |
|---|---|
| `file` | Python 函数参数名，同时默认对应上传字段名 |
| `bytes` | 上传内容将作为 Python 字节数据 |
| `File()` | 明确从文件上传字段中读取 |
| `Annotated[...]` | 将类型与 FastAPI 参数声明组合起来 |

你已经学过：

```python
username: Annotated[str, Form()]
```

现在变成：

```python
file: Annotated[bytes, File()]
```

语法很像，但用途不同：

- `Form()` 通常用于普通文本等表单字段。
- `File()` 用于上传文件。

### 2. Python 中的 bytes

你之前主要接触字符串：

```python
message = "Hello"
```

类型：

```python
str
```

而文件内容可以是一连串字节：

```python
content = b"Hello"
```

类型：

```python
bytes
```

所以：

```python
file: Annotated[bytes, File()]
```

表示 FastAPI 会将整个上传文件的内容读取出来，交给函数中的 `file` 变量。

例如用户上传一个文件，其内容为：

```text
Hello
```

那么：

```python
file
```

得到的类似：

```python
b"Hello"
```

于是：

```python
len(file)
```

结果为 5。

响应：

```json
{
  "file_size": 5
}
```

注意：`len(file)` 计算的是**字节数，不是文字字符数**。例如 UTF-8 编码下，两个汉字“你好”通常占 6 个字节，而不是 2 个。

### 3. bytes 方式的主要限制

这点非常重要。

使用：

```python
file: Annotated[bytes, File()]
```

FastAPI 会为你读取文件内容，而整个内容会作为 `bytes` 保存在内存中。

对于小型 TXT 文件，这样非常方便。

但对于几百 MB 的 PDF、音频或视频，如果同时有很多用户上传文件，就可能带来很大的内存压力。

所以：

**`bytes` 适合小文件或明确需要一次性获得全部内容的场景。**

对于更通用的 Agent 文件处理 API，我们通常更关注下一种方式。

## 五、使用 UploadFile 接收文件 ⭐

这是本章最值得掌握的内容。

官方教程还有一种写法：

```python
from fastapi import FastAPI, UploadFile

app = FastAPI()


@app.post("/uploadfile/")
async def create_upload_file(
    file: UploadFile
):
    return {
        "filename": file.filename
    }
```

在这里，`UploadFile` 是 FastAPI 提供的文件上传对象类型。

同样可以显式写为：

```python
from typing import Annotated
from fastapi import File, UploadFile

file: Annotated[UploadFile, File()]
```

我建议你先熟悉后一种形式，因为它更容易和以前学习的 `Annotated` 参数声明建立联系。

### 1. bytes 和 UploadFile 的区别

  

      

        **bytes**

        
把整个文件内容交给 Python，保存在内存中的 bytes 对象里。

        
适合小型文件

    

      

        **UploadFile**

        
提供可读取的文件对象、文件名、类型等信息，并支持按需读取。

        
适合更通用的上传场景

    

具体地说：

| 对比 | `bytes` + `File()` | `UploadFile` |
|---|---|---|
| 得到什么 | 文件内容的 bytes | 文件上传对象 |
| 文件名 | 不直接提供 | `file.filename` |
| 媒体类型 | 不直接提供 | `file.content_type` |
| 内存使用 | 整个内容作为 bytes 放在内存 | 使用可滚动到磁盘的临时文件 |
| 读取方式 | 内容已经读取完 | 可以按需读取 |
| 推荐用途 | 小文件 | PDF、图片、音频及一般文件上传 |

`UploadFile` 底层使用一种叫 `SpooledTemporaryFile` 的机制：先在内存中保存，超过一定阈值后可以转到磁盘，从而避免始终把整个文件都作为一个巨大的 bytes 对象留在内存中。

但请注意：如果你对 `UploadFile` 使用不带大小限制的 `await file.read()`，仍然可能把整个文件读入内存。

## 六、UploadFile 的属性

假设用户上传：

```text
report.pdf
```

对应的代码：

```python
@app.post("/upload/")
async def upload(
    file: UploadFile
):
    return {
        "filename": file.filename,
        "content_type": file.content_type
    }
```

可能返回：

```json
{
  "filename": "report.pdf",
  "content_type": "application/pdf"
}
```

这里：

```python
file.filename
```

表示客户端提供的文件名。

```python
file.content_type
```

表示客户端声明的文件媒体类型，例如：

- `text/plain`：普通文本。
- `application/pdf`：PDF。
- `image/png`：PNG 图片。
- `image/jpeg`：JPEG 图片。

但需要记住：

**文件名和 content_type 都来自客户端，不能仅凭它们就断定文件安全或内容真实。**

例如，一个恶意文件也可能自称 `report.pdf`。真实系统处理用户上传的文件时，还要有文件大小限制、内容检查、权限管理等措施。

## 七、UploadFile 的常用方法

`UploadFile` 不只有属性，还可以读取文件内容。

官方介绍了四个常用方法：

| 方法 | 作用 |
|---|---|
| `await file.read(size)` | 读取指定字节数 |
| `await file.write(data)` | 向文件对象写入数据 |
| `await file.seek(0)` | 将读取位置移到文件开头 |
| `await file.close()` | 关闭文件对象 |

在 `async def` 中调用这些异步方法时，要使用 `await`。

### 1. 读取部分内容

```python
@app.post("/preview/")
async def preview(
    file: UploadFile
):
    content = await file.read(100)

    return {
        "filename": file.filename,
        "preview_size": len(content)
    }
```

这里：

```python
await file.read(100)
```

表示最多读取 100 个字节。

它不是一定读取 100 个文字字符。

### 2. 理解读取位置

假设文件内容为：

```text
ABCDE
```

执行：

```python
first = await file.read(2)
```

得到：

```python
b"AB"
```

此时读取位置已经向后移动。

再执行：

```python
second = await file.read(2)
```

得到：

```python
b"CD"
```

不是再次得到 `b"AB"`。

如果希望重新从头读取：

```python
await file.seek(0)
```

再执行：

```python
content = await file.read()
```

就能重新读取完整内容。

这里的 `seek(0)` 非常值得记住。

### 3. 同步函数也可以读取

如果路径操作使用普通 `def`：

```python
@app.post("/sync-upload/")
def sync_upload(
    file: UploadFile
):
    content = file.file.read(100)

    return {
        "read_size": len(content)
    }
```

可以通过：

```python
file.file.read(100)
```

读取底层文件对象。

这是同步文件操作，与 `async def` 中的 `await file.read(100)` 有区别。

现阶段你只需要优先掌握：

```python
async def ...:
    content = await file.read(...)
```

## 八、可选文件上传与多文件上传

这两个功能也在《请求文件》官方教程中。

### 1. 可选文件上传

之前写：

```python
file: Annotated[UploadFile, File()]
```

没有默认值，所以必须上传文件。

如果用户可以不上传：

```python
@app.post("/files/optional")
async def optional_file(
    file: Annotated[UploadFile | None, File()] = None
):
    if file is None:
        return {"uploaded": False}

    return {
        "uploaded": True,
        "filename": file.filename
    }
```

这里和你之前学过的可选字段完全一致：

```python
UploadFile | None
```

允许文件对象或 `None`。

```python
= None
```

使文件参数可以省略。

但要区分：

- 没有选择文件：可能得到 `None`。
- 选择了一个内容为空的文件：仍可能得到 `UploadFile` 对象，只是文件大小为 0。

它们不是同一种情况。

### 2. 多文件上传

假设一个 Agent 任务需要同时上传：

```text
chapter1.txt
chapter2.txt
chapter3.txt
```

可以使用：

```python
from typing import Annotated

from fastapi import FastAPI, File, UploadFile

app = FastAPI()


@app.post("/files/multiple")
async def multiple_files(
    files: Annotated[list[UploadFile], File()]
):
    return {
        "filenames": [
            file.filename
            for file in files
        ]
    }
```

这里最重要的是：

```python
list[UploadFile]
```

它与之前学过的：

```python
list[Message]
list[AgentOut]
```

是相同的 Python 类型思想：**一个列表，里面装着多个指定类型的对象**。

只是这里每个元素都是一个上传文件对象。

客户端可以在同一次 HTTP 请求中发送多个同名的 `files` 文件字段。

响应例如：

```json
{
  "filenames": [
    "chapter1.txt",
    "chapter2.txt",
    "chapter3.txt"
  ]
}
```

也可以声明：

```python
files: Annotated[list[bytes], File()]
```

此时每个元素都是对应文件的完整 bytes 内容。

对于 Agent 上传多个 PDF 或文档的情况，通常优先考虑 `list[UploadFile]`。

## 十、第一章常见问题与错误

### 1. 没有选择必填文件

代码：

```python
file: Annotated[UploadFile, File()]
```

请求却没有 `file` 字段。

通常返回：

**HTTP 422。**

错误位置：

```json
["body", "file"]
```

因为上传文件仍属于请求体。

### 2. 文件字段名写错

后端：

```python
file: Annotated[UploadFile, File()]
```

客户端却发送：

```python
files={"document": f}
```

由于后端期待的是 `file`，通常会提示缺少对应字段。

名称应该匹配：

```python
files={"file": f}
```

### 3. 认为 UploadFile 会自动保存到项目目录

这是一个常见误解。

`UploadFile` 可以使用临时文件管理上传数据，但**它不等于你已经把文件永久保存进了数据库或某个指定目录**。

如果需要长期保存文档，还要主动实现：

- 文件持久化。
- 安全的存储路径。
- 文件大小与内容校验。
- 用户身份和文件访问权限管理。

### 4. 认为上传 PDF 就能直接得到文本

例如：

```python
file: UploadFile
```

只是接收文件。

它不会自动完成：

```text
PDF → 提取正文 → 分段 → 向量化 → 检索 → LLM 总结
```

这些都是未来 Agent/RAG 系统中的额外步骤。

`UploadFile` 解决的是**文件怎样进入后端**，不是**文件内容怎样被理解**。

**思考题 1 参考答案：**

`bytes` 会让整个文件作为一个 bytes 对象保存在内存中；`UploadFile` 使用可滚动到磁盘的临时文件，并允许分块读取，更适合较大的文件。

不过，`UploadFile` 并不是无限制的大文件解决方案。生产项目依然需要文件大小、存储空间、并发和安全限制。

**思考题 2 参考答案：**

```python
first  = b"AB"
second = b"CD"
third  = b"AB"
```

因为第一次读取后位置移动到 C；第二次读取后位置移动到 E；`seek(0)` 又让位置回到开头。

**第一章最重要的一句话：`File()` 指定文件上传来源，`bytes` 直接取得完整字节内容，`UploadFile` 则提供更灵活的文件对象和元数据。**
