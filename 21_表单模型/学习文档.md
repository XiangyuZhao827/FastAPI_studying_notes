# 第二章：表单模型（Form Models）

## 十一、为什么需要表单模型？

上一章，我们使用两个独立参数：

```python
@app.post("/login/")
def login(
    username: Annotated[str, Form()],
    password: Annotated[str, Form()]
):
    return {"username": username}
```

两个字段时很清楚。

但如果未来你的 Agent 平台有一个简单的配置页面，需要填写：

```text
agent_name = Chat Agent
max_steps = 3
theme = dark
debug = false
```

你可以为每个字段单独写一个 `Form()`，但字段逐渐增多时，接口函数就会越来越长。

回想你之前学过的三个模型：

```python
filters: Annotated[FilterParams, Query()]
```

```python
cookies: Annotated[AgentCookies, Cookie()]
```

```python
headers: Annotated[AgentHeaders, Header()]
```

它们的思路都是：

> 用 Pydantic 模型统一描述多个相关字段，再通过外层的参数工具指定数据来源。

表单模型也是一样的：

```python
data: Annotated[AgentSettingsForm, Form()]
```

这就是本章的核心。

## 十二、官网代码：用 Pydantic 接收整个表单

官方教程的核心示例：

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()


class FormData(BaseModel):
    username: str
    password: str


@app.post("/login/")
async def login(
    data: Annotated[FormData, Form()]
):
    return data
```

表单模型功能从 FastAPI **0.113.0** 开始支持。如果你的 FastAPI 版本比较旧，需要升级。

另外，官方示例直接返回 `data`，所以可能连 password 一起返回。它是演示表单模型解析的最简代码，**真实登录接口不应该照搬这种返回方式**。

下面我们逐行拆解。

### 1. FormData 是一个普通 Pydantic 模型

```python
class FormData(BaseModel):
    username: str
    password: str
```

你现在应该已经很熟悉了：

- `BaseModel`：定义字段结构。
- `username: str`：username 必填。
- `password: str`：password 必填。

到这里，它和你之前写的 `ChatRequest` 几乎没有区别。

### 2. 真正决定来源的是 Form()

```python
data: Annotated[FormData, Form()]
```

这行代码最重要。

我们拆开：

| 部分 | 作用 |
|---|---|
| `data` | Python 函数参数名 |
| `FormData` | Pydantic 模型类型 |
| `Form()` | 从 HTTP 表单字段读取数据 |
| `Annotated[...]` | 把类型与来源声明组合在一起 |

如果写成：

```python
data: FormData
```

没有 `Form()`，FastAPI 通常会把它当作普通 JSON Body 模型。

但是加上：

```python
Form()
```

以后，FastAPI 就会按照表单数据解析其中的各个字段。

### 3. 客户端需要发送什么？

正确的表单请求：

```http
POST /login/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

username=alice&password=example123
```

FastAPI 会构造一个类似：

```python
data = FormData(
    username="alice",
    password="example123"
)
```

的模型对象。

后端可以用：

```python
data.username
data.password
```

读取字段。

还可以调用：

```python
data.model_dump()
```

得到 Python 字典，但因为这个模型包含密码，**不要把整个字典直接写入日志或返回给客户端**。

### 4. 表单模型是否需要 data 外层？

**不需要。**

客户端不必发送：

```json
{
  "data": {
    "username": "alice",
    "password": "example123"
  }
}
```

因为这里不是 JSON Body。

它只需要提交名为 username 和 password 的普通表单字段。

这和你之前的 Cookie/Header 参数模型非常相似：

**Python 里把字段组织成了一个模型，不代表 HTTP 请求里也要增加一个同名的外层对象。**

## 十三、结合 Field() 为表单模型设置验证规则

这一部分是把你上一章学习的 `Field()` 直接用起来。

```python
from pydantic import BaseModel, Field


class LoginForm(BaseModel):

    username: str = Field(
        min_length=3,
        max_length=30
    )

    password: str = Field(
        min_length=8
    )
```

然后：

```python
@app.post("/login/")
def login(
    data: Annotated[LoginForm, Form()]
):
    return {
        "username": data.username,
        "message": "已收到合法格式的表单"
    }
```

现在会进行两层工作：

**第一层：Form()**

决定：

> 从 HTTP 请求体的表单字段中提取 username 和 password。

**第二层：Pydantic Field()**

决定：

> username 的长度必须在 3～30 之间，password 至少 8 个字符。

例如：

| 表单数据 | 结果 |
|---|---|
| `username=alice&password=example123` | 200 |
| `username=al&password=example123` | 422 |
| `username=alice&password=123` | 422 |
| 只有 username，没有 password | 422 |

因此，**Form() 决定数据来源，Field() 决定模型内部的规则。**

这句话和前面学习的 Query/Cookie/Header 模型可以完全对应。

## 十四、表单模型中的 `extra="forbid"` ⭐

你应该还记得之前讲过：

```python
model_config = {"extra": "forbid"}
```

它可以用于查询参数模型、Cookie 参数模型、Header 参数模型。

现在，它同样可以用于表单模型。

官方说明，表单模型禁止额外字段的功能从 FastAPI **0.114.0** 开始支持。

### 1. 示例代码

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel, Field

app = FastAPI()


class LoginForm(BaseModel):

    model_config = {
        "extra": "forbid"
    }

    username: str = Field(min_length=3)
    password: str = Field(min_length=8)


@app.post("/login/")
def login(
    data: Annotated[LoginForm, Form()]
):
    return {
        "username": data.username,
        "message": "字段验证通过"
    }
```

### 2. 合法请求

```text
username=alice&password=example123
```

没有额外字段，长度符合规则。

结果：HTTP 200。

### 3. 包含额外字段的请求

```text
username=alice&password=example123&role=admin
```

这里多了：

```text
role=admin
```

但是模型中只有：

```python
username
password
```

而且声明了：

```python
extra = "forbid"
```

因此 FastAPI 会拒绝这个额外字段。

错误响应的关键部分可能是：

```json
{
  "detail": [
    {
      "type": "extra_forbidden",
      "loc": ["body", "role"],
      "msg": "Extra inputs are not permitted",
      "input": "admin"
    }
  ]
}
```

这里：

```json
["body", "role"]
```

再次说明：

**Form 属于 HTTP Body，因此它的验证错误位置仍然是 body。**

### 4. 为什么要禁止额外字段？

它可以帮助你让 API 的输入结构更加严格。

例如：

```text
预期：username、password

实际：username、password、role
```

如果服务端明确不允许 role，就可以直接拒绝，而不是悄悄忽略它。

但要注意：

**`extra="forbid"` 只是输入结构验证，不是身份认证或权限控制。**

即使没有这个选项，服务器也不应该因为用户自己提交了：

```text
role=admin
```

就把他当作管理员。

管理员身份必须由可信服务器端逻辑确定。

## 十五、表单模型中的默认值、数值与布尔值

现在看一个更接近 Agent 开发的例子。

```python
from typing import Literal

from pydantic import BaseModel, Field


class AgentSettingsForm(BaseModel):

    agent_name: str = Field(
        min_length=3,
        max_length=40
    )

    max_steps: int = Field(
        default=3,
        ge=1,
        le=5
    )

    theme: Literal["light", "dark"] = "light"

    debug: bool = False
```

这四个字段分别是：

| 字段 | 类型 | 默认值 / 约束 |
|---|---|---|
| agent_name | str | 必填，长度 3～40 |
| max_steps | int | 默认 3，范围 1～5 |
| theme | Literal | 默认 light，只允许 light / dark |
| debug | bool | 默认 False |

接口：

```python
@app.post("/agent/settings")
def save_settings(
    data: Annotated[AgentSettingsForm, Form()]
):
    return data
```

注意，这是一个**模拟设置接口**，只是返回解析后的数据，不会真的保存配置。

### 1. 表单提交的原始值往往是字符串

例如：

```text
agent_name=Chat Agent&max_steps=2&theme=dark&debug=true
```

虽然表单里传输的是文本值：

```text
max_steps = "2"
debug = "true"
```

但 Pydantic 能根据模型类型进行解析：

```python
data.max_steps
# 2，Python int

data.debug
# True，Python bool
```

结果：

```json
{
  "agent_name": "Chat Agent",
  "max_steps": 2,
  "theme": "dark",
  "debug": true
}
```

### 2. 没有传 max_steps、theme、debug 呢？

假设只提交：

```text
agent_name=Chat Agent
```

由于其他字段有默认值，结果是：

```json
{
  "agent_name": "Chat Agent",
  "max_steps": 3,
  "theme": "light",
  "debug": false
}
```

你此前学过的：

```python
Field(default=3)
```

在表单模型中仍然照常生效。

### 3. 如果传 max_steps=9 呢？

因为：

```python
max_steps: int = Field(
    default=3,
    ge=1,
    le=5
)
```

要求：

\[
1 \le max\_steps \le 5
\]

而 9 超出了范围。

所以通常返回：

**HTTP 422。**

### 4. 关于 HTML 复选框

传统 HTML 复选框有一个特殊行为：

- 选中后通常会提交对应字段，默认值经常是 `"on"`。
- 没有选中时通常**不发送该字段**。

因此：

```python
debug: bool = False
```

是很实用的默认值设计。

选中并提交 `debug=on`，Pydantic 通常会解析为 `True`；没有提交 debug，则使用 `False`。

不过，正式 Agent 系统不能只凭客户端传来的 `debug=true` 开放内部日志、系统提示词或管理员功能；敏感调试权限仍然需要服务端授权。

## 十六、和以前学过的参数模型做一次完整对照

到这里，你已经学习过五种重要声明：

```python
# 1. 路径参数
agent_id: Annotated[int, Path(ge=1)]

# 2. 查询参数模型
filters: Annotated[FilterParams, Query()]

# 3. Cookie 参数模型
cookies: Annotated[AgentCookies, Cookie()]

# 4. Header 参数模型
headers: Annotated[AgentHeaders, Header()]

# 5. 表单参数模型
data: Annotated[AgentSettingsForm, Form()]
```

五者都是围绕同一个思想：

**让 FastAPI 明确知道：参数来自哪里，以及应该按什么类型和规则解析。**

最容易混淆的是 Body 与 Form：

```python
request: ChatRequest
```

通常是 JSON Body 模型。

```python
request: Annotated[ChatRequest, Form()]
```

则明确要求读取表单字段。

同一个 Pydantic 模型类可以用于不同位置，但数据编码方式必须与对应接口声明匹配。

# 十七、综合实战：用表单配置 Agent 🤖

现在我们把 `Form()`、`BaseModel`、`Field()` 和之前学过的响应模型结合起来。

## 1. 完整核心代码

创建 `agent_form_practice.py`：

```python
from typing import Annotated, Literal

from fastapi import FastAPI, Form
from pydantic import BaseModel, Field

app = FastAPI()


# 请求：表单模型
class AgentSettingsForm(BaseModel):
    agent_name: str = Field(
        min_length=3,
        max_length=40
    )

    max_steps: int = Field(
        default=3,
        ge=1,
        le=5
    )

    theme: Literal["light", "dark"] = "light"

    debug: bool = False


# 响应：对外输出模型
class AgentSettingsResponse(BaseModel):
    agent_name: str
    max_steps: int
    theme: str
    debug: bool


@app.post(
    "/agent/settings",
    response_model=AgentSettingsResponse
)
def save_settings(
    data: Annotated[AgentSettingsForm, Form()]
):
    return data
```

这个接口的职责只是**接收、验证并返回配置**。没有真实保存数据库，也没有执行 LangGraph。

注意两个模型的分工：

```python
data: Annotated[AgentSettingsForm, Form()]
```

负责接收表单。

```python
response_model=AgentSettingsResponse
```

负责规范响应。

这正好联系了你上一节学习的《响应模型－返回类型》。

## 2. 运行测试

点击 Execute。

```json
}
```

## 3. 使用 httpx 验证 Form 与 JSON 的区别

你之前已经用过 `httpx` 测试 Cookie 和 Header，现在再复习一次。

```python
import httpx

url = "http://127.0.0.1:8000/agent/settings"

# 正确：发送表单
response = httpx.post(
    url,
    data={
        "agent_name": "Chat Agent",
        "max_steps": "2",
        "theme": "dark",
        "debug": "true"
    }
)

print(response.status_code)
print(response.json())
```

`data={...}` 对应普通表单编码。

如果改为：

```python
response = httpx.post(
    url,
    json={
        "agent_name": "Chat Agent",
        "max_steps": 2,
        "theme": "dark",
        "debug": True
    }
)
```

这个接口通常返回 **422**，因为它要求接收 Form，而你发送了 JSON。

请记住：

**`data=` 和 `json=` 是 httpx 中两个不同的传参方式，影响请求体的实际编码格式。**

# 十九、两章知识总复习

| 比较维度 | 表单数据 | 表单模型 |
|---|---|---|
| 主要语法 | `Annotated[str, Form()]` | `Annotated[LoginForm, Form()]` |
| 数据来源 | 表单 Body | 表单 Body |
| 字段数量 | 通常逐个声明 | 集中在一个模型中 |
| 校验方式 | Form 参数约束 | Pydantic + Field |
| 是否可以设置默认值 | 可以 | 可以 |
| 是否能禁止额外字段 | 不通过单个字段的模型配置实现 | 可以使用 `extra="forbid"` |
| Agent 应用 | 简单登录输入 | 登录表单、Agent 设置表单 |

和之前学过的知识结合起来：

```text
Path     → URL 中的 Agent ID
Query    → URL 中的搜索与筛选条件
Cookie   → 浏览器会话相关数据
Header   → 请求元数据
Body     → JSON 任务内容
Form     → 表单编码的输入数据
```

**最重要的知识不是死记 `Form()` 的语法，而是理解：Form 和 JSON Body 都是请求体，区别在于客户端发送的数据格式；表单模型只是用 Pydantic 把多个表单字段组织起来。**
