# 08｜测试（Testing）

**FastAPI 用户指南 · 独立复习手册｜核心问题：怎样反复确认 Agent API 正常、错误请求也被正确处理？**

官方文档：https://fastapi.tiangolo.com/zh/tutorial/testing/

## 一、为什么需要自动化测试？

你第一次完成 `POST /chat` 时，在 `/docs` 中输入“你好”，看到正常回答，就证明这**一次**请求可用。但随后你可能会修改认证依赖、Agent 的配置模型或响应模型，旧功能可能被意外破坏。

自动化测试就是预先写好“输入 → 预期行为”，让程序以后能够反复核对。它关注的不是“永远返回 200”，而是**返回符合业务设计的正确结果**：该成功的成功，该拒绝的拒绝。

| 做法 | 谁发送请求 | 谁判断结果 | 适合做什么 |
| --- | --- | --- | --- |
| `/docs` 手动测试 | 人点击 Execute | 人阅读响应 | 探索接口、快速试验 |
| 自动化测试 | 测试程序 | `assert` 断言 | 重复检查功能和权限 |

## 二、官方的三个核心工具

- `TestClient`：创建模拟 HTTP 客户端，向 FastAPI 应用发起请求。
- `pytest`：找到并执行测试函数，汇总通过和失败信息。
- `assert`：判断实际结果是否与预期一致；不一致就让测试失败。

官方的 TestClient 基于 Starlette，底层使用 HTTPX。学习基础测试时不需要在终端单独启动一个 Uvicorn HTTP 服务器，它可以直接请求被导入的应用对象。

## 三、官方最小示例（可以直接阅读或运行）

```python
from fastapi import FastAPI
from fastapi.testclient import TestClient

app = FastAPI()


@app.get("/")
async def read_main():
    return {"msg": "Hello World"}


client = TestClient(app)


def test_read_main():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"msg": "Hello World"}
```

解读：

1. `client = TestClient(app)`：为这个应用准备测试请求客户端。
2. `client.get('/')`：模拟一次 GET 请求，取得 `response`。
3. `response.status_code`：检查 HTTP 状态码是否符合预期。
4. `response.json()`：将响应解析为 Python 数据，检查 JSON 内容。

以上函数名以 `test_` 开头，是 pytest 的常用自动发现规则。即使路由函数是 `async def`，基础 TestClient 的测试函数仍可用普通的 `def`；这里也不用 `await client.get(...)`。

## 四、测试代码通常放在哪里？

官方示例把应用和测试文件分开：

```text
app/
├── __init__.py
├── main.py
└── test_main.py
```

`main.py` 存应用，`test_main.py` 可通过 `from .main import app` 导入应用。这样你既能保持业务代码整洁，又能让测试直接对真实路由、校验规则和依赖逻辑发起请求。

在大型 Agent 项目中，也常使用独立 `tests/` 目录；本章重点是“测试代码与业务实现分开”，目录形式并非唯一。

运行方式：

```bash
python -m pip install pytest httpx
python -m pytest
```

pytest 会按测试文件和测试函数规则发现并运行它们。如果测试失败，它会展示失败的断言和上下文；如果通过，只能说明**这些已写出的测试条件**被满足，并不代表整个系统所有行为都已经覆盖。

## 五、必须测试错误请求，而不只是 200

官方扩展示例定义了读取和创建商品的接口，也模拟了 `X-Token: coneofsilence` 的请求头检查。典型测试包括：

| 测试情形 | 在官方示例中的预期 | 背后的知识点 |
| --- | --- | --- |
| 查询存在的商品 | 200 | 路径参数、正常读取 |
| 查询不存在的商品 | 404 | HTTPException、资源不存在 |
| 错误 X-Token | 400（该教学示例自行约定） | Header 与错误处理 |
| 创建新商品 | 200（官方示例） | POST + JSON 请求体 |
| 创建重复 ID 的商品 | 409 | 业务冲突 |

以下代码是官方测试思路的一个关键片段（假设已建立 `client`，应用有对应路径操作）：

```python
def test_read_nonexistent_item():
    response = client.get(
        "/items/baz",
        headers={"X-Token": "coneofsilence"},
    )
    assert response.status_code == 404
    assert response.json() == {"detail": "Item not found"}
```

这里测试**预期中的失败**。当不存在的商品准确返回 404，这个测试应该通过，而不是认为“出现 404 就是测试失败”。

## 六、测试请求可携带哪些内容？

你以前学过 Path、Query、Header、Body、Cookie、Form。TestClient 能按 HTTP 客户端的形式发送这些数据：

- `client.get('/items/123')`：测试指定路径。
- `client.get('/items', params={'limit': 5})`：测试查询参数。
- `client.get('/users/me', headers={'Authorization': 'Bearer ...'})`：测试请求头。
- `client.post('/items', json={'name':'book'})`：测试 JSON Body。
- `client.post('/token', data={'username':'alice','password':'...'})`：测试表单。
- `client.get('/items', cookies={'session':'demo'})`：按客户端 Cookie 方式发起测试。

这些只是 TestClient 的常见发送形式，带省略号的字符串是说明用占位符，不代表有效认证凭据。客户端是否获得 200 取决于对应 FastAPI 路由和验证逻辑。

## 七、Agent 实战：最值得先测的八种情况

你有 `POST /token`、`POST /chat`、`GET /agents/{id}`、`GET /sessions/{id}`。建议从这些测试开始：

1. 合法消息和合法身份：是否返回预期结构，且没有暴露内部敏感字段。
2. `message=''`：是否在 Pydantic 校验阶段被拒绝（常见为 422）。
3. 没有身份凭据：是否返回预期的 401。
4. 过期或伪造 Token：是否拒绝请求。
5. alice 访问 bob 的 Agent：是否正确做资源授权（教学场景常用 403）。
6. 查询不存在的 Agent：是否返回 404 或项目约定的结果。
7. 历史会话属于其他用户：是否防止越权读取私人记录。
8. LLM API 服务异常：是否有合理的错误处理、超时和响应，避免敏感日志泄漏。

**一个 Agent 特有的测试难点：**同样的问题让大模型回答，两次文字未必逐字相同。不要在所有测试中要求模型输出完全一致。初期优先验证 API 状态码、响应结构、授权规则；进一步的 Agent 行为测试可以通过模拟外部服务和制定明确的任务质量标准来实现。

## 八、测试与调试如何配合？

```text
运行 pytest → 发现某项断言失败
      ↓
查看预期值和实际值的差异
      ↓
用调试器找到传参/业务逻辑的问题
      ↓
修改代码，再次运行 pytest
```

测试负责“有没有偏离预期”，调试负责“为什么偏离预期”。如果把两者混成一回事，遇到复杂 Agent 问题就容易只会重试而找不到原因。

## 九、常见误区

1. **测试一定要先启动 FastAPI 吗？** 基础 TestClient 通常不需要独立启动 HTTP 服务。
2. **只测试一个成功场景够了吗？** 不够，应覆盖错误输入、权限、异常。
3. **断言返回 404，结果也是 404，是失败吗？** 不是，若符合预期就是测试通过。
4. **`response.json()` 是再次请求吗？** 不是，它解析已经收到的 HTTP 响应内容。
5. **LLM 回答不完全相同是否一定是 API 缺陷？** 不一定，要区分非确定性生成与稳定的 API 契约。

## 十、5 道复习题（附答案解析）

**1. TestClient 主要做什么？**  答：模拟客户端发起 HTTP 请求并取得响应。

**2. `assert response.status_code == 404` 是不是在要求服务永远报错？**  答：不是，只是在某个指定测试情形下断言它应返回 404。

**3. 为什么 pytest 能识别 `test_read_main`？**  答：符合测试函数发现的命名习惯。

**4. 为什么测试越权访问比只测 200 更重要？**  答：认证成功不意味着可以访问别人的 Agent，会话和文件需要独立授权检查。

**5. 怎么处理真实 LLM 输出不是每次都一样的问题？**  答：把稳定的协议/权限检查与内容质量测试分开，必要时模拟外部服务。

## 十一、思考题

你把 `/chat` 从一次性 JSON 改为 SSE，原来的一些自动化测试失败了。你要先检查什么，怎样设计新的测试目标？

**参考方向：**确认响应契约变化、Content-Type、事件字段与结束条件；测试合法/非法凭据、请求体验证和事件流结构，不要求生成文本逐字一致。

**本章一句话总结：**TestClient 发请求、pytest 跑测试、assert 判预期；可信 Agent API 必须验证正确的成功和正确的拒绝。
