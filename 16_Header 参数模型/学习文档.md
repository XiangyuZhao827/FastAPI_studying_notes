# 第四章：Header 参数模型

## 十二、为什么需要 Header 参数模型？

同样的道理，假设一个 Agent 系统需要读取：

```http
X-Client-Name: agent-web
X-Request-ID: req001
X-Debug: true
```

可以分别定义三个 Header 参数：

```python
x_client_name: Annotated[str, Header()]
x_request_id: Annotated[str | None, Header()] = None
x_debug: Annotated[bool, Header()] = False
```

但如果很多接口都需要读取这些请求头，就可以把它们组织成一个模型。

## 十三、官方代码：Header 参数模型

```python
from typing import Annotated

from fastapi import FastAPI, Header
from pydantic import BaseModel

app = FastAPI()


class CommonHeaders(BaseModel):
    host: str
    save_data: bool
    if_modified_since: str | None = None
    traceparent: str | None = None
    x_tag: list[str] = []


@app.get("/items/")
async def read_items(
    headers: Annotated[CommonHeaders, Header()]
):
    return headers
```

这同样是官方教程中的核心示例。Header 参数模型也要求 FastAPI 0.115.0 或更新版本。

### 1. 解释 CommonHeaders 模型

```python
class CommonHeaders(BaseModel):
    host: str
    save_data: bool
    if_modified_since: str | None = None
    traceparent: str | None = None
    x_tag: list[str] = []
```

| Python 字段 | HTTP Header | 含义 |
|---|---|---|
| `host` | `Host` | 请求访问的主机 |
| `save_data` | `save-data` | 一个布尔值配置 |
| `if_modified_since` | `if-modified-since` | 条件请求时间信息 |
| `traceparent` | `traceparent` | 分布式追踪相关信息 |
| `x_tag` | `x-tag` | 可重复的请求头列表 |

这里的：

```python
save_data: bool
```

没有默认值，因此是**必填的**。

但 `Host` 通常由 HTTP 客户端自动提供。

### 2. 为什么字段名又自动转换了？

例如：

```python
save_data: bool
```

HTTP 请求头要写：

```http
save-data: true
```

而不是默认使用：

```http
save_data: true
```

因为 `Header()` 默认仍然会将 `_` 转为 `-`。

### 3. 布尔值如何解析？

例如：

```http
save-data: true
```

到了 Pydantic 模型中，就变为：

```python
headers.save_data is True
```

如果传入：

```http
save-data: false
```

就解析为 `False`。

如果传入无法解析的值，比如：

```http
save-data: maybe
```

则会因为类型校验失败而通常返回 **422**。

### 4. 模型中的 x_tag 列表

例如：

```http
X-Tag: python
X-Tag: research
```

模型字段：

```python
x_tag: list[str] = []
```

就可以接收多个值。

你也可以改成我们之前学过的：

```python
from pydantic import Field

x_tag: list[str] = Field(default_factory=list)
```

这样能更明确地表达“没有提供标签时，创建一个空列表”。

## 十四、Header 模型也能 extra="forbid"

例如：

```python
class CommonHeaders(BaseModel):
    model_config = {"extra": "forbid"}

    host: str
    save_data: bool
```

如果客户端添加了其他 Header：

```http
tool: search
```

也可能出现：

```json
{
  "detail": [
    {
      "type": "extra_forbidden",
      "loc": ["header", "tool"],
      "msg": "Extra inputs are not permitted",
      "input": "search"
    }
  ]
}
```

官方教程也介绍了这种用法。

但和 Cookie 类似，这个功能也需要谨慎使用。

**真实浏览器和 HTTP 客户端通常会自动发送多个 Header，例如 `Accept`、`User-Agent`、`Host` 等。**

如果你没有在模型中声明这些 Header，又启用了 `extra="forbid"`，就可能导致正常请求也被拒绝。

对于你当前学习 Agent API 的阶段，我更建议先理解该功能，而不是在所有 Header 模型中默认开启它。

## 十五、Header 参数模型还可以关闭下划线转换吗？

可以。

```python
@app.get("/demo")
def demo(
    headers: Annotated[
        CommonHeaders,
        Header(convert_underscores=False)
    ]
):
    return headers
```

此时不再默认将：

```python
save_data
```

映射成：

```http
save-data
```

而是按包含下划线的名称处理。

但是部分 HTTP 代理服务器会限制这类请求头，所以一般保留默认行为更合适。

## 十六、把四章放在一起理解

现在再回头看四个最重要的声明：

| 学习内容 | FastAPI 声明 | 获取的数据 |
|---|---|---|
| 单个 Cookie 参数 | `session_id: Annotated[str, Cookie()]` | 单个字符串 |
| 单个 Header 参数 | `user_agent: Annotated[str, Header()]` | 单个字符串 |
| Cookie 参数模型 | `cookies: Annotated[Cookies, Cookie()]` | 一个 Pydantic 模型实例 |
| Header 参数模型 | `headers: Annotated[CommonHeaders, Header()]` | 一个 Pydantic 模型实例 |

真正应该记住的结构是：

```python
# 单个参数
name: Annotated[str, Cookie()]
name: Annotated[str, Header()]

# 一组相关参数
cookies: Annotated[CookiesModel, Cookie()]
headers: Annotated[HeadersModel, Header()]
```

**两套知识点不是四种完全不同的语法，而是“两个数据来源 × 两种组织方式”。**

接下来我们会把它们全部放进一个 Agent 对话接口里。

# 十七、综合实战：把五种参数来源全部接入 Agent 🤖

现在我们创建一个模拟 Agent API，让你看到之前学过的所有参数如何协作。

项目文件：`fastapi_cookie_header_agent.py`

### 1. 完整可运行代码

```python
from typing import Annotated, Literal

from fastapi import (
    Cookie,
    FastAPI,
    Header,
    HTTPException,
    Path,
    Query,
)
from pydantic import BaseModel, Field


app = FastAPI(
    title="Agent API - Cookie and Header Practice"
)

AGENTS = {
    1: "Chat Agent",
    2: "Code Agent",
    3: "Research Agent",
}


# ===== 1. 单个 Cookie 参数 =====

@app.get("/demo/cookie")
def demo_cookie(
    ads_id: Annotated[
        str | None,
        Cookie(min_length=3)
    ] = None
):
    return {"ads_id": ads_id}


# ===== 2. 单个 Header 参数 =====

@app.get("/demo/header")
def demo_header(
    user_agent: Annotated[
        str | None,
        Header()
    ] = None
):
    return {"user_agent": user_agent}


# ===== 3. 重复的 Header =====

@app.get("/demo/header-tags")
def demo_header_tags(
    x_tag: Annotated[
        list[str] | None,
        Header()
    ] = None
):
    return {"tags": x_tag or []}


# ===== 4. Cookie 参数模型 =====

class AgentCookies(BaseModel):
    session_id: str = Field(
        min_length=3,
        max_length=40
    )

    theme: Literal["light", "dark"] = "light"


@app.get("/demo/cookie-model")
def demo_cookie_model(
    cookies: Annotated[AgentCookies, Cookie()]
):
    return {
        "session_cookie_received": bool(cookies.session_id),
        "theme": cookies.theme,
    }


# ===== 5. Header 参数模型 =====

class AgentHeaders(BaseModel):
    x_client_name: str = Field(
        min_length=2,
        max_length=40
    )

    x_request_id: str | None = None
    x_debug: bool = False


@app.get("/demo/header-model")
def demo_header_model(
    headers: Annotated[AgentHeaders, Header()]
):
    return headers.model_dump()


# ===== 6. Agent 对话请求体 =====

class ChatRequest(BaseModel):
    message: str = Field(
        min_length=1,
        max_length=2000
    )

    max_steps: int = Field(
        default=3,
        ge=1,
        le=5
    )


# ===== 7. Agent 响应模型 =====

class ChatResponse(BaseModel):
    agent_id: int
    agent_name: str
    answer: str
    steps: list[str]
    theme: Literal["light", "dark"]
    client_name: str
    request_id: str | None = None
    debug: bool
    session_cookie_received: bool


# ===== 8. 五种参数来源联合使用 =====

@app.post(
    "/agents/{agent_id}/chat",
    response_model=ChatResponse
)
def agent_chat(

    agent_id: Annotated[int, Path(ge=1)],

    request: ChatRequest,

    cookies: Annotated[
        AgentCookies,
        Cookie()
    ],

    headers: Annotated[
        AgentHeaders,
        Header()
    ],

    verbose: Annotated[
        bool,
        Query()
    ] = False

):

    if agent_id not in AGENTS:
        raise HTTPException(
            status_code=404,
            detail="Agent not found"
        )

    planned_steps = [
        "理解用户问题",
        "制定执行计划",
        "调用模拟工具",
        "整理信息",
        "生成模拟回答",
    ]

    steps = planned_steps[:request.max_steps]

    answer = (
        f"{AGENTS[agent_id]} 收到了：{request.message}"
    )

    if verbose:
        answer += f"（展示 {len(steps)} 个模拟步骤）"

    if headers.x_debug:
        answer += " [client debug requested]"

    return ChatResponse(
        agent_id=agent_id,
        agent_name=AGENTS[agent_id],
        answer=answer,
        steps=steps,
        theme=cookies.theme,
        client_name=headers.x_client_name,
        request_id=headers.x_request_id,
        debug=headers.x_debug,
        session_cookie_received=bool(cookies.session_id),
    )
```

这里为了便于学习，把所有接口放在同一个文件中。实际项目一般会把路由、Pydantic 模型、Agent 执行器和会话管理分别放在不同模块。

## 十八、最关键的五个参数：逐行分析

看综合接口：

```python
def agent_chat(
    agent_id: Annotated[int, Path(ge=1)],
    request: ChatRequest,
    cookies: Annotated[AgentCookies, Cookie()],
    headers: Annotated[AgentHeaders, Header()],
    verbose: Annotated[bool, Query()] = False
):
    ...
```

这正好涵盖了五种参数来源。

| Python 参数 | 对应的数据 | 来自哪里 |
|---|---|---|
| `agent_id` | `2` | Path |
| `request` | `message`、`max_steps` | JSON Body |
| `cookies` | `session_id`、`theme` | Cookie |
| `headers` | `x_client_name`、`x_request_id`、`x_debug` | Header |
| `verbose` | `true` | Query |

它们进入函数后，统一变成 Python 对象或变量：

```python
agent_id
# 2

request.message
# "请解释 FastAPI"

request.max_steps
# 2

cookies.theme
# "dark"

headers.x_client_name
# "web-demo"

headers.x_debug
# True

verbose
# True
```

这里还有一个特别重要的跨章节知识点：

**虽然这个接口同时包含 Cookie 模型与 Header 模型，但它只有一个 JSON Body 模型 `request: ChatRequest`。**

因此默认请求体仍是：

```json
{
  "message": "请解释 FastAPI",
  "max_steps": 2
}
```

而不是：

```json
{
  "request": {
    "message": "请解释 FastAPI",
    "max_steps": 2
  }
}
```

只有使用 `Body(embed=True)` 或存在其他 Body 参数等情况时，才需要考虑额外的 JSON 包装层。

## 二十、常见错误：怎样区分 Cookie、Header、Body 的 422？

错误响应通常带有 `loc`，表示校验失败的位置。

| 错误位置 | 代表什么 |
|---|---|
| `["cookie", "session_id"]` | Cookie 的 session_id |
| `["header", "x_client_name"]` | Header 模型的 x_client_name |
| `["body", "message"]` | 请求体的 message |
| `["body", "max_steps"]` | 请求体的 max_steps |
| `["path", "agent_id"]` | 路径参数 agent_id |

例如：

```json
{
  "message": "",
  "max_steps": 6
}
```

会返回 422，因为 `message` 为空，并且 `max_steps` 大于模型允许的最大值 5。

而访问 `/agents/99/chat`，如果其他参数都合法，则会因为 Agent 99 不存在而得到 **404**。

还有一个重要的安全认识：

**Cookie 中保存的 session_id 只是标识，Header 中的 X-Client-Name 只是客户端提供的名称。FastAPI 能解析它们，但不会自动验证其真实性或完成授权。**
