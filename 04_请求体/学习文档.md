# 📘 FastAPI 请求体（Request Body）：零基础完整讲解

前面我们已经学习了 FastAPI 的两大基础知识：

- **路径参数（Path Parameters）**：通过 URL 路径传递数据。
- **查询参数（Query Parameters）**：通过 URL 中的 `?` 和 `&` 传递数据。

现在来到第三个核心知识点：**请求体（Request Body）**。

这一章尤其重要，因为你之前写的第一个 Agent API：

```python
@app.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest):
    result = run_agent(request.message)
    return ChatResponse(answer=result)
```

实际上就已经使用了请求体！

学完这一章，你不仅能理解官方的全部代码，还会真正明白：

**用户输入的问题，是如何从 JSON 变成 Python 对象，最终传递给 Agent 函数的。**

本次讲解按照 <Link url={turn486543view0.url.uri} title="FastAPI 官方中文教程《请求体》"/> 的章节顺序，结合官方代码、逐行拆解、流程图、运行结果以及 Agent 实战进行讲解。

## 一、什么是请求体（Request Body）？

### 1. 先看一个实际场景

假设你开发了一个 AI Agent，用户想问：

> 请帮我解释 FastAPI 和 LangGraph 的区别。

我们已经学过两种传递数据的方法。

**方法一：使用路径参数**

```text
/agents/123
```

适合传递 Agent 的 ID。

**方法二：使用查询参数**

```text
/agents?mode=chat&limit=10
```

适合传递筛选条件或其他简单选项。

但如果用户的问题很长，包含多段文字，甚至还需要同时提交会话 ID、模型配置等数据，把它们全部拼进 URL 就不合适了。

所以我们可以使用第三种方法：

**将数据放进 HTTP 请求体中。**

例如：

```text
POST /chat
```

请求体：

```json
{
  "message": "请帮我解释 FastAPI 和 LangGraph 的区别",
  "session_id": "abc123"
}
```

FastAPI 就能够从请求体里读取用户的问题和会话 ID。

### 2. 请求体到底在哪里？

一个 HTTP 请求不只是一个 URL，还可以包含请求头和请求体。

  
HTTP 请求结构示意图

    

        **① 请求行（Request Line）**
        
POST

      
`POST /chat HTTP/1.1`

告诉服务器使用什么方法、访问哪个路径

    

      **② 请求头（Headers）**
      
`Content-Type: application/json`

告诉服务器：请求体使用 JSON 格式

    

      

        **③ 请求体（Body）**
        
本章重点

      ```json
      {
        "message": "你好，Agent！",
        "session_id": "abc123"
      }
      ```
      
客户端真正提交给后端的业务数据

  

因此，请求体并不是 URL 的某个特殊部分，而是 HTTP 请求中的一个独立部分。

### 3. 请求体和响应体有什么区别？

这是官方文档开头特别强调的概念。

- **请求体（Request Body）**：客户端发送给服务器的数据。
- **响应体（Response Body）**：服务器返回给客户端的数据。

对于 Agent 项目：

  

    **用户 / 前端**
    
提出问题

  

    
请求体：用户的问题

  

    **FastAPI + Agent**
    
接收数据、处理任务

  

    
响应体：Agent 的回答

  

    **用户收到回答**

例如，请求体：

```json
{
  "message": "Python 是什么？"
}
```

经过 Agent 处理后，响应体可能是：

```json
{
  "answer": "Python 是一种高级编程语言。"
}
```

**一句话理解：请求体是输入，响应体是输出。**

### 4. 请求体为什么通常与 POST 一起使用？

官方提到：发送请求体时，一般会使用 POST、PUT、PATCH 或 DELETE 等 HTTP 方法，而不推荐在 GET 请求中发送请求体。

| 方法 | 常见用途 | 例子 |
|---|---|---|
| GET | 查询资源 | 获取 Agent 列表 |
| POST | 创建资源或提交处理任务 | 向 Agent 发送问题 |
| PUT | 更新或替换资源 | 更新 Agent 配置 |
| PATCH | 局部更新 | 修改 Agent 名称 |
| DELETE | 删除资源 | 删除某个 Agent |

GET 请求通常不使用请求体。虽然 FastAPI 在技术上支持某些带请求体的 GET 用法，但 HTTP 相关规范和中间系统的支持并不一致，所以初学阶段不应该采用这种设计。

## 二、为什么 FastAPI 要使用 Pydantic 的 `BaseModel`？

这是官方《请求体》一章最重要的概念。

### 1. 先理解一个问题

假设用户向你的 API 提交：

```json
{
  "name": "Python Agent",
  "price": 99.9
}
```

你希望：

- `name` 必须是字符串。
- `price` 必须是数字。
- 两个字段都必须提供。
- 如果用户输入错误，程序能自动提示。

那么，如何规定输入数据的格式呢？

这就是 **Pydantic 数据模型**的作用。

可以把它理解为一张提前制定好的数据表格：

| 字段 | 允许的类型 | 是否必填 |
|---|---|---|
| name | str | 是 |
| price | float | 是 |
| description | str 或 None | 否 |
| tax | float 或 None | 否 |

用户提交的数据必须符合这张表格规定的规则。

### 2. 官方第一段代码

官方首先导入：

```python
from fastapi import FastAPI
from pydantic import BaseModel
```

这两个东西的职责不同。

| 名称 | 作用 |
|---|---|
| `FastAPI` | 创建 Web API，接收 HTTP 请求 |
| `BaseModel` | 定义数据结构、解析与校验输入 |

注意：**Pydantic 是一个独立的 Python 库，不是 FastAPI 自己发明的数据类型。**

FastAPI 利用了 Pydantic 提供的数据验证能力。

### 3. 创建一个 Pydantic 数据模型

下面是官方的 `Item` 模型：

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
```

看起来只有几行代码，但里面包含很多初学者需要掌握的 Python 知识。

我们逐行分析。

**第一行：**

```python
class Item(BaseModel):
```

这里使用了 Python 的 `class` 语法。

`Item` 是你自己定义的类名。

`BaseModel` 是 Pydantic 提供的基类。

这段代码表示：

> 我想创建一种名为 Item 的数据模型，并且让它拥有 Pydantic 提供的数据解析和校验能力。

你可以把 `Item` 理解成一张数据填写模板。

**第二行：**

```python
name: str
```

表示：

- 属性名称：`name`
- 数据类型：`str`
- 没有默认值，所以必须提供

**第三行：**

```python
description: str | None = None
```

这是一个可选字段。

拆开来看：

| 代码 | 含义 |
|---|---|
| `description` | 字段名称 |
| `str` | 可以是字符串 |
| `\| None` | 也允许 None |
| `= None` | 没有提交时默认使用 None |

**第四行：**

```python
price: float
```

表示价格必须能够解析为浮点数，并且没有默认值，所以是必填字段。

例如：

```python
99.9
20.0
3.14
```

**第五行：**

```python
tax: float | None = None
```

表示税费可以是数字，也可以不提供。

### 4. 如何通过 JSON 向 Item 模型传递数据？

按照这个模型，下面的 JSON 是合法的：

```json
{
  "name": "Computer",
  "description": "A powerful computer",
  "price": 4999.0,
  "tax": 100.0
}
```

因为所有字段都符合要求。

但由于 `description` 和 `tax` 有默认值，下面这样同样合法：

```json
{
  "name": "Computer",
  "price": 4999.0
}
```

Pydantic 会自动补充默认值：

```python
description = None
tax = None
```

但是下面这样就不合法：

```json
{
  "name": "Computer"
}
```

原因是缺少必填字段 `price`。

### 6. `str | None` 和 `= None` 再次出现

还记得我们上一章的结论吗？

```python
q: str | None = None
```

这里有两个不同的概念：

- `str | None`：规定允许什么类型。
- `= None`：规定没有传值时使用什么默认值。

在 Pydantic 数据模型中也是一样。

例如：

```python
class Item(BaseModel):
    name: str
    description: str | None
```

这里的 `description` 虽然允许 `None`，但因为没有默认值，仍然要求客户端提供这个字段。

而：

```python
class Item(BaseModel):
    name: str
    description: str | None = None
```

就允许客户端完全不提供 `description`。

这也是为什么我们要区分：

**可为空（nullable）和可省略（not required），不是同一个概念。**

## 三、将 Pydantic 模型声明为函数参数

现在来到官方的「声明为参数」部分。

前面只是创建了一个 `Item` 模型，但 FastAPI 怎么知道需要使用这个模型呢？

答案就是：**把它写成路径操作函数的参数类型。**

### 1. 官方完整基础代码

```python
from fastapi import FastAPI
from pydantic import BaseModel


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None


app = FastAPI()


@app.post("/items/")
async def create_item(item: Item):
    return item
```

我们重点分析这三行：

```python
@app.post("/items/")
async def create_item(item: Item):
    return item
```

**第一行：**

```python
@app.post("/items/")
```

告诉 FastAPI：

用户使用 POST 方法访问 `/items/` 时，就执行下面的函数。

**第二行：**

```python
async def create_item(item: Item):
```

这行最关键的是：

```python
item: Item
```

和之前学习的：

```python
item_id: int
```

比较一下：

| 声明 | FastAPI 的一般识别方式 |
|---|---|
| `item_id: int`，出现在路径中 | 路径参数 |
| `limit: int = 10`，不在路径中 | 查询参数 |
| `item: Item`，Item 继承 BaseModel | 请求体 |

因为 `Item` 是 Pydantic 模型，FastAPI 就知道：应该从请求体读取符合 `Item` 结构的数据。

**第三行：**

```python
return item
```

表示把解析后的 `Item` 模型对象返回给客户端。

FastAPI 会将它转换成 JSON 响应。

### 2. 一个非常重要的问题：`item` 是什么？

假设客户端发送：

```json
{
  "name": "Book",
  "price": 45.2
}
```

FastAPI 会读取 JSON，然后根据 `Item` 模型解析并校验。

最终进入函数时，`item` 不是原始 JSON 字符串，也不是普通的 `dict`，而是一个 **Item 模型实例**。

你可以把它理解为 FastAPI 已经替你完成了类似下面的工作：

```python
item = Item(
    name="Book",
    price=45.2
)
```

因此可以像访问对象属性一样使用它：

```python
item.name
item.price
item.description
item.tax
```

你还可以自己运行一个实验：

```python
@app.post("/items/")
def create_item(item: Item):
    print(type(item))
    print(item.name)
    print(item.price)

    return item
```

当用户提交数据后，终端会打印：

```text
<class '__main__.Item'>
Book
45.2
```

它说明 `item` 已经成为 Python 对象。

### 3. 看懂整个请求处理流程

  
FastAPI + Pydantic 请求处理流程

    **① 客户端发送 POST 请求**
    
JSON：name = "Book"，price = 45.2

  

  

    **② FastAPI 解析请求体**
    
识别函数参数 `item: Item`

  

  

    **③ Pydantic 校验数据**
    
检查必填字段、解析类型、填充默认值

  

  

      

        **验证成功**
        
执行 create_item(item)

    

      

        **验证失败**
        
返回 HTTP 422

    

  
校验失败时，正常情况下不会进入 create_item 函数。

### 4. 为什么请求体不需要额外包裹一个 `item`？

这一点很容易搞混。

看下面的函数：

```python
@app.post("/items/")
def create_item(item: Item):
    return item
```

客户端应该发送：

```json
{
  "name": "Book",
  "price": 45.2
}
```

而不是：

```json
{
  "item": {
    "name": "Book",
    "price": 45.2
  }
}
```

**原因是：这里只有一个 Pydantic 请求体参数，FastAPI 默认直接使用整个 JSON 对象来创建 Item。**

函数参数叫 `item`，不意味着 JSON 最外层一定需要一个叫 `item` 的字段。

以后学习《请求体 - 多个参数》时，你会遇到需要把模型嵌入到 `item` 字段中的情况，但这一章的基础写法还不需要。

### 5. `async def` 是必需的吗？

不是。

官方使用：

```python
async def create_item(item: Item):
    return item
```

你也可以写：

```python
def create_item(item: Item):
    return item
```

对于这个简单示例，两者都可以正常工作。

`async def` 与异步编程有关，主要在以后调用异步 LLM SDK、数据库或网络 API 时发挥作用。

你现在的学习重点是：**请求体数据如何进入函数。** 暂时不用把 `async/await` 和 Pydantic 数据模型混在一起理解。

## 四、请求体的结果：FastAPI 自动帮我们完成了什么？

这是官方的「结果」「自动文档」和「编辑器支持」三节。

当你声明：

```python
@app.post("/items/")
def create_item(item: Item):
    return item
```

FastAPI 会自动完成很多原本需要手写的事情。

| 功能 | FastAPI 的作用 |
|---|---|
| 解析 JSON | 读取请求体数据 |
| 类型转换 | 根据 Pydantic 模型解析类型 |
| 数据校验 | 检查缺失字段、错误类型 |
| 错误提示 | 生成清晰的 422 错误信息 |
| 创建模型对象 | 把合法数据交给 `item` |
| 自动文档 | 在 `/docs` 显示请求体结构 |
| 编辑器提示 | 在 VS Code 中提示模型属性 |

### 1. 如果请求体数据错误会怎样？

我们来做一个实验。

模型要求：

```python
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None
```

但用户发送：

```json
{
  "name": "Book",
  "price": "hello"
}
```

注意：

```json
"price": "hello"
```

而你要求：

```python
price: float
```

Pydantic 无法把 `"hello"` 解析成浮点数，于是 FastAPI 返回 HTTP 422。

错误信息中会出现类似：

```json
{
  "type": "float_parsing",
  "loc": ["body", "price"],
  "msg": "Input should be a valid number, unable to parse string as a number",
  "input": "hello"
}
```

这里展示的是响应 `detail` 中的单个错误对象。

最重要的是：

```json
"loc": ["body", "price"]
```

它告诉你：

> 错误发生在请求体（body）的 price 字段。

回忆之前两章，我们已经见过三种错误位置：

| 错误位置 | 含义 |
|---|---|
| `["path", "item_id"]` | 路径参数错误 |
| `["query", "limit"]` | 查询参数错误 |
| `["body", "price"]` | 请求体字段错误 |

以后你调试 Agent API 时，只要看到 `loc`，就可以快速判断错误发生在哪里。

### 2. 自动生成 Swagger UI 文档

你已经使用过：

```text
http://127.0.0.1:8000/docs
```

当 FastAPI 发现 `item: Item` 时，会把 `Item` 模型转换成 JSON Schema，进而自动生成请求体文档。

例如：

  

    

Request Body API

Swagger UI 示意

  

    

POST

      **/items/**
      
create_item

    

Request body · application/json

    ```json
    {
      "name": "Book",
      "description": "Python tutorial",
      "price": 45.2,
      "tax": 3.5
    }
    ```

      
      
Try it out → Execute

  

在真实的 Swagger UI 中，你还会看到字段类型、必填要求和响应信息。

因此，**Pydantic 不仅用于数据校验，也相当于帮助 FastAPI 自动生成接口的数据说明书。**

### 3. 编辑器为什么可以自动补全？

假设你写：

```python
@app.post("/items/")
def create_item(item: Item):
    print(item.name)
    print(item.price)
    return item
```

当你在 VS Code 中输入：

```python
item.
```

编辑器通常能提示：

```text
name
description
price
tax
```

因为你已经通过：

```python
item: Item
```

告诉编辑器，`item` 是一个 `Item` 类型的对象。

如果你只使用一个没有明确结构的普通字典，编辑器就很难知道里面一定有哪些键。

这也是 FastAPI 官方推荐使用类型注解与 Pydantic 模型的重要原因。

## 五、使用模型：`.model_dump()` 到底是什么？

现在来到官方的「使用模型」一节。

这一节非常重要，因为你以后开发 Agent 时，会经常需要把 Pydantic 模型转换成 Python 字典。

官方示例的核心是：

```python
@app.post("/items/")
def create_item(item: Item):
    item_dict = item.model_dump()

    if item.tax is not None:
        price_with_tax = item.price + item.tax
        item_dict.update({
            "price_with_tax": price_with_tax
        })

    return item_dict
```

这段代码看起来有点复杂，但它只做了三件事：

1. 把 `Item` 模型对象转成字典。
2. 如果提供了税费，就计算含税价格。
3. 把计算结果加到返回数据里。

### 1. `item.model_dump()` 是什么意思？

假设：

```python
item = Item(
    name="Book",
    price=45.2,
    tax=3.5
)
```

此时 `item` 是一个 Pydantic 模型实例。

如果执行：

```python
item_dict = item.model_dump()
```

就会得到一个普通 Python 字典：

```python
{
    "name": "Book",
    "description": None,
    "price": 45.2,
    "tax": 3.5
}
```

你可以把 `.model_dump()` 理解为：

**把结构化的 Pydantic 模型对象，转换成普通 Python 字典。**

  

    **Pydantic 模型对象**
    
`item.name`、`item.price`

  

    
`.model_dump()`

  

    **Python 字典 dict**
    
`item_dict["name"]`、`item_dict["price"]`

这两种访问方式很容易混淆。

| 数据类型 | 读取 name |
|---|---|
| Pydantic 模型 | `item.name` |
| Python 字典 | `item_dict["name"]` |

你可以想象，Pydantic 模型是有明确字段定义的表单对象，而字典是一组普通的键值对。

补充：`.model_dump()` 是 Pydantic v2 的方法。如果你以后看一些老教程，可能会遇到 `.dict()`；现在学习新代码，优先掌握 `.model_dump()`。

### 2. 为什么要写 `if item.tax is not None`？

来看：

```python
if item.tax is not None:
```

这句话的意思是：

> 如果用户提供了税费，就计算含税价格。

你可能会问：

为什么不直接写？

```python
if item.tax:
```

区别在于，税费可能是合法的 `0.0`。

| item.tax | `if item.tax` | `if item.tax is not None` |
|---|---|---|
| 3.5 | True | True |
| 0.0 | False | True |
| None | False | False |

如果你的目的只是判断是否有数值，`is not None` 更准确。

### 3. `.update()` 是什么意思？

```python
item_dict.update({
    "price_with_tax": price_with_tax
})
```

这是普通 Python 字典的 `update()` 方法。

它可以给字典增加一个新的字段，或者更新已有字段。

例如：

```python
data = {"name": "Book", "price": 45.2}

data.update({"price_with_tax": 48.7})
```

结果：

```python
{
    "name": "Book",
    "price": 45.2,
    "price_with_tax": 48.7
}
```

对于这个例子，你也可以写成：

```python
data["price_with_tax"] = 48.7
```

效果一样。

### 4. 运行结果

客户端发送：

```json
{
  "name": "Book",
  "price": 45.2,
  "tax": 3.5
}
```

函数计算：

```python
price_with_tax = 45.2 + 3.5
```

最终返回：

```json
{
  "name": "Book",
  "description": null,
  "price": 45.2,
  "tax": 3.5,
  "price_with_tax": 48.7
}
```

注意：

- Python 里面使用 `None`。
- JSON 里面使用 `null`。
- `model_dump()` 默认会包含这些值为 `None` 的字段。
- `return item_dict` 后，FastAPI 会将字典编码成 JSON 响应。

这次代码使用简单浮点数进行演示。涉及真实支付和金额精确计算时，通常还要考虑 `Decimal` 等更适合金额处理的类型。

## 六、请求体 + 路径参数：可以同时使用吗？

**完全可以，而且很常见。**

假设你的 Agent 平台允许用户修改一个指定 Agent 的配置。

例如：

```text
PUT /agents/123
```

这里：

```text
123
```

表示要修改哪一个 Agent。

但具体修改成什么配置，需要通过请求体传入。

### 1. 官方代码

官方这一节使用商品的更新接口：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None


@app.put("/items/{item_id}")
def update_item(item_id: int, item: Item):
    return {"item_id": item_id, **item.model_dump()}
```

这段代码里同时出现了：

```python
item_id: int
```

和：

```python
item: Item
```

FastAPI 怎么知道它们来自哪里？

因为：

```python
@app.put("/items/{item_id}")
```

包含 `{item_id}`。

所以 `item_id` 是路径参数。

而 `Item` 是 Pydantic 模型，所以 `item` 是请求体参数。

### 2. 假设用户这样发送请求

请求 URL：

```text
PUT /items/123
```

请求体：

```json
{
  "name": "Computer",
  "price": 4999.0
}
```

FastAPI 实际传入函数的内容相当于：

```python
item_id = 123

item = Item(
    name="Computer",
    price=4999.0
)
```

然后执行：

```python
return {"item_id": item_id, **item.model_dump()}
```

### 3. `**item.model_dump()` 是什么意思？

这个写法很容易让初学者困惑。

我们先看：

```python
item.model_dump()
```

它返回：

```python
{
    "name": "Computer",
    "description": None,
    "price": 4999.0,
    "tax": None
}
```

前面的两个星号：

```python
**
```

在这里表示字典解包。

例如：

```python
data = {"name": "Tom", "age": 18}

result = {"id": 1, **data}
```

相当于：

```python
result = {
    "id": 1,
    "name": "Tom",
    "age": 18
}
```

因此：

```python
{"item_id": item_id, **item.model_dump()}
```

就是把 `item_id` 和模型里的各个字段放到同一个字典中。

最终返回：

```json
{
  "item_id": 123,
  "name": "Computer",
  "description": null,
  "price": 4999.0,
  "tax": null
}
```

**注意一个很重要的区别：** 这个官方示例虽然使用 `PUT` 并把函数命名为 `update_item`，但只是返回数据，并没有真正连接数据库或保存修改。

不要误以为使用了 `@app.put()`，FastAPI 就会自动更新数据库。

## 七、请求体 + 路径参数 + 查询参数

这是官方本章的最后一个主要代码示例，也是前面三章知识的综合应用。

你会发现：**FastAPI 可以同时识别三种不同来源的参数。**

### 1. 官方代码

```python
@app.put("/items/{item_id}")
def update_item(
    item_id: int,
    item: Item,
    q: str | None = None
):
    result = {
        "item_id": item_id,
        **item.model_dump()
    }

    if q:
        result.update({"q": q})

    return result
```

这里有三个参数：

```python
item_id: int
item: Item
q: str | None = None
```

它们的来源分别是什么？

| 参数 | 来自哪里 | 为什么 |
|---|---|---|
| `item_id` | 路径参数 | 路由包含 `{item_id}` |
| `item` | 请求体 | 类型是 Pydantic 模型 |
| `q` | 查询参数 | 普通类型，不在路径中 |

### 2. 用真实请求来理解

假设用户请求：

```text
PUT /items/123?q=promotion
```

同时发送请求体：

```json
{
  "name": "Laptop",
  "price": 5000.0,
  "tax": 100.0
}
```

FastAPI 的解析过程如下：

  

      
      **① 提取路径参数**

    

`/items/123` → `item_id = 123`

  

  

      
      **② 提取查询参数**

    

`?q=promotion` → `q = "promotion"`

  

  

      
      **③ 解析请求体**

    

创建 `Item` 模型实例

name = "Laptop"，price = 5000.0，tax = 100.0

  

  

      
      **④ 执行 Python 函数**

    ```python
    update_item(
        item_id=123,
        item=Item(
            name="Laptop",
            price=5000.0,
            tax=100.0
        ),
        q="promotion"
    )
    ```

最终结果：

```json
{
  "item_id": 123,
  "name": "Laptop",
  "description": null,
  "price": 5000.0,
  "tax": 100.0,
  "q": "promotion"
}
```

这三个参数并不会互相冲突，因为 FastAPI 知道去哪里读取它们。

### 3. 一个完整的参数识别规律

到这一章为止，你应该记住这张表：

| 声明 | 一般情况下 FastAPI 将其识别为 |
|---|---|
| 路由中包含 `{id}`，函数中有 `id: int` | 路径参数 |
| `limit: int = 10`，不在路径中 | 查询参数 |
| `q: str \| None = None`，不在路径中 | 查询参数 |
| `item: Item`，Item 继承 BaseModel | 请求体 |
| `request: ChatRequest`，ChatRequest 继承 BaseModel | 请求体 |

这是官方教程给出的核心规则。之后学习 `Path()`、`Query()`、`Body()` 和依赖注入时，还能显式指定或组合更复杂的参数来源。

## 八、不使用 Pydantic，可以接收请求体吗？

可以！

这正是官方本章最后的「不使用 Pydantic」一节。

官方在这一节告诉我们：除了 Pydantic 模型，FastAPI 还提供一个叫作 `Body` 的工具，可以显式声明请求体参数。

具体内容会在后续《请求体 - 多个参数》一章深入讲解，这里先看一个简单例子。

```python
from typing import Annotated
from fastapi import FastAPI, Body

app = FastAPI()

@app.post("/scores")
def create_score(
    score: Annotated[int, Body(embed=True)]
):
    return {"score": score}
```

客户端发送：

```json
{
  "score": 100
}
```

得到：

```json
{
  "score": 100
}
```

这里的：

```python
Body(embed=True)
```

告诉 FastAPI：从 JSON 请求体中读取名为 `score` 的字段。

其中 `Annotated` 是 Python 的类型注解工具，这一章你只需要先知道它可以为参数附加 FastAPI 使用的额外信息。

你不需要立刻深入理解它的所有机制。

**对于 Agent 开发，建议你目前优先使用 Pydantic 的 BaseModel。** 当请求体包含多个字段时，它更容易组织和维护。

参考：<Link url={turn270524view0.url.uri} title="FastAPI 官方教程《请求体 - 多个参数》"/>。

## 九、综合实战：创建你的 Agent 请求体练习项目 🤖

现在我们把这一章的知识全部结合起来。

我建议你创建一个新文件：


| 接口 | 功能 | 学习知识 |
|---|---|---|
| `POST /items/` | 创建模拟商品数据 | BaseModel、请求体 |
| `PUT /items/{item_id}` | 模拟更新商品数据 | 路径 + 查询 + 请求体 |
| `POST /chat` | 模拟 Agent 对话 | ChatRequest、ChatResponse |

### 1. 完整可运行代码

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI(title="Request Body Practice")


# ========== 第一部分：商品请求体 ==========

# 定义商品数据模型
class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None


# 创建商品（模拟，不保存到数据库）
@app.post("/items/")
def create_item(item: Item):

    # 将模型对象转换为字典
    item_dict = item.model_dump()

    # 如果提供了税费，则计算含税价格
    if item.tax is not None:
        price_with_tax = item.price + item.tax
        item_dict["price_with_tax"] = price_with_tax

    return item_dict


# 更新商品（模拟，不保存到数据库）
@app.put("/items/{item_id}")
def update_item(
    item_id: int,
    item: Item,
    q: str | None = None
):
    result = {
        "item_id": item_id,
        **item.model_dump()
    }

    if q:
        result["q"] = q

    return result


# ========== 第二部分：Agent 请求体 ==========

# 用户发给 Agent 的数据结构
class ChatRequest(BaseModel):
    message: str = Field(
        min_length=1,
        max_length=2000
    )
    session_id: str | None = None


# Agent 返回的数据结构
class ChatResponse(BaseModel):
    answer: str
    session_id: str | None = None


# 模拟 Agent
def run_agent(question: str) -> str:
    if "FastAPI" in question:
        return "FastAPI 可以把 Agent 封装为 Web API。"

    return f"模拟 Agent 收到了你的问题：{question}"


# Agent 对话接口
@app.post("/chat", response_model=ChatResponse)
def chat(request: ChatRequest):

    # 读取请求体中的 message 属性
    question = request.message

    # 调用模拟 Agent
    answer = run_agent(question)

    # 创建响应模型
    response = ChatResponse(
        answer=answer,
        session_id=request.session_id
    )

    return response
```

我们专门分析这段代码：

```python
class ChatRequest(BaseModel):
    message: str = Field(min_length=1, max_length=2000)
    session_id: str | None = None
```

这里的 `Field` 是你之前 `first.py` 里用过的。

它可以为模型字段添加验证要求。

```python
Field(min_length=1, max_length=2000)
```

表示：

- `message` 不能为空字符串。
- `message` 最多允许 2000 个字符。

注意，这种长度验证并不自动禁止只包含空格的字符串，例如 `"   "`。以后可以使用额外校验规则处理这种输入。

而：

```python
session_id: str | None = None
```

表示会话 ID 可以不传。

再来看：

```python
@app.post("/chat", response_model=ChatResponse)
```

这里出现一个新的知识点：

```python
response_model=ChatResponse
```

它不是请求体模型，而是**响应模型**。

作用是告诉 FastAPI：这个接口最终返回的数据应该符合 `ChatResponse` 的结构。

也就是说：

| 代码 | 含义 |
|---|---|
| `request: ChatRequest` | 规定用户发送什么 |
| `response_model=ChatResponse` | 规定接口返回什么 |
| `request.message` | 读取用户提出的问题 |
| `return response` | 把 Agent 回答交给 FastAPI 返回 |

这里的 `session_id` 只是原样传回，还没有真正实现多轮对话记忆。后续接入数据库或 Agent 状态管理时才会用它保存和查询会话。

你现在应该理解，之前写的 `first.py` 为什么要分别定义 `ChatRequest` 和 `ChatResponse` 了。

## 十、初学者最容易犯的 5 个错误

| 常见错误 | 原因 | 正确理解 |
|---|---|---|
| 直接在浏览器地址栏访问 `/chat` | 浏览器地址栏通常发送 GET，而接口需要 POST | 用 `/docs` 测试 |
| JSON 使用单引号 | 标准 JSON 的字符串必须用双引号 | 写 `"name": "Tom"` |
| 把 `None` 写进 JSON | JSON 的空值写作 `null` | Python 是 `None` |
| 使用 `item["price"]` | `item` 是 Pydantic 模型对象，不是字典 | 用 `item.price` |
| 缺少必填字段 | Pydantic 会拒绝缺少必填字段的请求 | 按模型提供数据 |

还有两个细节值得记住。

**第一：`POST /chat` 并不会自动调用大模型。**

FastAPI 只负责接口调用。到底是调用模拟函数、OpenAI SDK、LangGraph 还是自定义 Agent，取决于你在函数内部写的逻辑。

**第二：创建一个 Pydantic 模型也不等于保存数据。**

```python
item = Item(name="Book", price=99)
```

只是创建 Python 对象。想让服务重启后还能查到数据，还需要数据库等持久化存储。

## 问题四：为什么 `request.message` 可以读取 JSON 中的 `message`？🤔

**答案：因为 FastAPI 会利用 Pydantic，把客户端发送的 JSON 请求体转换成 `ChatRequest` 类的实例对象，而 `message` 正是这个类定义的属性。**

我们通过代码一步一步理解。

### 一、先看完整代码

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 定义请求体的数据结构
class ChatRequest(BaseModel):
    message: str
    session_id: str | None = None


@app.post("/chat")
def chat(request: ChatRequest):
    return {
        "answer": request.message
    }
```

假设客户端发送：

```json
{
  "message": "你好，FastAPI！",
  "session_id": "abc123"
}
```

FastAPI 会自动完成以下过程。

### 二、理解数据是如何转换的

  

第一步：客户端发送 JSON 请求体

    ```json
    {
      "message": "你好，FastAPI！",
      "session_id": "abc123"
    }
    ```

  

    
FastAPI 读取请求体

  

    **第二步：Pydantic 根据 ChatRequest 解析和校验数据**
    
检查字段名称、类型和必填要求

  

  

第三步：得到 ChatRequest 对象

    ```python
    request = ChatRequest(
        message="你好，FastAPI！",
        session_id="abc123"
    )
    ```

  

  

第四步：通过属性获取数据

    ```python
    request.message
    # "你好，FastAPI！"

    request.session_id
    # "abc123"
    ```

注意：第三步的 `ChatRequest(...)` 是帮助你理解内部过程的等效示意。实际上，FastAPI 和 Pydantic 会自动完成解析、校验和实例创建，你不需要在接口函数中手动写这一行。

### 三、为什么使用点号 `.`，而不是 `["message"]`？

因为 `request` 是一个 **Pydantic 模型实例**，而不是普通的 Python 字典。

这两种数据类型访问字段的方式不同。

**情况一：普通 Python 字典**

```python
request = {
    "message": "你好，FastAPI！"
}

print(request["message"])
```

使用：

```python
request["message"]
```

**情况二：Pydantic 模型实例**

```python
class ChatRequest(BaseModel):
    message: str

request = ChatRequest(
    message="你好，FastAPI！"
)

print(request.message)
```

使用：

```python
request.message
```

| 对比 | Python 字典 | Pydantic 模型 |
|---|---|---|
| 数据创建 | `{ "message": "hello" }` | `ChatRequest(message="hello")` |
| 数据读取 | `data["message"]` | `request.message` |
| 类型校验 | 不会自动按模型校验 | Pydantic 自动校验 |
| 转换成字典 | 本身就是字典 | `request.model_dump()` |

### 四、如果 JSON 中没有 message 会怎样？

例如用户发送：

```json
{
  "session_id": "abc123"
}
```

但是模型定义为：

```python
class ChatRequest(BaseModel):
    message: str
    session_id: str | None = None
```

由于 `message` 没有默认值，因此是必填字段。

FastAPI 会返回 HTTP 422，并提示请求体缺少 `message`。

这样一来，当程序正常进入：

```python
def chat(request: ChatRequest):
```

你就可以相信 `request.message` 已经通过了模型定义的基础数据校验。

### 五、最后用一句话记住 ⭐

```python
class ChatRequest(BaseModel):
    message: str
```

**定义了对象应该具有的属性。**

```python
def chat(request: ChatRequest):
```

**告诉 FastAPI 把 JSON 请求体解析为 `ChatRequest` 对象。**

```python
request.message
```

**通过对象的 `message` 属性读取用户传入的内容。**

这也是你以后开发 Agent 时最常使用的模式：

```python
@app.post("/chat")
def chat(request: ChatRequest):
    user_question = request.message

    answer = run_agent(user_question)

    return {"answer": answer}
```

整个过程就是：

**用户发送 JSON → FastAPI 接收 → Pydantic 创建对象 → `request.message` 获取问题 → Agent 处理 → 返回结果。** ✅
