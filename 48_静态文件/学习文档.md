# 07｜静态文件（Static Files）

**FastAPI 用户指南 · 独立复习手册｜核心问题：怎样通过 HTTP 访问已有的图片、CSS、JS 等文件？**

官方文档：https://fastapi.tiangolo.com/zh/tutorial/static-files/

## 一、先理解什么是静态文件？

一个 Agent 平台里会同时出现两类内容：

- **动态内容**：`POST /chat` 根据用户问题调用 Agent，返回的回答每次可能不同。
- **静态文件**：`logo.png`、`style.css`、`app.js` 等已存在的文件，不需要每次都运行 Agent 才能生成。

例如页面展示两个 Agent 的头像，这些图片可以由 FastAPI 直接提供，而不是为每个文件写一个独立的 `@app.get()` 路由函数。

## 二、官方核心示例：StaticFiles

```python
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()

app.mount("/static", StaticFiles(directory="static"), name="static")
```

假设项目结构：

```text
project/
├── main.py
└── static/
    ├── logo.png
    ├── style.css
    └── app.js
```

那么客户端访问 `GET /static/logo.png`，FastAPI 的 StaticFiles 会查找服务器 `static/logo.png` 文件并提供给客户端；你无需为它写一个专门的 Python 处理函数。

## 三、三个参数的职责

| 参数 | 小白理解 | 举例 |
| --- | --- | --- |
| `'/static'` | 在浏览器中访问资源的 URL 前缀 | `/static/logo.png` |
| `StaticFiles(directory='static')` | 映射到服务器的本地目录 | 磁盘上的 `static/logo.png` |
| `name='static'` | 被挂载应用的内部名称 | 方便应用内部按名称引用 |

**URL 路径不等于磁盘路径。**`/static/logo.png` 是对外可见的请求地址；`static/logo.png` 是服务器上的相对文件目录位置。服务启动时要保证目录确实存在。

## 四、什么叫 Mount（挂载）？

前面你学习过 `app.include_router(router)`，现在看到的是 `app.mount(...)`。

`include_router` 把一组普通路径操作整合进主 FastAPI 应用。`mount` 在某个路径前缀下交给相对独立的 ASGI 子应用处理请求。此章被挂载的子应用是 `StaticFiles`。

官方强调：挂载应用与 APIRouter 不同，主应用自动生成的 `/docs` / OpenAPI 不会自动枚举挂载子应用里的每个静态文件。

这不是缺陷：静态资源可能有上百张图片，没必要把每个文件都列成 API 文档里的一个业务接口。

## 五、与前一章 app.frontend() 怎么区别？

| 需求 | 优先考虑 | 原因 |
| --- | --- | --- |
| 提供 logo、图片、CSS、脚本 | `StaticFiles` | 简单映射文件目录 |
| 提供完整的 React/Vue 静态构建输出 | `app.frontend()` | 额外支持前端客户端路由 fallback |
| 运行实时 SSR 前端程序 | 需要其他方案 | 前端章节主要提供静态构建结果 |
| 调用 Agent 聊天 | 普通 FastAPI 路由 | 需要执行 Python 业务逻辑 |

官方说明 `app.frontend()` 底层也利用 StaticFiles，但对完整前端应用提供额外的客户端路由支持。不要把两者看成毫无关系的技术。

## 六、Agent 实战：什么文件适合放在公开 static 目录？

适合：Agent 产品 Logo、公开头像、网站样式、用户界面脚本、公开的帮助插图等。

不宜直接公开：用户上传的私人 PDF、带个人信息的历史对话文件、内部知识库原件、访问密钥或配置文件。

原因是：`StaticFiles` 的典型职责是按路径提供目录中的文件，**不能替代针对用户、文档、会话的业务权限检查**。私有资源通常应通过单独的受保护 API 或专用授权文件存储方式访问。

典型用户流程：打开网页 → 请求 HTML → 浏览器请求 `/static/app.js`、`/static/style.css`、`/static/logo.png` → 前端再调用 `/chat` → Agent 返回动态结果。静态文件只是其中的资源提供环节。

## 七、常见误区

1. **StaticFiles 就是网页后端业务？** 不是，它提供已有文件，不执行 Agent 推理。
2. **`/static` 是服务器上的目录吗？** 它是 URL 前缀；`directory='static'` 才指定磁盘目录。
3. **`app.mount` 和 `include_router` 完全一样吗？** 不一样。前者挂载独立子应用，后者整合路由。
4. **每个静态图片会出现在 `/docs` 中吗？** 不会被自动当成主应用的普通路径操作列出。
5. **用户上传的文件能直接扔在公开 static 目录吗？** 不建议，涉及权限和敏感数据时应保护访问。

## 八、5 道复习题（附答案解析）

**1. `StaticFiles(directory='static')` 表示什么？**  答：从服务器已有 `static` 目录提供文件，而非自动创建业务 API。

**2. 请求 `/static/logo.png` 会找到哪个文件？**  答：在上述挂载设置和目录结构下，查找 `static/logo.png`。

**3. 为什么 `mount()` 的文件不逐一显示在主应用 /docs？**  答：挂载的是独立子应用，不是把每个资源都注册成主应用路径操作。

**4. 若部署完整 React SPA，StaticFiles 一定比 app.frontend 更方便吗？**  答：不一定。app.frontend 额外处理 SPA 客户端路由等约定。

**5. 能否依靠把文件放进 /static 来验证用户权限？**  答：不能。敏感文件需要专门的授权访问机制。

## 九、思考题

你的 Agent 平台允许用户上传机密研究报告，还会显示公开的 Agent 图标。哪些文件可以进 `static/`？上传报告应该怎样防止其他用户下载？

**参考方向：**公开图标、CSS、JS 可作为静态资源；报告则保存到受控存储，用经过身份认证与资源授权的接口检查访问权限后再提供。

**本章一句话总结：**StaticFiles 解决“已存在的文件如何通过 URL 提供”，不是“如何运行 Agent 或保护私有文件”。
