# 📘 FastAPI 第一章重讲：表单数据（Form Data）

## 一、表单的基本概念

先暂时忘记 FastAPI、Python 和 HTTP。

想象你在网上填写一张报名表：

  

    **AI 学习助手 · 意见登记**

  

昵称

      alice

  

    
留言内容

      hello

  

    **提交**

  
示意图：两个输入框和一个提交按钮，暂不涉及真实发送。

上面这整块可以填写并提交信息的区域，就是一个**网页表单（Web Form）**。

表单并不是某种神秘的数据类型。它首先是一种很普通的网页交互方式：**让用户在多个输入框中填写内容，再一次性提交。**

例如，这张表单包含两项信息：

| 字段名称 | 用户填写的值 |
|---|---|
| nickname | alice |
| message | hello |

当用户点击「提交」时，浏览器需要把这些信息发送给后端服务器。

所以表单涉及三个不同的东西：

1. **表单界面**：用户在网页上看到的输入框和按钮。
2. **表单数据**：用户填写的字段名称和值，例如 `nickname=alice`。
3. **表单提交**：浏览器把这些数据封装成 HTTP 请求，发给服务器。

我们现在学习的 FastAPI `Form()`，主要负责第三步之后的事情：**从收到的 HTTP 请求中提取表单字段。**

## 二、一个表单在网页中的实际代码

刚才那张表单，可以使用 HTML 写成：

```html
<form action="/submit" method="post">

    <label>
        昵称：
        <input name="nickname" value="alice">
    </label>

    <label>
        留言：
        <input name="message" value="hello">
    </label>

    <button type="submit">提交</button>

</form>
```

你现在完全不需要掌握 HTML，只看其中几个重要部分。

### 1. form 表示整个表单

```html
<form action="/submit" method="post">
```

这里规定了两件事：

- `action="/submit"`：把数据发送到后端的 `/submit` 地址。
- `method="post"`：使用 HTTP POST 方法发送。

### 2. input 表示输入框

```html
<input name="nickname" value="alice">
```

这里：

- `name="nickname"`：这个字段的**名称**叫 nickname。
- `value="alice"`：当前输入框里的值是 alice。

所以浏览器知道它需要提交：

```text
nickname = alice
```

第二个输入框：

```html
<input name="message" value="hello">
```

代表：

```text
message = hello
```

特别注意：**`name` 是发给后端的字段名称，不是输入框旁边显示的中文提示。**

如果前端使用 `name="message"`，后端就应该按 `message` 这个名称接收。

### 3. button 触发表单提交

```html
<button type="submit">提交</button>
```

当用户点击它，浏览器就会按照 form 设置的 `action` 和 `method` 发送数据。

这一刻，表单从“网页上的输入框”，变成了“要发送给服务器的数据”。

## 三、浏览器把表单转换成 HTTP 请求

现在继续刚才的例子。

用户填写：

```text
nickname = alice
message  = hello
```

点击「提交」。

对于这样一个普通的 POST HTML 表单，浏览器通常会构造类似下面的 HTTP 请求：

```http
POST /submit HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: application/x-www-form-urlencoded

nickname=alice&message=hello
```

这是理解整章的关键。

我们把这个请求拆开看：

  

① 请求目标

    **POST /submit**

浏览器要调用后端的 /submit 接口

  

② 请求头 Header

    `Content-Type: application/x-www-form-urlencoded`

告诉服务器：请求体采用普通表单编码

  

③ 请求体 Body

    `nickname=alice&message=hello`

真正提交的两个字段及其值

对于普通表单，浏览器会把多个字段编码成类似：

```text
字段名1=值1&字段名2=值2
```

的形式。

- `=` 连接字段名称和字段值。
- `&` 分隔多个字段。
- 空格、中文和其他特殊字符会按照编码规则处理，浏览器会自动完成。

这种请求体的格式叫：

```text
application/x-www-form-urlencoded
```

现在再看整个过程：

```text
用户看到网页表单
      ↓
在 nickname 输入框填写 alice
      ↓
在 message 输入框填写 hello
      ↓
点击提交
      ↓
浏览器读取输入框中的 name 和 value
      ↓
组成 nickname=alice&message=hello
      ↓
放进 HTTP POST 请求体
      ↓
发送到 /submit
      ↓
后端接收并解析
```

**表单数据并不是 HTTP 中一个独立于 Body 的新位置。普通 POST 表单数据就是放在 Body 里的，只是编码方式与 JSON 不一样。**

## 四、表单与其他请求数据的区别

先把你之前学过的几种参数放在一起。

假设我们都要向服务器传递一个值：

```text
nickname = alice
```

这个值可以放在 HTTP 请求的不同位置。

| 数据类型 | 在 HTTP 请求中的位置 | 请求示例 | FastAPI 接收方式 |
|---|---|---|---|
| Path | URL 路径 | `/users/alice` | `Path()` |
| Query | URL 问号后 | `/users?nickname=alice` | `Query()` |
| Header | 请求头 | `X-Nickname: alice` | `Header()` |
| Cookie | Cookie 请求头 | `Cookie: nickname=alice` | `Cookie()` |
| JSON Body | 请求体 | `{"nickname":"alice"}` | `BaseModel` / `Body()` |
| Form Body | 请求体 | `nickname=alice` | `Form()` |

现在，请重点比较下面三种情况。

### 1. Query：字段写在 URL 中

```http
GET /search?nickname=alice HTTP/1.1
```

后端可以写：

```python
nickname: Annotated[str, Query()]
```

FastAPI 从 URL 的 `?` 后面提取 nickname。

### 2. Form：字段写在 POST 请求体中

```http
POST /submit HTTP/1.1
Content-Type: application/x-www-form-urlencoded

nickname=alice
```

后端写：

```python
nickname: Annotated[str, Form()]
```

FastAPI 从采用表单编码的请求体中提取 nickname。

### 3. JSON：字段同样写在请求体中，但编码不同

```http
POST /submit-json HTTP/1.1
Content-Type: application/json

{"nickname":"alice"}
```

后端通常写：

```python
class RequestData(BaseModel):
    nickname: str
```

看出关键区别了吗：

**Query 和 Form 的内容看起来可能都是 `nickname=alice`，但位置不同。**

**Form 和 JSON 都在 Body 里，但数据的编码方式不同。**

这是本章最重要的两组区别。

## 五、网页表单与 Form 数据并不完全等同

这里还有一个我之前没有解释清楚的细节。

**同样是网页上看得见的表单，使用 GET 和 POST 提交时，数据的位置也可能不同。**

例如：

```html
<form action="/search" method="get">
    <input name="nickname" value="alice">
    <button type="submit">搜索</button>
</form>
```

点击提交，浏览器会访问：

```text
GET /search?nickname=alice
```

字段进入了 URL，因此 FastAPI 使用 `Query()` 接收。

但改成：

```html
<form action="/submit" method="post">
    <input name="nickname" value="alice">
    <button type="submit">提交</button>
</form>
```

浏览器就会把字段放进 POST 请求体，通常使用表单编码，FastAPI 使用 `Form()` 接收。

因此需要区分：

- **HTML 表单**：网页上的一种输入与提交界面。
- **HTTP 表单数据**：客户端使用特定编码方式传递的字段数据。

另外，表单编码的数据也不一定非要来自网页上的 `
`。Python `httpx` 等客户端，同样可以主动发送这种数据。

## 六、FastAPI 的 Form() 正式登场

现在理解它的用途就很自然了：

**浏览器已经提交了表单，FastAPI 需要从请求体里把每个字段取出来。**

例如：

```python
from typing import Annotated

from fastapi import FastAPI, Form

app = FastAPI()


@app.post("/submit")
def submit(
    nickname: Annotated[str, Form()],
    message: Annotated[str, Form()]
):
    return {
        "nickname": nickname,
        "message": message
    }
```

这里：

```python
nickname: Annotated[str, Form()]
```

可以理解成：

> 从表单请求体中提取名叫 nickname 的字段，并将它作为字符串传给这个 Python 参数。

再看：

```python
message: Annotated[str, Form()]
```

意思完全一样，只是接收另一个字段。

因此：

```text
nickname=alice&message=hello
```

经过 FastAPI 解析后，效果相当于函数获得：

```python
nickname = "alice"
message = "hello"
```

最终返回：

```json
{
  "nickname": "alice",
  "message": "hello"
}
```

如果请求没有提交必填的 `message`，FastAPI 通常会返回 **422**。

一个值得记住的细节是，错误位置通常显示：

```json
["body", "message"]
```

因为表单数据依然属于 HTTP Body。

## 七、动手验证完整流程

为了让你不再只能靠想象理解，我准备了一个真正包含 HTML 网页表单的 FastAPI 项目。

这个项目有三个接口：

| 地址 | 作用 |
|---|---|
| `GET /form` | 显示真正的网页表单 |
| `POST /submit` | 使用 `Form()` 接收提交的数据 |
| `POST /submit-json` | 使用 Pydantic 模型接收 JSON，供你比较 |

先安装依赖：

```bash
python -m pip install "fastapi[standard]" python-multipart
```

下载下面的 Python 文件，并在 Windows 的 `(llm)` 环境运行：

```bash
fastapi dev fastapi_form_从零理解_实践.py
```

然后在浏览器打开：

```text
http://127.0.0.1:8000/form
```

你会看到两个真正的输入框。保留默认值 alice 和 hello，点击提交。

浏览器会向 `POST /submit` 发送表单数据，然后显示服务器返回的 JSON：

```json
{
  "nickname": "alice",
  "message": "hello",
  "received_as": "form data"
}
```

接着打开：

```text
http://127.0.0.1:8000/docs
```

分别观察 `/submit` 和 `/submit-json` 的请求体格式，你会更清楚地看到 Form 和 JSON 的区别。

我也测试了这两个接口：正确编码可以得到 200，把 JSON 错发给 Form 接口、或把表单错发给 JSON 接口，在这个示例中都会得到 422。

## 八、把整章压缩成一条理解链

  

    **用户填写网页表单**

昵称 alice，留言 hello

  

  

    **浏览器读取字段名和值**

nickname → alice；message → hello

  

  

    **浏览器发送 POST 请求**

    `nickname=alice&message=hello`

  

  

    **FastAPI 使用 Form() 提取字段**

转成 Python 参数 nickname 和 message

  

  

    **Python 业务函数处理数据**

验证输入、执行业务逻辑、返回响应

`Form()` 不负责绘制输入框，不负责让用户点击按钮，也不负责自动发送请求。

**它只负责在后端收到表单数据之后，正确提取并验证这些字段。**

这才是第一章真正要建立的理解。
