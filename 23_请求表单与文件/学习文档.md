# 第二章：请求表单与文件（Request Forms and Files）

## 十二、从单独上传文件到同时提交任务说明

这一章其实是上一章和《表单数据》的组合。

假设你正在开发一个“AI 文档总结 Agent”。

用户需要填写两项内容：

- 任务说明：`请总结这份资料`
- 上传文件：`notes.pdf`

如果只允许上传文件，Agent 不一定知道用户想做什么。

而如果只允许输入任务说明，Agent 也拿不到文档。

因此，我们希望用户可以在同一个页面里完成：

  

    **文档总结 Agent · 示意界面**

  

任务说明

      请总结这份文件

  

    
选择文件

      

        **notes.pdf**

    

  

最大模拟步骤数

      3

  

    上传并提交任务

  
教学示意：同一次请求中既有普通文字，也有文件内容。

现在要传的数据是：

```text
instruction = 请总结这份文件
max_steps   = 3
file        = notes.pdf 的实际文件内容
```

这里有两种不同性质的数据：

**普通字段：**

```text
instruction
max_steps
```

**文件字段：**

```text
file
```

因此可以组合：

```python
Form()
File()
```

## 十三、HTTP multipart 的完整结构

这次 HTTP 请求可能是：

```http
POST /agent/analyze HTTP/1.1
Content-Type: multipart/form-data; boundary=abc123

--abc123
Content-Disposition: form-data; name="instruction"

请总结这份文件
--abc123
Content-Disposition: form-data; name="max_steps"

3
--abc123
Content-Disposition: form-data; name="file"; filename="notes.pdf"
Content-Type: application/pdf

...PDF 文件字节内容...
--abc123--
```

这个示意请求很重要。

你可以把它理解成：

```text
同一个 HTTP Body
      │
      ├── 第 1 部分：instruction 普通文本
      │
      ├── 第 2 部分：max_steps 普通文本
      │
      └── 第 3 部分：file 文件内容
```

因此不需要发送三次 HTTP 请求。

浏览器可以把它们一起封装成一个 `multipart/form-data` 请求体。

这就是本章最核心的原理。

## 十四、官方代码：同时声明 File 和 Form

官方教程展示了同时接收两个文件和一个普通表单字段的写法。

这里把原本用于演示的 `token` 换成普通的 `note`，避免让你形成回显认证令牌的习惯。

```python
from typing import Annotated

from fastapi import FastAPI, File, Form, UploadFile

app = FastAPI()


@app.post("/files/")
async def create_file(
    file: Annotated[bytes, File()],
    fileb: Annotated[UploadFile, File()],
    note: Annotated[str, Form()]
):
    return {
        "file_size": len(file),
        "fileb_content_type": fileb.content_type,
        "note": note
    }
```

这段代码看起来有三个参数，我们逐个分析。

### 1. file：第一个文件

```python
file: Annotated[bytes, File()]
```

客户端要提供一个名为：

```text
file
```

的文件字段。

FastAPI 将文件内容读成 `bytes`。

因此：

```python
len(file)
```

得到文件的字节数。

### 2. fileb：第二个文件

```python
fileb: Annotated[UploadFile, File()]
```

客户端还要提供一个名为：

```text
fileb
```

的文件字段。

这一次使用 `UploadFile`，所以可以访问：

```python
fileb.filename
fileb.content_type
```

这里的 `file` 与 `fileb` 是**两个不同的上传字段**，不是同一个文件变量的两种写法。

### 3. note：普通表单字段

```python
note: Annotated[str, Form()]
```

客户端需要提交文本，例如：

```text
note=请帮我检查上传的文件
```

FastAPI 将它作为字符串传给 `note`。

### 4. 三个参数的数据来源

| Python 参数 | FastAPI 声明 | 获取的数据 |
|---|---|---|
| `file` | `File()` + `bytes` | 第一个文件的字节内容 |
| `fileb` | `File()` + `UploadFile` | 第二个文件的上传对象 |
| `note` | `Form()` + `str` | 普通文本 |

**它们虽然使用不同的 Python 类型，但全部来自同一个 HTTP multipart 请求体。**

这句话一定要记住。

## 十五、Agent 实战：上传文档并附加处理指令

现在我们把官方示例改造成一个更贴近未来 Agent 开发的接口。

需求如下：

- 用户上传一个文档。
- 用户填写处理指令。
- 用户可以选择 Agent 最大步骤数。
- FastAPI 验证这些输入。
- 服务器返回已经收到的文件信息。

目前先不接入 LLM，避免混淆“上传文件”和“理解文件”的职责。

### 1. 完整代码

```python
from typing import Annotated

from fastapi import (
    FastAPI,
    File,
    Form,
    HTTPException,
    UploadFile,
)
from pydantic import BaseModel

app = FastAPI()


# 模拟练习：限制我们在函数中读取的文件大小
MAX_DEMO_BYTES = 1024 * 1024  # 1 MiB


# 输出模型
class UploadSummary(BaseModel):
    instruction: str
    filename: str | None
    content_type: str | None
    received_bytes: int
    max_steps: int
    status: str


@app.post(
    "/agent/analyze",
    response_model=UploadSummary
)
async def analyze_document(

    # 普通表单字段
    instruction: Annotated[
        str,
        Form(min_length=1, max_length=500)
    ],

    # 上传文件字段
    file: Annotated[
        UploadFile,
        File()
    ],

    # 带默认值的表单数值
    max_steps: Annotated[
        int,
        Form(ge=1, le=5)
    ] = 3

):

    content = await file.read(MAX_DEMO_BYTES + 1)

    if len(content) > MAX_DEMO_BYTES:
        raise HTTPException(
            status_code=413,
            detail="File is too large for this demo"
        )

    return UploadSummary(
        instruction=instruction,
        filename=file.filename,
        content_type=file.content_type,
        received_bytes=len(content),
        max_steps=max_steps,
        status="received_only_no_llm_processing"
    )
```

我们按照此前的方式，从数据声明开始分析。

### 2. instruction：用户希望 Agent 执行的任务

```python
instruction: Annotated[
    str,
    Form(min_length=1, max_length=500)
]
```

这是普通表单字段。

用户填写：

```text
请总结这份文件
```

就会被解析为 Python 字符串。

其中：

```python
min_length=1
```

和之前学习的 `Field(min_length=1)` 一样，限制最小长度。

它不会阻止纯空格字符串；如果需要禁止纯空白内容，仍然需要额外验证。

### 3. file：上传的文档

```python
file: Annotated[
    UploadFile,
    File()
]
```

这是文件字段。

用户可以选择：

```text
notes.pdf
```

然后浏览器发送这个文件的内容。

FastAPI 将其解析为 `UploadFile` 对象。

### 4. max_steps：表单中的数值字段

```python
max_steps: Annotated[
    int,
    Form(ge=1, le=5)
] = 3
```

它虽然在 HTTP 表单中通常表现为文本：

```text
max_steps=2
```

但 Pydantic 会根据 `int` 的声明，把合法的数字文本解析成整数：

```python
max_steps = 2
```

如果客户端不提供它：

```python
max_steps = 3
```

如果传入：

```text
max_steps=99
```

就会因超出允许范围而通常返回 HTTP 422。

注意，`max_steps` 在这里仍然只是一个参数，并没有自动控制真实的 LangGraph 执行次数。

### 5. 文件内容的大小限制

```python
content = await file.read(MAX_DEMO_BYTES + 1)
```

这段代码只读取最多 1 MiB 再多 1 个字节。

如果读到了超过 1 MiB 的内容：

```python
if len(content) > MAX_DEMO_BYTES:
```

就抛出：

```python
HTTPException(status_code=413)
```

HTTP 413 通常表示请求内容过大。

这是为了让你看到：**除了 FastAPI 自动执行的 422 字段校验，业务函数还可以主动检查文件大小并拒绝处理。**

但是，这个演示只在**请求已经到达端点之后**进行判断，并不防止客户端先发送一个很大的请求。真实生产系统还要在代理或网关层设置请求大小限制，并考虑文件存储、扫描及并发限制。

### 6. 为什么不直接总结 PDF？

因为：

```python
await file.read(...)
```

得到的是文件字节。

它不等于已经提取了 PDF 文本，也不等于 LLM 已经理解文档。

未来你需要增加：

```text
接收文件
   ↓
检查大小、格式、权限
   ↓
读取或解析文件内容
   ↓
提取 PDF / TXT / 图片信息
   ↓
构造 Agent 输入
   ↓
调用 LangGraph / LLM / Tools
   ↓
生成结果
```

我们当前的代码只实现了前面几步，所以响应会明确标记：

```json
{
  "status": "received_only_no_llm_processing"
}
```

这样不会误导你以为已经做了 AI 文件分析。

### 使用 httpx 测试

```python
import httpx

url = "http://127.0.0.1:8000/agent/analyze"

with open("notes.txt", "rb") as f:

    response = httpx.post(
        url,

        # 普通表单字段
        data={
            "instruction": "请总结这份文件",
            "max_steps": "2"
        },

        # 上传文件字段
        files={
            "file": f
        }
    )

print(response.status_code)
print(response.json())
```

这段代码是两章知识最直接的结合。

你以前学过：

```python
data={...}
```

代表普通表单字段。

今天新增：

```python
files={...}
```

代表文件上传。

**同一个 `httpx.post()` 里同时使用 `data` 和 `files`，客户端就会构造适合上传文件与文本的 multipart 请求。**

## 十八、File、Form 和 JSON Body 的重要区别

这是两章中最容易成为错题的地方。

假设你的接口需要：

```python
instruction: Annotated[str, Form()]
file: Annotated[UploadFile, File()]
```

此时客户端必须发送表单与文件上传格式，也就是：

```http
Content-Type: multipart/form-data
```

但是，假设你还想同时传入复杂的 JSON 模型：

```python
class AgentConfig(BaseModel):
    max_steps: int
    tools: list[str]
```

你不能简单地再写：

```python
config: AgentConfig
```

就期待 FastAPI 自动在同一个 multipart 请求中，把另一份 `application/json` Body 解析出来。

**一个 HTTP 请求只有一个整体的请求体媒体类型；文件上传接口的请求体采用 multipart，而不是独立的 JSON Body。** 

### 两种常用设计

**设计 A：使用普通 Form 字段搭配文件**

例如：

```python
instruction: Annotated[str, Form()]
max_steps: Annotated[int, Form()]
file: Annotated[UploadFile, File()]
```

这正是本章实战采用的方式。

**设计 B：先用 JSON 创建任务，再用单独的请求上传文件**

例如：

```text
POST /tasks
Content-Type: application/json

{"instruction":"请总结","max_steps":3}
```

服务器返回任务 ID 后，再通过文件上传接口关联任务：

```text
POST /tasks/123/files
Content-Type: multipart/form-data
```

对于需要复杂参数、多个大文件或任务异步处理的 Agent 项目，这种设计也很常见。

还可以把 JSON 序列化为某个表单字段的字符串，然后在后端单独解析验证，但那属于后续进阶设计，不是 `Form()` 和 JSON Body 自动合并。

## 十九、第二章常见错误

| 情况 | 常见结果 | 原因 |
|---|---|---|
| 没有上传必填的 file | 422 | 缺少文件字段 |
| 没有提交 instruction | 422 | 缺少必填表单字段 |
| max_steps=99 | 422 | 超出允许范围 1～5 |
| 将 `"file": "notes.pdf"` 放在 JSON 中 | 422 | 文件名字符串不等于实际上传文件 |
| 文件超过本项目的教学大小限制 | 413 | 业务代码主动拒绝 |
| 使用 GET 调用只支持 POST 的接口 | 405 | HTTP 请求方法不匹配 |

还要牢记：不能仅凭 `.filename` 或 `.content_type` 就确认文件安全，更不能直接使用不可信文件名拼接服务器上的保存路径。

**思考题 1：Agent 文件上传接口设计**

设计一个接口，要求接收：

- `instruction`：必填的任务说明字符串。
- `file`：用户上传的文档。
- `max_steps`：默认 3，允许 1～5。

说明每个参数使用 `Form()` 还是 `File()`。

**思考题 2：JSON 与文件内容**

前端向文件上传接口发送：

```json

}
```

而后端声明：

```python
file: Annotated[UploadFile, File()]
```

解释为什么这个 JSON 不等于真正上传了 report.pdf。

**思考题 3：Agent 文件处理流程**

用户上传一份 PDF，并输入：

从 FastAPI 接收到文件，到真正返回 LLM 总结，中间还需要哪些主要步骤？

| 题号 | 答案 | 核心解析 |
|---|---|---|
| 1 | B | multipart 可以容纳文件和普通表单字段 |

| 4 | C | data 负责表单字段，files 负责文件 |
| 5 | C | Form 中的数值校验失败通常返回 422 |
| 6 | A | HTML 使用 multipart 编码发送文件 |

`instruction` 和 `max_steps` 是普通表单字段，`file` 是文件字段。三者共同放在一个 multipart 请求体中。

**思考题 2 参考答案：**

因为：

```json

```

只提供了一个字符串，内容是文件名。

它没有把 report.pdf 中的真实字节发送给服务器。

**思考题 3 参考答案：**


# 二十一、两章最终总结

| 你的需求 | 推荐写法 |
|---|---|
| 直接接收小文件的全部字节 | `file: Annotated[bytes, File()]` |
| 接收一般上传文件，获取文件名和元数据 | `file: Annotated[UploadFile, File()]` |
| 一次上传多个文件 | `files: Annotated[list[UploadFile], File()]` |
| 文件可以不上传 | `file: Annotated[UploadFile \| None, File()] = None` |
